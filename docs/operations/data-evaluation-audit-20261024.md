## 本轮独立复现的待处理项

### A1 / P2：非法分类被原MCC公式排除，可造成虚高

`tools/testdata/verdict_eval.py:175`直接复用API vendored `score_replay`；`services/api/app/_vendor/aisoc_benchmark/replay.py:633`构建MCC方阵时只纳入四个合法预测标签。非法非空输出虽进入总混淆矩阵、仍被统计为已回答，却未进入MCC分母。

断网构造72条观察：按opaque ID排序，偶数序号36条填正确原标签，奇数序号36条填`invalid-model-output`，置信度统一0.9。实际输出：observed=72、graded=72、headline_accuracy=0.5、balanced_accuracy=0.5354166666666667，但matthews_corrcoef=1.0。这是继承原评分器的缺陷；离线JSON仍标不可发布模型成绩，但单项指标会误导。

建议：处理非法预测时使用完整类别分母，或先在存在非法分类时停报MCC并说明原因；补真实反例测试。修复前不可据此指标排名模型。本次只登记，不修改公式。

### A2 / P2：批次选择未完整冻结，文档的一对方案尚不可执行

`tools/testdata/verdict_live.py:31`准备入口固定要求两对四条；文档建议只跑材料完整的AWS-03一对，实际调用会报`Select exactly two distinct complete pairs`。`load_inputs`核单条来自固定可见原件，却不重新验证完整配对或原先选择。

断网复现：正常prepare两对；改为固定可见语料排序的前四条，并同步重算manifest的inputs_sha256/finding_ids，load_inputs仍接受；四条分别来自四个不同对（每对1条）。原件内容不能被替换的校验有效，但不能据此称整批选择已锁定。

建议：支持一个或两个完整对的有界选择；在不把答案交给运行器的前提下冻结并核对整批选择、完整配对、anchor和批次参数。保持请求/用量上限与逐例停止。本次未修。

### A3 / 已知业务输入阻塞：原raw_event摘要截断关键证据

原分诊经`format_extra_fields_for_llm`对raw_event最多摘要10行。核读本地preflight与preflight-v2 summary，均为offline_http_stub、4请求/0真实模型、ready_for_live=false：

停在输入设计讨论合理，不可按完整答案把缺材料造成的结果计为模型能力。40行/4000字符是尚未实施的候选；先对齐调查新版输入合同。也可在A2支持后只做材料完整的一对，明示覆盖限制，不改真值、不补模型未见材料。
