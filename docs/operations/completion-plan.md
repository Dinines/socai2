```text
自动：已有告警 → Fusion → 自动分诊
                      ├─ 满足原关闭策略及证据条件 → 自动关闭并保存依据
                      ├─ 需调查 → 自动升级 → 自动取证/知识查询/研判 → 结果/证据/报告可查

人工：已有告警 → Case/调查问题 → 人工发起调查 → 同类工具/知识/研判 → 结果/证据/报告可查
```

自动升级后无需人再次点击才能开始调查。人工链先接通是为了复用并核实公共工具/数据；不能把自动能力降为只给建议、只创建Run或只留入口。

## 自动调查专项覆盖

B4是完整业务批次，至少包含下列五段，不以“自动升级已调用一个函数”代替完成：

原版触发设计分两条，不是本轮新增需求：

- **规则触发playbook。** 原`playbook/store.py:200`的`find_matching`检查enabled、事件、severity及tags；`alert_trigger.py`从告警路径调用。playbook可含`investigate`步骤，`engine.py:405`调用Case调查API。它还有部署/preview/live限制；调查步骤缺Case上下文会skip。原模板已存在critical触发并包含调查的例子（`templates.py:47`及`:62`）。这些是代码设计证据，不等于本项目已启用或整链通过。
- **分诊后自动升级。** 原worker在分诊未自动关闭时调用`_maybe_escalate`→`run_escalation`，受`AISOC_AGENT_ESCALATE_TO_GRAPH`及writer许可控制，本地另有review_only限制。它不以单独的严重级别筛选作为触发条件。

迁移沿用原职责与路径；playbook仍按既定原则整体保留、额外改测暂缓，不借此次设计讨论增加新调查规则动作、优先级策略或通用引擎。普通自动调查的既有功能缺口仍按本计划原B4处理。

1. 告警自动触发受护worker和真实分诊，采用实际告警、组织/策略及所用上下文。
2. 满足原关闭策略且有支持证据时，canonical Alert状态和关闭理由实际保存；缺证/失败不自动关闭。
3. 需调查时由worker自动进入原run_escalation；跳过已完成的自动分诊，不重复调用分诊模型。
4. 自动执行增强、知识/上下文查询、调查分析及所需攻击路径步骤；结果区分事实、推断、未知和缺源。
5. 分诊结果、调查结果、证据/报告及用量可查询关联；若原graph只返回state、缺必要持久或报告出口，直接补接已有机制，不另建调查框架。

常规启动worker完成正常自动消费属于功能接入；不要求先完成R02常驻窗口、启动/退出或恢复矩阵。实施时只明确本批受控tenant、新输入、消费对象及模型调用边界，保留旧unknown与积压，不自动重放历史材料。模型分类/授权/时间理由若仍不正确，应先修本次实际输入或调用问题；不能无限循环提示词/盲测，也不能用review_only冒充完整自治交付。
