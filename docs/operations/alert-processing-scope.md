## 输入与交付边界

输入是外部已经形成的告警/finding，包含受控tenant归属、来源标识、发生时间、严重度、实体和证据引用。接收边界需要认证、校验、必要的告警字段映射、拒绝回执和来源追溯；不承接设备采集、原始日志解析、扫描及从普通事件生成告警。

当前功能主链为：

```text
已有告警 → 校验/受理 → 去重归并/关联/风险 → 分诊
    → 按策略自动关闭，或自动升级/人工调查
    → 工具/知识/上下文查询 → 结构化结论/证据/报告/处置建议
```

原有playbook、审批/响应和反馈等一体实现保留；playbook/反馈额外工作后置，真实响应仍按受控目标与审批，不因源码随整体迁入而自动启用。

交付是API响应、可查询的持久化记录、消息事件及需要时的报告文件。保留tenant、来源告警、Case、Run、Evidence、Approval、Action与结果之间的关系。没有前端也必须能检查状态、失败、unknown、调用记录和授权；不以页面、控制台、图表或浏览器交互作为验收条件。

原版Fusion已有 `RawAlert` 和 `aisoc.alerts.raw` 消费路径，可作为告警输入合同的核对起点；具体外部传输/认证/字段适配在接入批次验证。`RawAlert` 是融合前告警，不等于原始日志。当前没有因为范围对齐而改动订阅、开关或入口实现。
