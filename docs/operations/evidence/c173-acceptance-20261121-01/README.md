## 截断原因与失败兜底复核

两批实际聊天输入均低于上下文上限的八分之一，计入 Schema、安全余量和完整输出额度的预检也均通过。去除来源编号后，已核对的长证据行存在原样重复，重复部分低于这些行字符数的一成。两批生成都到达配置的 8192 输出 token，末尾空白超过响应字符数的九成。剥去尾部空白后，首个成员对象仍缺分隔符，没有闭合的可用分析单元。已复现默认生成约束允许在这个位置继续空白；两轮记录未识别触发连续空白的具体输入内容。

真实 HTTP 回执确认，原告警、分诊、事件资料、冻结输入范围、任务和轮次失败原因、原答工件仍可读取。事件诊断和业务判定字段存在，当前这两轮按合同为 `null`。首轮 Case 继续使用原始材料和已有分诊，保存独立结果及事件诊断缺口。失败 Run 不更新事件的当前诊断指针。

4173 已按当前 HTTP 合同修正诊断轮次读取。失败轮次现在直接显示失败原因，结论和模型判定按实际空值呈现。31 项服务模式页面测试和 37 项后端读取、部分交付与 Case 上游材料检查通过。该修正位于当前工作树。
