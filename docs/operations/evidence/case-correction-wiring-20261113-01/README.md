# C3/C6局部纠错的离线调用接线核验

2026-11-13。沿固定流程收口，只检查上一轮精简反馈是否进入真实调用代码，以及纠正仍失败时是否保留原答、失败和独立有效分析。没有发现新的业务接线缺口，本轮未修改业务代码、HTTP合同、数据库表或运行配置，未部署。

## 执行范围

[程序](replay.py)读取固定05批保存的C1、输入来源映射、C3原答1/2及C6原答5/6，经实际 `ModelSteps.call`、Case接收器、局部保留及最终Publication装配执行。网关只依序返回已保存原答，存储复用已有测试的内存Ledger，计量为明确标记的替身；不连接模型、数据库、HTTP或其他网络。没有创建Run，旧usage仅供重放校验，不是本轮新用量。

复用原冻结输入和profile，没有给旧原答换上新C3材料。程序从原冻结来源生成Schema，再通过实际provider/C3转换；两步首次请求均与原请求逐值相等，纠错请求均与上一轮预览逐值相等。纠错返回的是**历史第二答**，它不是模型对新反馈的响应，不能由此判断新反馈有效或无效。

每个环节网关替身只收到2份请求（首答和一次纠正），第二份请求关联第一份回答工件。内存保存的4份原答与旧回执逐值相等，两次失败原因、纠正前后工件关系及局部保留结果均可追溯；未对原答去重、补引用或改写。C3第二步记录为completed是因为返回了可保留的局部分析，仍同时记录原拒收原因；不能理解为整份原答通过。

C6的Publication为completed执行收尾、rejected校验、partial交付、unavailable结论，所有成员`conclusion_covered=false`。采用函数既有条件要求accepted且有有效模型结论，故这种结果不具备采用资格；**本轮没有执行数据库采用函数或GET**。真实存取继续复用[05批拒收读回](../fixed-investigation-20261112-05/flow/readback-checks.json)和[07批接受路径](../model-input-selection-20261112-07/README.md)，不重复跑数据库流程。
