## 3. 页面字段与真实数据缺口

下表的“缺失”是**该批保存材料没有提供**，不自动表示后端不存在相应表或字段。源字段NULL、未采集、缺关联和后端待接入分别列明。

| 页面元素 | 取值/转换依据 | 已有值及缺口 | 当前呈现/后续承接 |
| --- | --- | --- | --- |
| 告警标题、描述、严重程度 | canonical `title/description/severity` → 页面；high/critical合为高 | 20六条均可读；原值保在raw | 不根据标题重判等级 |
| 告警时间 | canonical `event_time`；上海时区显示 | 20/21六条均有；底层ISO精度保留 | 不用入库时间补发生时间 |
| 告警检测源 | 20 `original_input.source`；21 `enrichment_data.socai2_fusion.identity.source` | 两批均为 `showcase-security-sensor`，不是已核实的厂商名称 | 本轮修正原始数据页遗漏，raw没有source顶层时从已有告警source展示；原JSON不改 |
| 源记录ID | `detailMaterial.raw.source_ref` | 20六条未提供；21六条来自Fusion源身份 | 20显示“—”，不以canonical告警ID或rule_id冒充源记录ID |
| 类别/ATT&CK阶段 | 原输入 `mitre_tactics` → 分类展示；技术编号取 `mitre_techniques` | **20六条原输入均是Execution**，即使标题是凭据读取/上传也不按标题补改；21按原材料展示 | 事件按成员分类计数；阶段覆盖不是检测覆盖率或攻击成功率 |
| 检测置信度 | `alerts.confidence`，0—100 | 20/21六条均80；历史联合Case输入未提供 | 缺值保留“—” |
| 页面风险评分/AiSOC告警评分 | `alerts.ai_score × 100`，不是上游risk_score或Graph confidence | 20：95/65/95/85/95/95；21对应场景95或85等不同实际结果 | **含义是分诊判定置信度**；与判定一起理解，不聚合成事件分数 |
| 处理状态/分诊判定/Run完整性 | 告警status、disposition、Run status及completion分别读取 | 20/21均有5条调查partial及1条仅分诊关闭；Run completed不代表完整交付 | 保留分离语义，不因partial或Run结束关闭事件 |
| 告警负责人 | 源assigned_to关联用户目录 | 20canonical导出没有负责人字段；21本批未分配 | 页面未分配；需人员目录及写读接口，不能套用演示人员 |
| 涉及资产/对象 | 20原输入hostname/username/IP；21已保存entities与源输入 | 两批均未匹配真实库存，15条实际输入整体均没有可用库存关联 | 展示已有对象；`inventory=false`，不伪造库存ID、OS、风险级别、资产详情或标签 |
| 资产标签 | 库存 `assets.tags` | 实际输入未关联库存，两批均空 | 不使用告警标签或synthetic标记代替资产标签 |
| 发生了什么/Explain | 独立Explain返回summary及suggested_actions | 20六条没有保存Explain；21六条有模板兜底结果，llm_used=false；历史Case三输入没有Explain | 20正常空态；不能把调查报告或分诊理由冒充Explain |
| 原始数据 | 已白名单保存的canonical/raw_event/original_input | 保存的是允许展示的字段投影，非全库全字段；20无source_ref | 原样保留结构；不添加虚构原始日志 |
| 告警时间线 | event_time及已有分诊/调查事件 | 20有发生/分诊/结果交付；完整检测、人工分派、关闭审计等未全部采集 | 不自动补齐实际时间线；新增演示单独提供这些分支 |
| 自动处理步骤/工具 | delivery.audit_log / investigation_events | 20/21工具多数只有result_preview；graph_step常只有节点状态 | 保留部分返回、失败与跳过；不声称每步输入输出完整 |

| 事件状态/负责人/优先级 | 独立事件管理字段 | 六个实际事件组源状态未提供、owner未记录、priority=null | 按已确认本地规则默认新建；源缺状态另存sourceHandlingStatus。分配后处理中，人工解决；不代表后端已实现 |
| 事件更新时间 | 已保存成员时间汇总 | 无独立事件updated_at实际值 | 当前最大成员时间仅为前端汇总，不能声称源事件管理更新时间已取到 |
| 为什么关联在一起 | 共同对象ID及成员时间；独立关联规则另取 | 有共享主机/账号/IP；未保存归并rule_id、决策记录或事件关联置信度 | 展示共同线索和可回查告警；保留“当前记录未提供具体归并规则” |
| 事件关系图 | 源告警到已记录对象的关联 | 无完整实体间攻击因果、方向、授权关系或Attack Path结果 | 只画已有关系；Case中另看调查材料，不将线索画成确认攻击路径 |
| 事件处理活动 | 告警发生、Run已有事件和本地管理操作 | 原人工事件生命周期记录不完整 | 不以自动调查步骤冒充事件负责人操作 |
| Case关系 | `alerts.case_id`与真实Case成员；前端集合另有标识 | 20/21这12条原告警无后端Case，当前6个Case为本地整理集合；历史联合Case是真实身份 | 页面能进入本地集合；文档明确区别。新建/关联不等于后台创建或启动Run |
| 列表统计、管理、反馈、导出 | 当前加载集合及浏览器本地状态 | 不代表线上总体库存；管理/反馈/Case按钮尚未接真实写入 | 本轮只用现有交互演示，不把前端操作说成后端能力已完成 |
