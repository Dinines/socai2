## 两个环节分别做什么

| 环节 | 要判断什么、供谁使用 | 需要哪些材料 |
| --- | --- | --- |
| C3 | 初步解释本案行为、成员联系、可能性质/授权/影响，提出改变判断所需的关键补查；供C4取证、C6复核 | 成员原始事实、有效A判断、I结论及发现/反证/待核、实际业务查询结果、H原文和依据、适用知识 |
| C6 | 核对初步解释和补查是否得到证据支持，给出当前综合结论、已证影响和下一步建议；供Result/当前判断保存 | 原始事实、实际补查、C3必要解释/发现/问题答案/矛盾、Deep答案与支持反证、H、所需原计划/比较、适用知识 |

知识用于解释行为含义、提示需要核实什么，不能当作本案行为已经发生的证据；原始事实不能被前序总结替代。C6只在有可用指定历史结论时比较，否则沿用上批已实现的程序固定说明。

## 实际程序取舍

- **C3：选择有用的前序判断。** 无有效结论的历史Result不默认进入；I已有整体结论时，提供结论、业务限制、发现和待核，不再默认附加总览summary。没有整体结论时保留summary，明确依赖可保留原记录；没有删发现、反证或改写分析文字。
- **C6：不默认叠加所有前序层。** 有有效C3时，A/I判断、继承的历史判断和纯目录按结构化依赖提供；C3、Deep、H及原计划需要的支持/反证，从已冻结材料补回。独立人工反证、历史业务记录和原始成员事实仍保留。无有效C3时，保留A/I供独立综合。
- **C6：选择解释内容，不复制整份分析对象。** 保留C3的summary、findings（含反证/替代解释）、业务questions、conflicts和必要followups；成员概要、领域矩阵交由C6依据事实重新判断，不再作为另一份前序输入。已选正文逐字保持；知识、H及来源角色不变。
- **去掉不能帮助判断的程序材料。** 对象登记边`source_reports_object`不默认作为图关系提供，业务关系仍保留；告警内部来源域/厂商登记字段及已识别的I程序标记留后台，业务限制及未知文本保留。同步修正“补充程序事实”再次补回厂商字段的路径，不只在一处隐藏字段。

规则按结构、字段含义和本环节职责执行，没有按本例主机、账号、IP或文字做删改，没有新增摘要模型或语义筛选框架。所选知识仍为448字符业务卡，角色为参考材料。本批没有证明知识使用效果；C6仍承接07原C3的既有错误推断，不能把输入调整记成旧答案已经修好。
