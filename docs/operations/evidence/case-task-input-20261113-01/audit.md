## 实现与规格对应

- **C3形成初步解释和必要补查。** `case_c3_input_selection.py` 仅在同一I已有非空整体结论时默认省略总览summary；缺整体结论仍保留summary。无可用结论的历史Result不默认进入；明确引用可以覆盖上述省略。I发现、反证及待核仍保留，limitations只剔除配置中已识别的程序标记和当前冻结成员对应的triage标记，业务限制及未知文本保持。该规则不按本例主机、账号或正文关键词改写判断。
- **C6复核前序解释与事实。** `case_followup_selection.py` 保留C3的summary、findings、业务questions、conflicts及必要followups，省略members/domains矩阵；支持、反证和替代解释仍在所选结构中。`case_followup_input.py` 只在存在已接受C3时把A/I、历史判断及纯目录改为依赖材料，保留冻结行供C3、Deep、H及原计划的结构化引用恢复，并继续以原引用和原范围装配。无可用C3时不启用该省略，A/I背景仍可用于独立综合。
- **事实与独立反证不由C3替代。** 原始成员事实、业务查询结果、独立human_statement及包含未知业务字段的历史记录没有被当作整层前序判断删除；已有检查明确覆盖人工否认授权及0、false、有效空列表。恢复的A/I引用继续通过原映射关联证据，不改变来源角色或把历史判断变成本案观察。原件guard、接受前序的校验、profile一致性检查及输出适配仍保留。
- **目录与后台字段选择有明确边界。** C6仅默认省略配置的`source_reports_object`目录边，业务关系继续提供；所需原依赖按原角色处理。告警来源域/厂商登记字段同时从告警展示和补充程序事实投影移出，最终两份输入没有被补充事实重新带回这些字段。标题、业务时间和成员事实仍保留。
