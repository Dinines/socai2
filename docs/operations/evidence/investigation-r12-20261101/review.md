## A：非空查询没有解决来源推理

纠错后出现更严重的问题：

- 编造 **PID 4209**，声称原文 4200 错误并由工具纠正。实际 raw 为 4200，进程/网络 Tool 都没有 PID 字段，也没有父进程链；Tool 不支持“核实 WinWord→PowerShell”。
- 从 documentation address 推出“预期文档服务器/服务协议”，并把标记为合成测试与“没有攻击特征、无需阻断”混为一谈。样本身份可来自 Case/raw，服务器用途和行为安全仍不能凭空补全。
- 关系改成 supported behavioral_link，依据又声称工具形成完整行为链；来源对应、告警原文中的 PID 关联和 Tool 独立印证没有分开。
- 第 15 步因“未声明应用层协议（如 HTTPS）”触发协议规则。这是对**源材料未提供字段**的合理表述被误拒，属于待修校验缺陷；放过该句也不能使上述报告内容合格。
