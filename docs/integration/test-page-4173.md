## 启动和入口

历史记录里的 4173 对应旧 V1；当前仓库保留的测试页面源码是 `prototypes/security-pages-v2`，旧 V1 目录已不在当前检出中。本轮使用现有启动器恢复4173，后台进程只监听`127.0.0.1`，未修改页面源码或清除浏览器数据。启动日志位于本机`.local/logs/preview-4173-20261118-104728.log`；若重启电脑或进程退出，按下方命令启动。

在 socai2 仓库根目录执行（SpiritHub 中先进入 `server`）：

```sh
python3 prototypes/security-pages-v2/serve.py --port 4173
```

保持终端运行，Ctrl+C 停止。只需要 Python 3，不需要 npm install、打包、数据库或模型。只监听 `127.0.0.1`；其他电脑需在自己的检出中启动，不能把维护者的 localhost 当远程地址。已有端口占用时可用 `--port 4174`，下列 URL 相应替换。

## 默认打开时的数据是什么

| 数据来源 | 文件 | 能说明什么 |
| --- | --- | --- |
| 产品设计与交互样例 | `data.js`、`case-outcome-data.js`、`case-exploration-data.js`、`page-showcase-data.js` 等 | 展示功能与预期交互；样例结论、助手回复不是当前 API 执行结果 |
| 21 最新测试快照 | `socai2-recorded-preview4173-21-20261118-01.js` | 保存21新批次的真实结果和执行状态。两轮分别冻结1、2条告警，精确入口见[本批回执](../operations/evidence/preview4173-21-20261118-01/README.md) |
| 保存过的实际验收记录 | `socai2-recorded-*.js`、`persisted-case-data.js`、`recorded-examples.js` 等 | 展示对应批次的冻结数据；保留失败、partial、unknown，刷新不会自动从21更新 |
| 浏览器本地编辑 | 当前 origin 下 localStorage 的 `aisoc-workspace-v2` | 普通预览模式的修改仅在当前浏览器保存，不写21；4173与4174的浏览器存储分别独立 |
| 实时服务模式 | `service-workspace.js` 使用填写的 API 地址 | 实际读取/操作选定环境；账号所属租户和实际响应决定数据 |

初始数据数量随已收录记录变化，浏览器历史编辑也会改变显示数量，不用固定条数作为接口验收标准。要看干净样例可开新的浏览器配置或无痕窗口，不需要清除原有 localStorage。静态样例 ID（例如 `outcome-case-01`）不能传给真实 HTTP 接口；使用[当前测试数据](backend-test-guide.md)中的 UUID。

使用顺序：先看三类列表 → 打开详情 → 查看材料/当前判断/运行记录 → 对照[功能清单](../../deliverables/investigation-validation-20261106/frontend-feature-list.md)理解设计 → 到 Swagger 验证真实接口。问答示例可以展示设计，但真实 E19/E20 当前仍返回501，不能据按钮存在判断已实现。E21已有调查结果的采用已交付；页面示例不替代其HTTP验收。

实际快照的案件页保留页头和右下角的“询问 AI”。助手可以打开、关闭和预览提问范围，“案件问答待接入”时发送按钮禁用。演示案件可继续体验原有对话与保存流程。

## 若需要用此页面读取真实 API

2026-11-20候选已将现有操作接到当前异步合同：创建按实际 `allocations` 分别读取案件和首轮任务；“检查并更新调查/诊断”提交check，“重新调查/诊断”提交rerun，均独立GET任务状态。已受理且尚无Run时显示任务空态，旧pending Run不提供退役start按钮。读取失败保留已受理回执，再次读取不重复提交；跨主体返回不覆盖新页面。该接线的29项定向测试通过，真实服务批次进度见[本次回执](../operations/evidence/http-real-data-20261120-01/README.md)。

页面服务模式已在S4候选补齐Case/事件的风险属性管理和时间线，不承诺涵盖全部HTTP操作。正式部署仍需核对版本；操作、读取和错误行为见[S4页面交接](subject-risk-pages-s4-20261120.md)，后端完整联调以同版Swagger/HTTP为准。

1. 按[Swagger 配置说明](../../deploy/api-docs/README.md#选择调用哪个-api)建立本机28024到21的转发。
2. 打开 `http://127.0.0.1:4173/?data=service#/cases`。
3. “服务地址”填 **`http://127.0.0.1:28024/api/v1/socai2`**，这里需要包含业务前缀；本机隔离服务可填 `http://127.0.0.1:18024/api/v1/socai2`。
4. 可信HTTP联调使用[无认证头调用示例](backend-test-guide.md#2-先跑读取)。S4候选表单可留空凭据；若填写只保存在当前页面内存，不作为业务后端的接入要求。
5. 先只读查看列表、主体、Run、结果和任务，再在本批明确的测试主体操作。事件入口为`?data=service#/incidents`。服务模式的保存是实际写入，不是本地样例编辑。

现有测试页面拒绝非回环地址的明文 HTTP，所以直接填 `http://192.168.1.21:18024` 会被页面拒绝；本轮不改该页面逻辑，使用 localhost 转发即可。API 的 `AISOC_CORS_ORIGINS` 还需显式包含实际预览origin（默认为 `http://127.0.0.1:4173`），格式是逗号分隔文本，不能写JSON数组字符串；仅转发不自动解决跨域。不能连接时先用 curl/Swagger核对 API，不切回样例并当作真实数据。
