# 当前调查业务表与写入职责

2026-11-12，按当前 V1.1 实现分析。范围只包括本项目的 `socai2` 调查业务表；资产、用户、租户、来源配置等基础数据由业务后端负责。下文不把旧 AiSOC 的功能和公共表列入调查交付。

**当前保留 28 张调查表：24 张有主链业务写入、2 张有读取用途、2 张预留但仍有结构依赖。** 有写入路径不表示所有字段或所有产品操作都已实现；下表列出实际用途。清理完成状态见[本项任务](../../openspec/changes/archive/2026-11-12-remove-unused-investigation-graph-table/tasks.md)。

## 1 当前有业务写入的 24 张表

以下省略 `socai2.`。业务后端调用已有命令或供数适配入口，调查模块维护内部记录及版本；页面 GET 不写表。

| 表 | 实际保存内容 | 当前写入者与时机 |
| --- | --- | --- |
| `alerts` | 调查所需的告警身份、来源事实、当前材料/分诊引用 | 入站适配保存告警事实；A 分诊保存后更新分诊/解释指针。通用管理字段存在，不代表状态、分派等所有写操作已接完。 |
| `alert_materials` | 一份告警材料的原文、结构内容、版本、hash | 入站适配接到新材料时追加；历史材料不被新版本覆盖。 |
| `alert_source_refs` | 材料引用哪些来源事件及其命名空间、路径 | 与材料同次写入；只保存来源引用，不生产或采集原始日志。 |
| `alert_objects` | 材料中出现的主机、账号、IP、域名等对象和出处 | 入站适配从已收到材料提取。它是告警对象索引，不是资产库存表。 |
| `incidents` | 调查使用的事件主体、当前诊断引用 | 入站适配保存来源事件；I 完成后维护诊断引用。 |
| `incident_alerts` | 事件包含哪些告警、归并依据与关系来源 | 入站适配保存已确定关系；不是页面按主机/标题自行推定。 |
| `alert_assessments` | 告警分诊判定、理由、置信度、建议及材料/Run 来源 | A 分诊通过保存校验后追加 `kind=triage`。`human_feedback` 有存储与读取设计，但正式告警级人工反馈写入口未接。 |
| `incident_diagnoses` | 事件诊断尝试的状态、摘要、诊断正文和待核事项 | I 开始时建立尝试，完成/失败时保存实际结果或错误。 |
| `cases` | 案件主体、范围版本、分类/期限及当前判断、证据目录指针 | Case 命令建案、更新已接管理字段/范围，结果采用与证据保存更新对应指针。 |
| `case_alerts` | Case 的当前正式告警成员 | 建案、替换成员、关联或跨案移动命令维护；已冻结 Run 的范围不随之重写。 |
| `case_incidents` | Case 与事件的显式关联 | 建案/关联服务保存；与“共享某条告警”的间接关系分开。 |
| `runs` | 每轮 A/I/Case 的主体、状态、时限、停止原因和交付状态 | 执行服务创建、领取、结束；Case 的 prepare 建待更新 Run，start 才执行。 |
| `run_members` | 本轮成员及冻结的材料、分诊、反馈版本和分析状态 | 领取/冻结时保存输入指针，结束时保存实际处理情况。 |
| `run_steps` | 本轮阶段、模型、工具等执行步骤及实际状态、用量、错误 | 执行器围绕实际调用写入；父阶段与调用步骤分别记录。 |
| `artifacts` | 冻结输入、模型请求/原答、工具请求/结果、报告、图及证据目录 | 入站/执行/证据服务保存原件，按主体、Run、Step 及版本关联。不是让模型重写主体 ID 或执行状态。 |
| `results` | Case 本轮正式结果：结论、发现、问题、建议、比较和影响 | Case 发布服务保存通过装配/校验的结果及状态；结果可以部分交付或无可用结论。 |
| `result_members` | 正式结果对每个告警的分析与结论覆盖 | 与 Result 同次发布；被纳入 Run 不等于结论覆盖。 |
| `case_assessments` | 本案当前采用判断的版本、来源与有效性 | 发布后的采用逻辑建立判断版本；系统交接说明单独标为系统来源。 |
| `case_assessment_sources` | 该判断采用了哪些结果或系统交接工件 | 与判断一同保存来源；人工任务版本引用仍是预留能力，不列为已接写入。 |
| `case_assessment_members` | 该判断实际覆盖的告警 | 采用逻辑保存覆盖成员；与 Case 当前全体成员分开。 |
| `tasks` | Case 人工任务的稳定身份、来源及当前修订指针 | 人工任务 POST/PUT 创建任务或更新版本指针。 |
| `task_revisions` | 任务的每版状态、负责人、期限、人工结果、范围、完成人/时刻 | 人工创建/修订时追加；下一轮调查冻结所选版本，不覆盖旧轮输入。 |
| `activities` | 已实施的 Case/成员/任务/发布等业务操作及操作者 | 服务命令保存操作回执；不把模型调用步骤混作业务活动。 |
| `activity_targets` | 一次业务操作具体影响的目标、前后值、结果和原因 | 与 activity 同次保存，可包含多个目标。 |

入站实现在 [socai2_sink.py](../../services/fusion/app/services/socai2_sink.py)；A/I 保存见 [stage_results.py](../../services/api/app/socai2/stage_results.py)；Case 命令见 [case_service.py](../../services/api/app/socai2/case_service.py)，执行发布见 [baseline_store.py](../../services/api/app/socai2/baseline_store.py)，人工版本见 [human_task_service.py](../../services/api/app/socai2/human_task_service.py)。这些代码路径已核对，本轮没有重新调用模型证明质量。

## 3 后端接手边界

- 业务后端提供告警材料及明确的事件关系、租户/用户身份、资产或其他查询来源；调查侧保存本次实际收到/查询到的材料及来源。已有接入代码仍有外部表依赖，这次表清理不宣称已完成对后端自有存储的适配。
- 业务后端通过已接 Case/成员/人工任务命令发起操作；执行器保存 Run、Step、工件、正式结果和采用关系。接口细节见[数据交接](socai2-page-data-handoff-20261106.md)和[OpenAPI](../design/socai2-independent-api-v2.openapi.json)。
- 证据、报告、调查图、查询回执复用 `artifacts`；当前没有要求后端另建独立 evidence、report、graph、资产库存或旧 AiSOC 调查表。
- 告警人工反馈正式写入、Q 问答、探索保存、完整评论附件、真实响应操作、自动消费者和模型正文质量，不因已有表或部分接口而列为已完成。
- 当前表目录以[机器字典](../design/socai2-data-contract-current.json)和本项迁移结果为准；[冻结 V1 SQL](../../deploy/database/init_socai2_v1.sql)保留原件，包含的公共支撑表不是本次业务后端建表清单。
