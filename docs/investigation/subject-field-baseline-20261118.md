# 告警、事件、Case 字段审查与验收基准

2026-11-18。**业务必需不等于数据库 NOT NULL，也不等于 API 有同名键。** 负责人本轮明确：调查建立时需要系统给出的初始严重程度、优先级；形成结论后需要本轮严重程度意见和依据。待人工复核不免除这些产出责任，缺失必须列为功能缺口。

本页保留11-18审查基准；11-20[S1](../operations/evidence/subject-risk-s1-20261120-01/README.md)已补创建/读取，[S2](../operations/evidence/subject-risk-s2-20261120-01/README.md)补独立意见/自动上调，[S3](../operations/evidence/subject-risk-s3-20261120-01/README.md)补人工管理并通过候选存取验证；[S4页面候选](../operations/evidence/subject-risk-s4-20261120-01/README.md)现已通过直接验收及限定独审；正式未发布，未覆盖的页面缺口仍保留，以下11-18审查内容不追改。归属[主调查任务及分步安排](../../openspec/changes/complete-socai2-investigation-chain/subject-field-audit-20261118.md)，不新开一套任务树。证据为[只读核对](../operations/evidence/subject-field-audit-20261118-01/README.md)、已发布 80 操作 OpenAPI、当前写入/读取代码及 4173 实际页面；不以演示数据验收后台功能。

## 1. 先统一含义和产生责任

| 属性 | 业务含义 | 应由谁产生 | 与其他字段的关系 |
| --- | --- | --- | --- |
| 来源严重程度 | 检测源对原告警的评级 | 上游提供、程序规范化并保留原值 | 不是模型对整个事件/Case 的最终判断 |
| 系统严重程度意见 | 对本主体当前风险、潜在/已确认影响的等级判断及依据 | 建立时由明确规则给初值；分析后由本阶段模型给有范围的意见，程序验证保存 | 可以同时“高严重程度、证据不足待复核”；不能用置信度或处置状态替代 |
| 当前生效严重程度 | 列表和主体详情使用的等级 | 程序按已定义的系统意见/人工覆盖规则选取 | 必须说明来源；历史 Run 保持当时意见，不能读最新值覆盖过去 |
| 处理优先级 | 先处理谁、需要多快介入 | 程序按配置规则生成初值和依据，允许人工调整 | 不是恶意概率；不可直接把 AI 分诊置信度乘 100 填进去 |
| 业务判定 | 恶意/安全威胁、正常或已授权、误报、尚不能定性等判断 | 模型给本轮意见；人工可形成独立复核/采用版本 | “尚不能定性”是有效业务意见；不能因此省略严重程度和下一步 |
| 结论确定性 | 当前材料对结论的支持程度 | 模型输出、程序保存 | `supported/uncertain` 不等于恶意/良性，也不等于已人工复核 |
| 人工复核/采用 | 人是否审阅、是否采用，以及采用了哪一版 | 人工作出决定，程序记录人、时间、来源和版本 | `validation_state=accepted` 是程序接收，不是人工批准；自动采用也不是人工复核 |
| 处理状态 | 新建、处理中、完成/解决等业务生命周期 | 人工操作及已明确的程序状态规则 | Run 已结束不自动意味着 Case 已解决 |
| 响应建议 | 建议做什么、针对什么、为什么及限制 | A 或 C6 等既有分析环节输出 | 不需要为“展示建议”额外再问一次模型；建议不代表批准或执行 |
| 实际响应 | 已批准、已执行及执行结果 | 响应系统真实回执 | 没有回执只能显示未执行/未记录，不能由模型补造 |

“必须/可选”和“人工/模型”是两组维度：同一字段可以业务必需、系统先给、允许人工修改；不能把它们当作四个互斥分类。

## 2. 必需时点及缺失处理

- **建立时必需**：主体身份、名称、成员/来源关联、状态、时间、版本；事件和 Case 的当前严重程度及处理优先级要有可解释的系统初值。初值必须标明规则来源，不能伪装为已经完成的模型分析。
- **正常分析交付时必需**：本轮结论、依据、适用范围、未确定事项，以及本轮应承担的严重程度意见和后续处理意见。可以明确待复核，不可以“正常完成但永远未实现产出”。
- **条件必需**：人工覆盖时的操作者/时间/理由；分配后负责人；关闭后的关闭时间和说明；提出实际动作时目标和依据；第二轮比较时的指定基线或不可比较原因。
- **真正可选**：未发生的人工分配、未设置的截止时间、来源没有的厂商信息/标签/战术、未产生的附件/评论/实际响应等。空列表必须确实表示无记录；未查询、读取失败和未知不能写成空列表或 0。
- **模型或程序异常**：保留已有初值/上一有效意见并显示其来源、时间、范围和是否过期；本轮缺产出记为问题，不能冒充本轮已给意见。可用结果继续后续流程，不因一个属性缺失阻断整条链，也不能把该字段验收勾成通过。

## 3. 共同字段

下表字段名均为当前合同已有名称；写“目标”的是后续业务要求，不代表当前已实现。HTTP 必有键但值可空的细目见[合同摘录](../operations/evidence/subject-field-audit-20261118-01/contract-inventory.json)。

| 字段/字段组 | 必需条件 | 产生者；人工能否改 | 当前状态与验收要点 |
| --- | --- | --- | --- |
| `id`、后台 `tenant_id`、来源命名空间 | 建立时必需 | 程序/接入配置；不能当普通资料改 | 身份与关联后台保留。不得为防模型泄露删除关系；无判断用途的租户/测试控制标识不送模型 |
| `title` | 建立时必需 | 告警来自来源；事件由归并生成；Case 由请求/系统创建 | Case 可管理修改；不要求模型重复生成标题 |
| `description` | 可选；有值则保留原文 | 来源或人工 | 空说明不代表没有告警原件；不让程序语义改写原文 |
| `handling_status` | 建立时必需，后续按操作更新 | 程序状态机/人工 | A 的 `completed`、I/Case 的 `resolved` 与 Run `completed` 分开 |
| `owner_id/assignment_state/owner_source_value/assigned_at` | 分配状态必有；已分配时身份/时间条件必需 | 程序记录人工分配 | 未分配是合法状态；未解析负责人不伪装为未分配 |
| `tags` | 集合键必有，可 `[]` | 来源/人工 | 有标签不表示其内容是独立证据 |
| `priority_value/state/source/basis` | **目标：I/Case 建立后有系统值及依据；人工可调整** | 程序规则→人工覆盖 | 现有量纲 0–100，三主体字段已预留；本流程未找到系统写入链，管理 API 也无优先级修改。A 当前是可选已有优先级，不扩写其冻结合同 |
| 创建/接收/业务更新时间、`row_version` | 对应动作发生时必需 | 程序 | 不能让模型编时间；业务更新时间不是告警发生时间 |
| `reopened_at`、关闭/解决人、时间、说明 | 发生对应操作后条件必需 | 程序记录人工/既有规则操作 | 从未关闭则允许空；不能从模型“建议关闭”写为已关闭 |
| 评论、附件、人工任务、响应、关联对象 | 按实际有无提供，计数可为 0 | 程序保存真实记录，人工明确创建内容 | 模型建议不自动成为人工任务；未接外部响应不冒称“已处置” |

## 4. 告警字段矩阵

告警负责单条分诊，不把 Case 的全部输出机械复制到 A。告警交接字段冻结，本轮不修改字段名、枚举、空值或关联合同。

| 字段/字段组 | 必需/可选及产生时点 | 产生者；人工边界 | 当前实现与验收判断 |
| --- | --- | --- | --- |
| `source_alert_id/vendor_alert_id`、来源关联 | 可回溯身份必需；具体上游别名有则保存 | 接入程序；模型不生成 | 多种身份不强求每种都有；后台唯一标识与来源映射不能丢 |
| `connector_id/type/original_vendor/category` | 来源提供时保存，否则可空 | 上游/接入程序 | 不以厂商或测试来源名称推断恶意/良性 |
| `severity/severity_raw` | 正常接入应有来源等级；旧/异常材料缺失须显式披露 | 上游评级、程序规范化；当前管理接口不支持人工改告警等级 | 当前 Fusion 投影保存收到的等级；A 不产出新的严重程度。缺来源不能让界面暗补“低”，也不能冒称这是模型意见 |
| `event_time/event_time_source` | 发生时间有来源则必保留；来源缺失可空且注明 unknown | 上游/程序解析 | 不用 `ingested_at` 冒充发生时间；`first_seen_at/last_seen_at` 按实际观察保存 |
| `ingested_at/source_updated_at` | 接收/更新时必有 | 程序 | 与事件时间分别显示 |
| `latest_material_id`、材料版本/原文/OCSF/检测信息 | 接入后必须可定位已接收材料；内容可用性单列 | 程序保存原件及版本 | 模型只读取任务所需业务投影，不整包透传原件 |
| 对象、资产、来源引用、战术/技术 | 有明确来源时提供；可无资产台账匹配 | 来源/程序提取与关联 | 来源主机不等于已匹配台账；来源战术不等于已证实攻击链 |
| 分诊 `verdict` | 正常 A 分析后必需 | 模型给意见；人工反馈独立保存 | 已有 `true_positive/false_positive/benign/needs_review`，待复核合法；不要用默认“良性”补缺项 |
| `rationale`、解释 `explanation` | 正常 A 分析后必需 | 模型；不得偷偷覆盖历史原答 | 已有输出/保存；理由和解释用途不同，引用和正文质量分别验 |
| `decision_basis` / `source_refs` | 定性时有具体定性依据；待复核的 `decision_basis` 可 null | 模型引用，程序还原来源 | 已有内部合同；`needs_review` 不强迫伪造恶意/授权/误报证据 |
| `confidence/score_state` | 状态必有；只有有真实分数才给数值 | 模型/当前接收规则 | 对判定的置信度，可空且注明 not_computed；它不是严重程度或优先级 |
| `recommendations/limitations` | 集合必有；无建议可以为空但应能理解原因 | 模型；实际执行另记 | 已保存建议；缺事实时可建议补证，不能强造隔离或封禁 |
| `disposition/latest_feedback_id`、反馈理由 | 人工反馈后条件必需 | 人工，程序记录人/时间/版本 | 不替换原 `triage.verdict`；模型待核与人工意见并列可追溯 |
| 分诊 Run、材料版本、新鲜度、可用性 | 有分诊即必有真实关联 | 程序 | 最新指针不等于适配最新材料；失败/部分结果与旧有效结论分开展示 |

## 5. 事件字段矩阵

| 字段/字段组 | 必需/可选及产生时点 | 产生者；人工边界 | 当前实现与验收判断 |
| --- | --- | --- | --- |
| `source_incident_id`、成员关系及归并依据 | 建立时必需 | 程序归并/明确关联 | 共同对象和时间接近是关联依据，不自动证明攻击因果 |
| `member_count`、活动起止、未知时间/等级数量 | 有成员即可按真实材料计算 | 程序 | 不交给模型计数；未知不记成 0 |
| `severity_auto` | 建立后从已知成员派生 | 程序取成员最高等级 | 已实现；信息 < 低 < 中 < 高 < 严重。仅为来源汇总，不等于模型对整个事件的风险分析 |
| `severity_override/reason/at/by` | 人工设置时条件必需 | 人工、程序记录 | 已有管理入口；清除覆盖恢复成员派生值 |
| `severity_effective/source` | 建立后列表/详情必需 | 程序选人工覆盖，否则成员最高 | 已有 API；代表事件为 medium/member_max。4173 快照导入只取 override，错误显示“未记录” |

| `priority_*` | 目标：建立时给初值，分析后按政策更新；人工可改 | 程序规则/人工覆盖 | 字段存在，当前值为空；生产与修改链缺失 |
| 诊断 `summary/conclusion` | 正常 I 交付后必需 | 模型 | 已有保存/读取；未定性可以明确说明，不应强行有罪/无害 |
| `members/findings/open_questions/limitations` | 每轮按冻结成员给状态、发现和待核事项；无发现可空 | 模型分析，程序校验范围 | 已有；未选入、未分析、已分析但待核不同，不混为“已完成全部事件” |
| 结构化业务判定/当前分析意见 | 形成诊断后应可明确读取 | 模型意见、程序映射；人工复核另存 | 当前核心为自由结论正文，缺独立可筛选的事件判定属性；后续与 I 输出职责一起定，不从词语猜枚举 |
| `input_selection/analysis_coverage`、历史 Run、新鲜度 | 有诊断即有相应范围和真实状态 | 程序 | 已有选择/覆盖合同；待核成员算已阅读，不等于未执行 |
| 后续处理意见、`resolution_note/resolved_*` | 建议随诊断事实；解决后必须有说明和时间 | 问题/补证由模型；解决由人工/程序 | I 当前提供待核问题，无独立响应建议列表；Case 可承接深入调查。不得把问题列表写成已执行措施 |
| `case_receiving` 及关联 Case | 有接收目标时条件必需 | 程序 | 活跃目标、关闭/超期和承接关系不能由模型决定或伪造 |

## 6. Case / 调查字段矩阵

Case 是持续业务对象，Run 是一次执行，Result 是该次结果，current_assessment 是当前采用判断；四者不得混成一个“调查状态”。

| 字段/字段组 | 必需/可选及产生时点 | 产生者；人工边界 | 当前实现与验收判断 |
| --- | --- | --- | --- |
| `id/title`、成员/事件关系、`scope_revision` | 建立时必需，范围变更有版本 | 程序；人工可改名称、按规则调整成员 | 已有创建/关联/读取；不能用当前成员反填旧 Run |
| `severity/severity_source` | **建立时有系统初值；分析后有系统意见；当前生效值有来源** | 规则初值→本轮模型意见；人工覆盖独立记录 | 当前创建只取请求 severity，来源记 manual；后续可手改/承接旧值；**没有自动初值和 C6 意见写入链** |
| 严重程度依据、意见时点、适用范围 | 正常分析交付后必需 | 模型依据 + 程序绑定 Run/Result/范围 | 当前 C6 和 Result 没有相应结构，**功能缺口**；不能只让前端显示成员最高来宣称已完成 |
| `priority_value/state/source/basis` | **建立时有系统值和依据，允许人工修改** | 程序配置规则；人工覆盖 | 当前有列与读取，但没有当前流程生产及管理 API 写入，**功能缺口** |
| `handling_status`、负责人 | 状态必需；负责人可未分配 | 人工/程序状态规则 | 分析结束仍新建可能是合法人工流程状态；不等于分析未跑 |
| `classification` | 当前为人工/导入管理分类；尚未填写可空 | 人工/导入 | 枚举 true_positive/informational/false_positive；不能将 uncertain 自动塞成 false_positive，不能当作模型必产出的最终判定已实现 |
| **结构化系统业务判定**（目标业务项） | 正常 C6 交付后必需，可明确待复核 | 模型，本轮保存；人工结论另形成版本 | 已有结论正文与 supported/uncertain，**缺独立业务判定结构**；确定性不等于恶意/正常/误报 |
| `determination` / 当前采用结论 | 采用有效结果后必需 | 程序读取 `current_assessment.conclusion` | 已实现同源读取；不另造一份结论存储。自动采用不代表人工复核 |
| 本轮 `conclusion/conclusion_state/conclusion_origin` | 正常 C6 交付后必需 | 模型意见 + 程序真实来源 | 已有；异常系统收尾不是模型结论。当前两轮均 model/uncertain，原文保留 |
| `findings/support/counterevidence/limitations` | 分析后有结果结构，内容依实际证据 | 模型；程序还原证据关联 | 已有；空发现可以成立，缺必要依据另记问题，不能补造引用 |
| `questions`、领域分析、未确定事项 | 每轮明确做了哪些领域及哪些仍待核 | C3/Deep/C6 分工，程序按该 Run 读取 | 已有原件；当前采用摘要的 import `basis/unresolved` 固定空，需从实际所采用结果读取，不能把“不在摘要”解释为模型没分析 |
| `case_impact` | 正常 C6 交付后必有影响说明和范围 | 模型 | 已有 summary/supported_changes/cannot_generalize/affected_scope/next_steps。没有证实影响可以明确说明，不能等同于低严重程度 |
| `recommendations` | 正常 C6 交付后有建议或明确无建议理由 | C6 模型 | 两轮各 3 条已保存；现有结构含动作类别、目标、reason、来源和限制。页面只展示 investigate、折叠正文，属展示缺口；不必另开模型对话 |
| 建议审批/执行回执 | 真正审批/执行后条件必需 | 人工与业务响应服务 | 当前真实审批执行仍未接；不把模拟回执/模型措辞当执行。没有真实动作不强求制造一条响应 |
| `comparison_result_id/change_kind/change_summary` | 首轮明确 initial；后轮比较有指定身份或不可比较原因 | 程序冻结身份，模型作比较 | 已有；本批 R2 指向 R1；正文质量单验，不用最新成功轮替代失败轮身份 |
| `current_assessment_id`、来源、覆盖、新鲜度、采用时间 | 当前有判断时条件必需 | 程序自动采用或人工作决定 | 已有；采用结果不隐式修改 severity/classification。独立人工“是否复核”不能从 accepted 推断 |
| `due_at`、结案/重开字段、承接链 | 期限可选；发生结案/承接后条件必需 | 人工/程序 | 没设置期限正常；若未来有 SLA 规则再按规则必填，不由模型编期限 |
| 证据索引/数量、成员数、对象数、轮数、任务数 | 可按真实数据读取时必需 | 程序计算 | Case 轮数、A/I 执行数和人工任务数分别统计；当前本案只有 2 轮 Case，关联 6 个 A/I/C Run，不应全部称为 6 轮 Case |
| Run 输入、步骤、原答、用量、质量/交付状态 | 实际执行后必须可追溯 | 程序记录；模型不得编执行台账 | 缺失/失败/unknown 如实展示；`final_delivery_saved` 是技术结束原因，不能作为业务待核事项 |

## 7. 系统初值、人工覆盖和后轮更新设计

以下按负责人最新确认同步；[OpenSpec 定稿](../../openspec/changes/complete-socai2-investigation-chain/subject-field-audit-20261118.md)给出完整合同影响、步骤和验证。**尚未实现，不代表线上已具备这些能力**：

1. **建立时**：事件和 Case 按实际纳入成员的已知来源等级取最高，保存规则、成员版本和时间；全部未知时按配置以 medium 初始，标明“规则初值/待分析/来源等级缺失”，不冒充模型意见。
2. **分析时**：I/C6 在各自原有调用中输出本主体的等级意见、依据、潜在/已确认影响及不确定性。无需为每个属性新增一次问答。等级意见不等于已证实攻击；证据不足仍可给有说明的暂定风险意见，不能保证模型每次成功，异常按第 2 节处理。
3. **生效时**：每轮意见与当前值分存。自动只升不降，人工可升降；人工改过的当前值仍可被新的适用模型意见上调，不是永久人工锁。降低建议保存但不自动生效，时间线注明原因；相同等级不重复提醒。旧结果重放、较早轮次晚到和运行期间发生人工修改都不得撤销新人工操作。Case 清空等级、Incident 撤销覆盖的差异及兼容方案已在定稿 §4 明列，不能静默复用 null。
4. **优先级**：按当前生效等级映射 info=10、low=30、medium=50、high=75、critical=95，配置化并保存版本。第一版只用这套映射，不加置信度或资产乘数。人工覆盖保留，即使严重程度上调也只更新系统建议；人工撤销后恢复当前等级对应值。人工值可为 0–100，含 0；不猜填历史空值。
5. **紧急程度**：目前未发现独立 urgency 合同。用户所说“先处理/多快处理”先纳入处理优先级和其时效依据，不擅自再造第三个无定义评分。若要单独展示处置时限，需明确时间起点、规则和逾期含义。
6. **后轮**：按已确认的只升不降、冻结范围、人工修订号及幂等规则处理独立有效等级单元，部分交付不自动废弃完整单元；字段缺失保留当前值并记录本轮问题，流程继续。成员变化标明旧意见的范围/新鲜度，Run 历史不能被新值回填。

这会触及内部 I/C6 Schema、结果/意见保存、采用、查询和页面，不能只改提示词或把页面空值替换为常数。告警对外交接若需增量，须先列受影响字段/页面和兼容方案；本轮保持现行合同。
