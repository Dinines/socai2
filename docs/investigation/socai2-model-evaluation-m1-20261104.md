## 哪些是我们的设计问题

| 编号 | 本批确认事实 | 归因与后续修法 |
| --- | --- | --- |
| M1-D01 | 9B C3在0.162秒返回400；同时间窗网关报 `Grammar error: Unimplemented keys: ["uniqueItems"]` | 我们没有适配该后端支持的Schema子集。应显式生成兼容请求，唯一性仍在本地严格校验；不是模型分析能力失败，也不靠放宽结果校验或重试绕过 |
| M1-D02 | 两条新版DeepSeek A引用的实际字段都可见，但正文和结构化数组不一致 | 双份引用增加生成负担；原OCSF与raw副本还存在同值不同编号。改为单一结构化引用、服务端生成展示引用，保持可追溯，不能偷偷给原答补号冒充通过 |
| M1-D03 | I历史理由S20仍含上一轮S14，旧S14指历史查询，本轮S14却指tcp；任意输入正文出现S1还会触发“原值名为S1”的例外 | 历史引用命名空间与本轮混用，且字面值豁免范围过大。历史原件保持，投影隔离历史编号；豁免仅针对确切的原始名称值，不针对整段旧分析 |
| M1-D04 | C3两个准确的行为发现引用了原始观察，同时附带S22/S23告警时间；这两个时间被定义为source_label | 时间上下文和证明行为的依据共用support_ids，造成混合角色拒收。需明确区分上下文与观察依据，不能将所有source_label改为事实 |
| M1-D05 | 发送的Domain Schema允许undetermined同时带finding_ids，解析器则禁止；本批identity/insider触发 | 输出合同与本地条件未对齐。先明确待定领域是否允许关联已知事实，再让请求约束/提示与接收规则一致，不能靠模型猜未声明条件 |
| M1-D06 | 四份9B良性原答都被解析器接受 | “引用存在且至少有一条观察”只能证明活动有记录，不能证明良性/授权。必须区分行为证据与定性依据；防止测试标签或空查询变成降级依据 |

另外，9B仍无视明确的标签/授权边界，属于本配置下实测的模型输出问题；DeepSeek旧网络答复的HTTPS、当前进程答复的“受管”也属于具体事实越界。不能把这些归给数据未传或输出截断：本批必需字段完整可见，11答均完整。

离线诊断只在内存中去掉C3两处时间引用，随后暴露领域关联错误；再去掉两处待定领域链接后解析通过。**这只是定位后续阻断点，不是修复原答或采纳结果。** 原答与业务状态均保持。详见[离线诊断](../operations/evidence/socai2-model-comparison-20261104/m1/offline-diagnostics.json)和[400及请求一致性核验](../operations/evidence/socai2-model-comparison-20261104/m1/remote-verification.json)。

## 输出如何判定

分别记录原答结论、自报置信度、Schema 有效性、当前引用解析器结果和人工语义核对。旧/新输入都使用固定的当前解析器检查，不能把结果当旧解析器的复现。程序通过不等于语义通过。

核对重点为：来源/测试标签不能证明良性或授权；空查询不是反证；TCP443不能推定HTTPS；网络记录的PID/用户未知；同主机近时间不能证明进程引发连接；存储完整不能宣称全文审阅；预算跳过不等于来源未接通。保留所有失败/未知，不挑重跑结果。

每模型每格只有一次，且仅两个合成来源，不能推导通用准确率。已确认这两个A的判定未改变，但不能外推为所有输入的结论均不受影响，也不能把7份解析通过当成7份语义合格。
