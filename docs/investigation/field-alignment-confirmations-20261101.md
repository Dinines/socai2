# 远端告警事件需求与Fusion调查实现对照

2026-11-01，以远端功能分析中最新告警页、事件页及字段对照为需求基准，判断当前Fusion及调查实现能否正确保存和使用收到的数据、支撑对应功能，并定位缺口、偏差和影响。用户已明确模块名是Fusion。核对从Fusion接收输入开始，继续贯穿处理、持久化、关联、分诊/业务管理、API、Case调查输入、Tool补查和报告。

**最新范围边界：用户明确Fusion前置输入数据的问题不用处理。** 输入本来缺失、不准确或上游规范化不到位，只注明输入限制，不追查、不修复、不要求补数据，也不作为本轮待办或验收阻塞。仍核输入已有但Fusion及下游漏传、替换、错误合并、未入库或误用的问题；未知值被我们当成确定事实展示／分析，也属于下游处理问题。

“调查页面暂不考虑”仅排除该页面本身的设计比对，不排除调查后端。此前持续确认展示与交互规则、并把Case数据核对整体后置，均把任务收窄了。第1—15项已确认口径继续有效；第3—6项Case输入决定重新纳入完整数据链评估，不因页面有字段就全部送入模型，也不因模型缺字段就判定上游没有数据。

r13报告问题保留于[问题记录](../operations/evidence/investigation-r13-20261101/review.md)：A报告截断，B空查询反证化、审批语义及Tool编号错误。报告修复暂缓，5.3仍未完成；本次字段确认不再以报告达标为前提，不重跑r13。

### 每段如何核对和交付

每项使用同一结构：“页面功能/字段→Fusion实际收到的输入→转换/入库位置→下游读取和使用→具体断点→页面/调查影响→最小修复→证据及未验范围”。源数据未提供或不准确归输入限制、排除待办；处理中丢失或改义、未持久化、读取投影遗漏、功能未接通和报告使用偏差继续核对。后续段次沿用同一项结论继续追踪，不重复抄写同一缺口。

先读代码和已有材料，再补必要的直接验证。已保存的Fusion来源材料、页面字段对照和r10—r13调查材料按适用范围复用；保留样本的入口、版本、时间和真实/演示性质。手工入库fixture或前端静态样本不能证明真实Fusion路径完整，源码有写入逻辑也不能证明线上样本非空。缺少某段实际原件时明确标为未验，先用代码定位，不为填满表格制造样本或重跑全部案例。

每段结束给出一份短结论：已支持的能力、已定位缺口、对下游的影响、最小修复建议，以及真正需要用户决定的业务语义。对应阶段的核心字段和功能必须有结论或明确未验原因，才标记该段“核对完成”；这不等同缺陷已修复或真实验收通过。尚未修复的问题带入后续段继续分析影响，不把逐段全部修完设置成新的前置门。

疑问先查来源与实现；只有仍未定的业务含义才逐项询问。已确认规则直接沿用，不为每段新增审批/独审环节。实际修复和验证按具体缺口安排，复用未变化的通过证据，不扩通用框架、权限/恢复/压力专项或冗余测试。

## 已有决定直接沿用

- 检测源只显示原始日志厂商/产品；未知留空，不用接入平台或自由来源标识补位。
- 类别列取MITRE战术，不拿通用category或技术编号代替；资产标签取资产表，不拿告警标签代替。
- 告警分配/认领不改处理状态；启动调查算进行中。事件状态独立，不从成员或Run状态推算。
- 发生时间与入库时间分开；缺原始时间不静默用created_at冒充。
- 创建/关联Case与启动调查分开；事件汇总，实际调查在Case。旧Run保留当时成员范围。
- 数据中的平台告警ID、Fusion来源ID、external_id和原始事件ID各有含义，缺值不相互冒充。远端合同原先待确认的源记录ID含义，已由用户在第2项明确为Fusion接入来源编号；canonical ID或规则ID不能用于拼造该编号。

## 第1项 检测源缺失时的处理

**事实：** `identity.source`是自由来源标识，不能保证是原始厂商名。v2告警调查上下文及事件成员目前也未完整输出它；`connector_type`和连接器名称不能无条件替代原厂。

**用户已确认：** “检测源只显示原始厂商，未知就留空”。
