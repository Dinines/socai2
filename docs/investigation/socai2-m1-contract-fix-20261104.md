## 数据库、工件和读取

无 DDL、ORM 或业务表列变更，仍为 `socai2` 29 表 459 列。原请求/回复、诊断和映射继续使用 `artifacts.content_json`；A 的 decision_basis 在模型原答内，正式分诊的 source_refs 仍来自校验后的 evidence_ids，没有新增独立依据表。

新 model_request 的 provider 元数据保存 schema_profile，payload.body 是转换后实际发送体。分组输入 v3 与准备视图 v4 保持旧视图读兼容；不回算历史 Run，也不把离线解析通过写成历史成功。

领域工件的 analysis_block 合同新增可选 applicability 枚举（applicable / not_applicable / undetermined），运行 Schema、设计 JSON Schema、数据字典合同三份同步。新 C3/C6 必须写实际值；可选是为了读取旧块和共用 Deep 块，不代表可由 findings 推断。

原服务、共享 LiteLLM、独立 DeepSeek profile、页面和消费者均未修改。本批 PG 操作仅在既有合成验证库 `socai2_schema_review_20261103_a1`，不是独立运行库或原业务库。验证使用临时受限角色和隧道，完成后清理。

## 两条告警的例子

1. A0 原始材料记载 PowerShell 活动，A1 记载 TCP 外联；Synthetic/fixture 等仍按来源标签传入。不能删除标签让测试变容易，也不能以这些标签证明良性。
2. A 若给 benign，必须另外指出“哪条事实或人工确认支持授权/预期行为”。仅把 fixture 标题列为 decision_basis 会被拒绝；引用了行为观察但错误解释成授权，仍可能通过结构检查，须在真实质量验收中判失败。
3. I 冻结两份有效分诊及其原理由。如果旧理由写 S14，新请求使用 N1_S…；旧 S14 不会变成本轮 TCP 字段。正文多写了一个已知当前编号，只留 warning，不把它偷偷补到正式证据数组。
4. C3 的“某时发生 PowerShell 活动”可同时引用活动观察和该成员时间；只引用时间不行。身份领域可保留这条相关事实，同时标 undetermined、待核账号授权。
5. Deep 补查和 C6 最终综合使用各自请求的编号映射。历史比较保留原范围、原结果及新成员，不沿用当前编号解释旧答。旧原答作为诊断材料，不作为新输入下的模型效果。

## 验证与证据

纯检查最新 56 项通过（其中本批新增 13 个参数化场景）；后续字面名助手与领域工件合同各作 1 项定向复核，均为已计入用例，不额外累加不同用例数。覆盖明确后端配置、旧编号隔离、原文保持、展示 warning、未知/错成员拒绝、独立定性依据、时间与领域边界。m1 的 DeepSeek C3 原答不删字不改引用即可由新规则解析；这只是合同修正验证，不采纳该旧结果，也不证明整案语义全部正确。

PG 验证按 A 4、I 2、C3 2、完整执行器 2、C6 历史比较 1 共 11 个不同方法记录；实际 SQL/事务，模型和湖返回使用替身。包括标签依据被拒且已有成功指针保持，C3→Deep→Deep→C6 的原预算编排，以及冻结旧范围/新成员比较。各方法最终状态和原失败见[机器回执](../operations/socai2-m1-contract-fix-20261104.json)。

初次失败均保留：旧测试夹具未跟新必填字段/编号/版本同步；新编号扫描将 Tool UUID 对象错误交给 JSON 序列化，已改为只递归扫描文本；领域工件 applicability 和请求工件 schema_profile 两处新增属性的 Schema 分别漏同步，已同步三份合同。不能描述为首次全绿。

同冻结材料的本地输入计量：A0 4,988B、A1 5,864B、I 7,926B、C3 7,946B。均在原 8KiB 用户材料额度内；I/C 两成员的必需事实与有效同次分诊完整可见，可选字段仍有明确省略。不是所有字段全量送模，也不是 tokens 实测。完整消息及请求预留仍按原额度，不提高调用/输出/执行预算。
