## 修复实际起了什么作用

1. **新增依据门有实际拦截效果。** A0主引用中有 observation，旧的“存在任何直接来源”条件会成立；本次显式依据中混有来源标签，新增门将它拒收。A1本次全为标签，主证据门和新依据门都拒收。两份原答未改写、未入业务判断。
2. **来源角色仍不能证明主张为真。** 离线复制 A0 原答，仅从 decision_basis.source_ids 中移走标签、保留原用户名和主机名，错误授权主张保持不变，解析器仍会接受。该反例没有调用模型、没有改原答或采纳。它证明还不能把“结构/角色通过”作为授权事实成立的保证。
3. **历史编号隔离已进入实际请求。** 新来源使用 N1_S…，历史分诊的 S14 原文保持。正式引用按当前映射检查，没有将旧 S14 重解释为当前 TCP 字段。本批 Deep A没有答复，因此“合法正文编号仅warning”在该路径仍只有本地验证，不能宣称真实 A 已验。
4. **领域关联规则得到新答验证。** Deep C3的 identity/insider 均为 undetermined，同时分别关联 F1/F2，程序接受。新答的 observed 发现并未附时间标签；“观察+时间上下文”例外本批仍只由旧原答离线回放验证，不能混称新实测覆盖。
5. **小后端 Schema 不再含 uniqueItems，本地重复检查仍生效。** I的小模型重复引用仍被拒，没有为了兼容关闭唯一性检查。C3只有超时，没有答复，不能证明其全部 Schema/输出路径已兼容。
