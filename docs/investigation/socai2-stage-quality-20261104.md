# A/I真实首批问题与最小修复

本页只记录A/I质量修复；新版独立服务的完整验收由当前OpenSpec 3.7继续。原始n4、r1请求/回复/用量及已保存结果不改写，旧r13不在本批范围。

## 实际问题

固定合成材料的三个真实调用，原件保存在[首批导出](../operations/evidence/socai2-next-acceptance-20261104/20261104T052345-export/receipt.json)。A0和A1结构通过但语义不合格：前者把“规则命中”解释成true_positive，同时声称行为良性；两者把来源的测试标识/厂商/环境自述当成授权或无害证明。A1正文还出现内部S编号。I返回的limitations有null/字符串，严格合同拒收，且原答仍把先前分诊提升为事实，并将一条成员的用户泛化到另一条。

成功HTTP或已完成Run不能核销这些问题。A0原答的自然语言真假也不能靠新增结构校验自动证明。

## 修改及边界

| 修改 | 实际行为 |
| --- | --- |
| 判定含义 | 提示明确true_positive表示有据成立的恶意/威胁，false_positive表示有据证明描述不成立，benign表示真实行为有正常/授权依据，needs_review表示不足或矛盾；检测命中不能代替威胁判定 |
| 原字段角色 | A/I共用字段路径分类：metadata/product/rule/detection/tags/labels/enrichment及无法识别的注释保source_label；明确process/actor/user/端点/网络/文件/活动等记录字段保observation。分类不检查某个fixture名或Synthetic值；字段原值/引用路径/冻结原件保持 |
| 分诊引用 | I提示明确triage_usable只表示版本配对有效，不证明判断正确；判定与理由冲突仍须核实，成员属性不得搬给其他成员 |
| 数组合同 | 提示明确空数组使用[]；parser仍拒null和字符串，不做静默归一、不重试模型 |
| 正文来源编号 | 仅对本次实际可见S别名按词边界核查，拒其泄入理由/解释/总结等叙述；若真实可见原值本身含该标识（例如账号S1），允许原值被正常描述。它不是通用事实或因果校验 |

未改表、DDL、公共枚举、预算、模型调用次数、输出tokens、网关、旧结果、自动处置或人工状态。未知注释仍可读取，但不能单独满足确定判定的直接来源要求。新提示是否改善真实推理，必须在新候选、不同operation_key的新批次验证，不重发已结束的r1挑选结果。

## 验证

[固定汇总](../operations/socai2-stage-quality-20261104.json)记录5个纯函数边界检查、2个新增真实PG检查和4个受影响回归的最新结果。PG只使用既有独立合成库，模型为明确替身。新增A测试首轮误从alert_assessments读取保存在Explain工件的source_refs，原失败保留；仅修测试读取路径后定向通过。
