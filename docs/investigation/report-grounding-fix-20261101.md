## 修改与作用

1. **具体PID/账号按所引字段核对。** 新增小型纯校验模块，检查摘要、发现、成员判断和关系依据中的明确PID/账号写法。发现/成员/关系只使用该条引用的来源；摘要使用当前原始来源集合。A仅取description/raw_event及用户实体，E仅取成功返回的rows对应字段；标题、saved_analysis、T/H既有判断及查询参数不作为这些值的事实依据。明确写成Tool观察时，仅能使用引用Tool实际返回的字段。原文4200不能支撑4209，也不能因为A有4200就写E核实了4200。完整诊断保留字段路径，不以分数代替检查。
2. **修正两种实际协议误拒。** 允许“未声明应用层协议（如HTTPS）”与“无法分析……或确认是否为HTTPS”。保留无据肯定/否定、双重否定、混合其他协议断言和跨版本断言的拒收；联合句式不能掩盖前半句已肯定的其他协议。
3. **保留已知坏报告的拒收。** 成功空查询场景检查r10/r12已经出现的接入/捕获、清洗/丢失、范围不匹配和采样原因推测。检查限定到引用空查询的判断，或明确讨论查询的摘要/缺口/反证；不拿其他来源未接入的说明冒充空查询原因。明确表示无法判断原因、不能证明日志丢失可以保留。新增拦截r12的`evidence_id_list_`占位文本。
4. **一次纠错收到多项可判定错误。** 成员自身来源引用校验移至报告校验阶段，与来源值、协议和占位文本错误一同返回。越界/重复成员及结构错误仍在映射阶段拒绝；没有为了聚合而放行它们。内部错误码及字段诊断留在账本，模型只收到位置和可读约束，不回灌被拒原答，仍最多纠错一次。
5. **精简并对齐报告提示。** 要求原文陈述、Tool观察、推断分项，摘要不增加事实；共同背景支持shared_context，原文PID关联不冒充Tool独立印证或已确认攻击链；建议也不能预设注入或日志丢失已经发生。保持原schema、公开结果、账本、预算和历史读回合同，不新增Case记忆层或模型。
