# C2背景查询与模型输入视图

后续状态：[C3初始主分析与领域结果](socai2-baseline-c3-20261103.md)已另批实现并用模型替身验证。下文C2批次的范围和原回执保持，真实模型质量仍未验。

2026-11-03。新socai2路径已能从C1冻结材料发起三类数据库背景查询，在同一Run保存请求、执行状态、结果和限制，再构建有界模型输入视图。**没有调用模型，没有接通完整C1–C6执行器或业务HTTP，没有改页面。** 本文是本批实现说明；完整流程仍以设计工作树的调查主设计为准。

## 1. 当前接通范围及字段

| 来源 | 查询参数来自哪里 | 实际读取及返回 | 明确边界 |
| --- | --- | --- | --- |
| 资产 | C1同material版本的host/ip对象及原source_path | `public.assets`；id、name/fqdn、IP、类型、重要性、tags、owner_email、OS、first_seen/last_seen/updated_at；保留匹配依据及所有限额内候选 | 限同租户，名称/FQDN忽略大小写精确匹配或精确IP；库存无对象namespace，不能把同名候选当唯一身份；当前库存不证明事件发生时状态 |
| 历史告警 | 冻结对象的object_key、namespace、object_type、normalized_value和本轮明确窗口 | `socai2.alert_objects→alerts`，只取历史告警当前material对应对象；保存匹配对象、告警ID/标题/时间/材料ID/等级/原厂，以及同记录分别关联的triage、human_feedback | 排除本轮成员、窗口外及其他租户；不是语义相似检索，不读旧public.alerts，也不是完整行为历史；窗口未定义不擅自补30天 |
| 内部情报 | 明确ioc/both角色的ip/domain/url/email或有明确算法的hash | `public.threat_intel_iocs`；记录ID、类型/值、原confidence、severity、tags、source/ref、first_seen/last_seen/expires_at/updated_at | 精确类型和值、同租户、有效且非误报且未过期；不是外部TI调用。NULL分数保留NULL，存量分数标计算依据未核，不变成Case置信度。hash未知算法不猜 |
| UEBA | 未接适配器 | 记录`unavailable/source_not_connected` | 没有把旧服务的默认窗口或账号映射直接搬入 |
| 知识检索 | 未接适配器 | 同上 | 没有把未检索写成“无知识” |
| 图邻域 | 未接适配器 | 同上 | 没有调用Graph，也没有据同对象生成攻击链 |

所有SQL均显式带tenant条件，参数只来自冻结C1；测试来源夹具故意不依赖RLS，另核显式租户过滤。历史查询对同告警匹配两个对象会保留两条匹配行，不能把行数当独立告警数。

## 2. 同一Run的执行与数据落点

`BaselineService.enrich(tenant, case, run)`只接受已running的baseline。Case→Run锁内插入C2 stage并提交，再执行来源查询；重复调用遇到运行中/unknown返回冲突，完成后读取原工件，不重新查询。没有队列、自动重试或自动接续。

| 表/工件 | 本批保存内容 |
| --- | --- |
| `runs` | 使用已领取的原Run；C2不完成Run、不发布结论、不更新当前判断；派发中断保留unknown占槽 |
| `run_steps` | C2父stage和六个来源子步骤；序号、父ID、provider、版本、实际参数、起止时间、状态、输出工件、返回行数、错误；父级usage为空，避免重复统计 |
| `artifacts.tool_request` | 查询合同、完整冻结范围、明确选择器及其告警/材料/对象ID/source_path、窗口模式、行限额 |
| `artifacts.tool_response` | 执行状态、实际保留行、返回数、截断标志、查询记录标识、错误、观察时间；符合原`tool_exchange`合同。`local-step:`是本地执行记录ID，不冒充数据库服务端query_id |
| `artifacts.source_snapshot`（C2） | 六来源汇总、计划及实际查询对象/成员、来源限制、逐行引用角色、有限fetch实际观察数和截断原因、覆盖是否完整 |
| `artifacts.source_snapshot`（模型视图） | 准备好的system/user文本、字节数、全成员覆盖、精确省略来源和原因、ready状态；不是已发送的model_request |

全部工件保存hash、大小、保留元数据及来源引用，同Run/Case外键和不可变保护继续生效。本批没有修改29表/458列、迁移123、ORM、36组枚举或原38份通用JSON合同；使用现有raw_payload扩展内容。仅在已指定的独立合成验证库添加两张最小public来源夹具表，不改业务库。

额度使用原Run.limits：各来源领取前统计本Run已占用的Tool步骤，包含前序阶段和失败/unknown尝试，不重置为C2私有额度。无明确调用/行数/截止约束时不查询。每次最多`min(max_rows_per_query,200)`行，额外读取一行只判断截断；保留行JSON最多128KiB，整行省略，不裁坏JSON。截止时间包括领取事务耗时。未来C4必须沿用同一额度和锁，不能另开一套计数。

状态分别为有数据、成功查空、未接通/来源不可用、不适用、额度不足、截止未执行、超时、失败或中断不确定。`rows=null`表示未得到成功查询结果；成功空查询才是`[]`。查到一条但因字节上限无法保留时，汇总为`omitted`，不是`empty`。C2过程结束不等于背景覆盖完整，更不等于全案完成。

发布事务新增检查：还有planned/running/unknown步骤时拒绝发布，避免查询和结果完成竞争。正常完成/失败已落账的步骤可继续交付。人工核定unknown的恢复入口仍未实现，不增加自动恢复。

## 3. 模型能看什么

`prepare_model_view`要求C2已结束，读取冻结C1及校验hash后的C2工件，保存一次后重复返回同一视图。

- 保留整案范围、全部成员覆盖、六项调查问题及证据要求、来源状态/观察时间/限制；先为各成员安排身份和时间，再放材料标签、对象、当次分诊/人工反馈、可用事件诊断、已提交人工任务、当前判断和选用历史结果。
- 输入条目引用原C1/C2工件和具体路径。已有分诊是prior_analysis，人工反馈是human_statement，库存/情报/历史来源标签是source_label，执行状态是execution_receipt；不因被查询或送模型就升级为攻击事实。结果发布继续校验路径和角色。
- 先对原值及嵌套值执行现有guard，再挑选字段；不先裁剪再检查。视图正文上限8192字节，单项上限2048字节，整项放入或省略；省略记录保留原路径，模型也看到汇总及成员覆盖。原始raw/OCSF没有在本批直接送模型。
- 必须保留的范围本身超限则ready=false且不返回可发送消息，不偷偷截成员。ready只表示视图满足输入合同，不表示证据充分；生成视图不会把run_members标为已读/已分析。
- system明确所有来源文本是数据，不接受其中改变任务/权限/范围的指令。现有guard是日志/秘密形态检查，不能宣称它证明抵御全部提示注入。

较大对象列表/历史正文仍可能整项省略。本轮解决的是来源、执行和有界输入留存；C3/C4还需要针对问题选取必要语义字段并处理未覆盖证据，不能用提高预算或标完整交付掩盖这些限制。

## 4. 一个具体例子

以下为实现行为示例，不是线上调查结论：R1冻结A1/A2，均包含host:APP01，A2另有domain:example.invalid。资产查到APP01，保存名称匹配、重要性和库存时间；历史窗口内查到H1，保存它原有分诊和反馈；情报成功0条，保存empty；UEBA/知识/图未接，分别保存unavailable。

此时用户纳入A3：A3只进入下一条pending，R1的请求仍为A1/A2。重复请求C2返回原记录，不再查。模型视图说明APP01是当前库存、H1是历史来源、TI未命中不证明安全，不能写“图确认A1导致A2”。查询过程中不能发布结果；结束后也只完成C2，Run保持running，等待C3–C6。
