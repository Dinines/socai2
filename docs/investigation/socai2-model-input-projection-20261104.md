# 已收到字段进入 A / I / C3 模型的修复

本批针对独立新服务 n6。范围是 Fusion 已收到并已持久化的数据；不要求上游补字段，不改页面、不建表，不重写历史 Run。原始材料、C1 冻结记录、版本与来源路径保持。

## 确认的缺口

| 路径 | 修复前 | 现在 |
| --- | --- | --- |
| A 单告警 | 原字段存在，但元数据与行为字段争用同一输入限额 | 先读明确进程、账户、主机、端点、协议和动作字段；标签和其他原字段后置，值不按测试样本特判 |
| I 事件诊断 | 大块成员关系、旧分诊与标签靠前，已收到命令行、网络端点可能被额度挤出 | 各成员轮流放入必要行为字段，来源只关联自己的成员；精简对象/归并记录的内部存储元数据 |
| C3 初始调查 | 只读 C1 元数据，原材料语义直到后续 C4 才读；真实 r2 首次分析没有 observation 字段 | 按 C1 冻结的 material_id 读取必要原字段，先放行为事实，再放可用人工反馈、标签和已有判断；不会跟随 latest_material_id 切到新版本 |
| 明确 OCSF 路径 | 缺 user.name、device.hostname、network.protocol_name 的读取 | 补这三个通用路径；若与已有路径冲突则并存并标冲突，不推定哪一值正确 |
| 省略记录 | A/I 只有汇总数量 | 请求工件保存来源路径及省略原因；明细最多 16 KiB，保存总数和是否截断，完整原件仍在冻结材料中 |
| C6 剩余额度 | Schema 增大请求后，原先可运行的最终交付可能因额度不足跳过 | 只在原预算不足时按既有候选优先级移除末尾可选值，同步来源枚举、覆盖数和省略记录；成员/问题/来源状态等必需目录不删，仍不足就停止 |

字段单值 2 KiB、模型数据 8 KiB、完整消息 12 KiB、单回复 3000 tokens，以及同 Run 原模型/工具/总 tokens/时间上限保持。元数据原值不从数据库删除；仅不再让 hash、retention 等存储细节优先占用模型输入。所谓 observation 是“原记录声称的字段”，不代表独立核验事实或授权证明。

C3 将确实进入模型视图的材料标记为已读取选定字段；不等于完整原文已经审阅、模型分析完成。旧 Run 已存在的视图继续按原 hash 读取，不重建、回填或覆盖。
