# 告警、事件与调查产品需求说明

更新日期：2026-11-02。

本文是告警、事件与 Case 调查的统一产品需求入口，面向产品、设计、研发和验收人员。内容按当前业务规则与用户流程组织；页面功能、操作结果、跳转及验收要求在对应章节描述。尚未确定的事项集中放在最后一节。

当前交付为可交互页面原型。资料阅读、成员管理、图谱探索、人工记录和 AI 结果保存具有本地交互；真实 AI 执行、工具调度、基础调查自动更新、服务端持久化及响应执行尚未接入。本文区分产品要求和预览能力，具体交付范围见第 15 节。所有页面链接均要求本机预览服务运行。

## 1 产品目标与范围

### 1.1 产品要解决的问题

帮助安全分析员从单条告警进入关联事件，再围绕 Case 持续核查事实、积累证据和协作处理。使用者应能清楚回答：

1. 发生了什么，哪些告警和对象与此有关？
2. 为什么这些告警被关联，依据能否回查？
3. 已经调查了什么，当前判断适用于哪些输入？
4. 每次调查新增了什么发现，对案件认识有什么影响？
5. 还缺什么，哪些可以由 AI 查询，哪些需要人确认？
6. 下一步应查看材料、继续提问、扩展成员，还是处理人工任务？

当前重点是告警判定、关联范围核查和证据补查。完整攻击过程重建、因果验证、攻击源追踪和溯源分析作为后续可选能力保留。关系图有连线，不足以证明攻击路径或受害范围已经确认。

### 1.2 使用角色

| 角色 | 工作目标 | 产品应支持的决策 |
| --- | --- | --- |
| 告警分析员 | 阅读检测与依据，处理告警 | 是否为真实威胁、误报、正常行为，是否需要继续核查 |
| 案件负责人 | 组织成员、查看结果、提出问题、安排人工确认 | 范围是否足够，下一步查什么，谁负责未解决问题 |
| 响应审阅人 | 核对建议动作的目标、依据和业务影响 | 是否允许执行具体动作，执行是否成功 |
| 交接与复核人员 | 回看输入、证据、人工反馈和判断 | 当时知道什么、为什么得出结论、哪些问题仍未解决 |

这些是业务角色。账号权限、审批资格及多人并发编辑规则需在生产接入时明确。

### 1.3 产品原则

- 告警、事件和 Case 分工清晰；同一事项有明确的主要处理位置。
- 所有案例使用同一套解析、页面、空态和交互规则，差异来自数据与能力条件。
- 完整示例用于说明功能，实际保存结果保持原值、原范围和缺口。
- 每轮调查有可读的收尾结果，明确依据、变化、影响及限制；运行中不提前生成最终结论。
- AI 能获取的信息由 AI 按需处理；业务授权等需要人确认的事实以简单人工任务承接，不强制提供工单或附件。
- 当前案件、历史调查输入、探索候选和已确认判断分别保存，避免相互覆盖。

## 2 核心概念与职责

| 对象 | 产品定义 | 主要回答的问题 | 关系与边界 |
| --- | --- | --- | --- |
| 告警 | 一条检测及其原始数据、解释、关联对象和处理信息 | 为什么产生这条告警，是否需要处理 | 归属事件，可关联 Case；没有 Case 也能查看已保存自动处理结果 |
| 事件 | 多条相关告警的集合 | 是什么、为什么关联、有哪些关系 | 展示集合信息和关联依据；深入研判进入 Case |
| Case／案件 | 持续调查和协作的工作区 | 当前认识、材料范围、调查进展和待办是什么 | 包含多条告警，可关联多个事件，保留多次调查与人工任务 |
| 基础调查 | 围绕案件成员进行必要信息收集和整体分析的调查 | 当前案件范围内发生了什么，还缺什么 | 首次调查及成员新增后的更新均保留独立执行记录 |
| AI 调查 | 用户通过案件助手提出明确问题，由 AI 回答或按需取数分析 | 这个具体问题能否回答，依据是什么 | 明确保存有价值结论后进入调查记录；每条消息不等于一条正式记录 |
| 人工任务 | 人创建、分配和完成的事实核实或处理事项 | 需要人确认什么，谁负责，结果是什么 | 属于 Case；结果可被 AI 和后续基础调查引用 |
| Run／调查执行 | 一次执行的固定输入、过程、状态和产出 | 这一次做了什么、查到什么、为什么结束 | 后续成员变化不能改写当次输入和结果 |
| 案件当前判断 | 对明确案件范围形成的综合认识 | 当前已经确认什么，尚未确认什么 | 有来源、时间和覆盖范围；不能直接取最后一条回答替代 |
| 响应动作 | 对具体目标的处置建议、审批与执行记录 | 允许做什么、实际做过什么、结果如何 | 批准与执行分开，报告建议不代表已执行 |

页面统一使用“涉及资产”表达资产范围；涵盖账号、IP、文件、技术等更广范围时使用“对象”。“判定”“严重程度”“处理状态”“执行状态”“交付完整性”具有不同含义。

## 3 三类调查工作的业务流程

### 3.1 基础调查：建立与更新案件认识

“基础”表示案件调查中必然存在的过程，不表示分析浅或工作简单。告警或事件进入案件调查流程后，应有一次基础调查，收集重要材料、分析成员告警与对象、形成发现和未解决问题。自动研判按业务策略决定转入案件调查，以及用户从告警或事件主动推进，均应遵循相同的范围与首次调查规则。

| 触发或操作 | 产品要求 | 用户可见结果 |
| --- | --- | --- |
| 从告警或事件推进到 Case 调查 | 对明确纳入的成员形成首次基础调查 | 执行提示、当次范围、调查结果及限制 |
| 向 Case 正式加入新的告警 | 以更新后的成员范围发起基础调查更新；可复用有效材料 | 新的一轮记录说明新增输入及与已有认识的差异 |
| 将多个事件加入 Case | 关联事件分别保留，成员告警取并集并去重 | 显示多个关联事件及实际新增告警数 |
| 重复加入已有告警，成员没有增加 | 不因重复提交产生重复更新 | 关联信息保持一致，新增数为零 |
| 仅预览、展开图谱或保存探索 | 不改变案件成员，不触发基础调查更新 | 仅探索工作区变化 |
| 已有调查正在执行时再加入告警 | 保持执行中的输入不变，新增内容进入待更新范围 | 提示新增告警待分析，并保留当前执行入口 |

基础调查更新应记录“为什么更新、增加了哪些输入、引用了哪些人工结果、结论有何变化”。不要求每轮都改变结论，也不要求无差别重取所有资料。

当前预览在成员确认后保存关联并显示“基础调查待更新”，不会实际自动启动后台调查。生产接入需落实上述自动更新流程。仅移出告警、空案件首次启动和已解决案件新增成员的自动策略仍需确定，见第 16 节。

### 3.2 AI 调查：围绕明确问题执行与保存

用户可以从案件故事、某轮结果、告警或图谱对象提出问题。发送后，AI 应处理该问题，而不是只记录问题或要求再建立一份调查草案。

| 问题情况 | AI 应做什么 | 交付要求 |
| --- | --- | --- |
| 已有资料足以回答 | 使用当前案件材料分析并回答 | 结论、引用依据、适用范围及限制 |
| 需要额外且可用的只读查询 | 选择合适工具，在明确范围内查询后分析 | 查询过程、结果、失败或空结果、最终答复 |
| 范围或意图不明确 | 询问必要的澄清信息 | 明确需要用户补充什么，不虚构执行 |
| 需要业务授权或人员背景确认 | 说明已查到什么、还缺哪项人工事实 | 可由用户建立人工任务，完成后用于后续分析 |
| 工具不可用或执行失败 | 说明失败与仍可使用的材料 | 不把查询失败解释为不存在风险 |

一次对话可以产生有价值的结论，也可以只解释已有内容。用户选择“保存到调查记录”，核对标题与结论并确认后，形成一条正式 AI 调查记录；未保存的聊天继续保留在该案对话中，不自动混入正式调查历史。

执行过程与正式结果保存是不同动作：发送即处理，保存用于沉淀经过用户确认的结论。保存不会再执行一次，也不自动把该结论采用为全案判断。

对话正在等待某项人工反馈时，收到反馈应继续原问题的分析；确认事实本身不另建 Run。原执行已经结束后提出新的补查问题，则按新的问题和范围处理，保留先前执行结果。实际反馈续接服务尚未接入。

### 3.3 人工任务：补充人的判断和事实

用户阅读案件后可创建明确事项，例如“确认此次登录是否由本人执行”。任务包含负责人、期限、状态和处理结果；完成时直接填写确认即可。

人工任务不要求用户编排工具，不以工单号码或附件作为完成前提。任务结果在案件故事和材料上下文中可见，AI 可以回答“这项人工确认对当前判断有什么影响”。人工任务完成不等于启动 AI 调查，也不自动解决案件。

### 3.4 三类工作如何互通

| 信息流转 | 产品规则 |
| --- | --- |
| 基础调查 → AI 提问 | 可围绕整轮结论、某项发现或限制提问，并带入对应范围 |
| 人工结果 → AI 提问 | 助手可读取同案人工事项、结果、状态和完成时间；明确它只确认了哪些事实 |
| AI 结果 → 正式调查记录 | 用户明确保存，冻结问题、回答、输入及所引用材料的当时内容 |
| 人工结果 → 基础调查更新 | 作为后续分析可用的材料，保留人工来源，不修改已结束调查 |
| 新成员 → 后续调查 | 当前成员更新，既有调查原始输入保持；新增输入需单独分析 |
| 调查结果 → 案件当前判断 | 需要有明确采用依据与覆盖范围；最新一轮或最后一句回复不能直接覆盖全案判断 |

同一 Case 最多有一个活跃调查执行；排队中、执行中及执行状态待确定的记录不能当作已结束。已经结束但结果仍需人工复核，不因此算作活跃执行。阅读历史、编辑人工任务和基于已有材料提问仍可进行。涉及新的实际执行时需遵守单活跃约束；与基础更新并发时的调度顺序见后续决策。

## 4 通用业务与数据规则

### 4.1 成员关系和调查范围

1. 告警关联、事件关联、案件添加、图谱加入和移动告警采用同一套来源环境与租户校验。
2. 先校验全部选择，再保存；一个事件含不可用成员时说明原因，不留下半个关联或空案件。
3. 添加采取并集去重；移动需明确目标案件，源案件移出、目标案件加入，分别显示范围变化。
4. 添加不会从其他 Case 偷移成员；移动才改变源、目标两边的成员关系。
5. 当前成员变化保留业务活动记录；历史 Run 输入、已保存结论及其引用不随之重写。
6. 同名主机、账号或近似时间不足以跨来源匹配；来源未知不能作为任意匹配条件。
7. 关联事件数与实际新增告警数分开表达。仅关联事件而成员未变化，不应宣称新增告警已调查。

### 4.2 状态与评分含义

| 信息 | 含义 | 展示要求 |
| --- | --- | --- |
| 处理状态 | 告警、事件或案件的业务处理进度 | 与调查执行状态分开；调查结束不自动等于业务已解决 |
| 判定 | 对明确告警或调查范围的判断 | 同时显示依据与适用范围，不扩展到未分析成员 |
| 严重程度 | 来源等级，或按规则汇总的等级 | 事件按成员最高等级呈现；不能用分诊置信度替代 |
| 优先级 | 已有优先级评估结果 | 无来源不合成，不取成员分数平均值；Case 页头缺值不占用评分模块 |
| AiSOC 分诊评分 | 对应分诊判定的置信度 | 与判定一起理解，不代表事件优先级或恶意概率 |
| 关联分数 | 候选线索的排序依据 | 仅用于决定优先查看谁，不作为严重程度、判定或响应许可 |
| 交付完整性 | 本轮结果和材料是否完整 | 部分交付仍可阅读已有结果，同时保留缺项与失败原因 |

告警页部分评分当前仍使用“风险评分”名称，命名与解释统一列入第 16 节。数据含义不因显示名称改变。

### 4.3 缺失与异常

| 情况 | 统一处理 |
| --- | --- |
| 字段缺失、值为空 | 显示未提供、未记录或不占用可选模块，不能补零或编造结果 |
| 明确数值为零 | 保留零，与未记录区分 |
| 查询无匹配 | 表示本次查询范围内无匹配，不能直接推导全案安全 |
| 查询失败、超时、未执行 | 明确相应状态与影响，不当作查询结果 |
| 只保存了摘要 | 可读摘要，同时明确原始材料未保存 |
| 引用失效、对象不存在 | 显示未找到，不借用另一轮或另一案件的材料 |
| 部分交付或缺少路径 | 保留已有结果和不足；完整示例不能填充实际记录 |

### 5.3 导航一致性

- 列表名称进入详情；预览图标打开侧栏，避免以展开箭头暗示展开子告警。
- Case 默认进入案件资料。每个页面保持当前 Case 身份及公共操作。
- 切换单次调查内容保持当前 Run；切换 Run 时保留阅读视图，清除上一轮的查询或工件定位。
- 查询、证据和图谱引用应回到同轮对应材料。不能仅按相同名称跳入其他调查。
- 打开助手或带入范围不会自动发送问题。关闭未确认表单不保存；已确认的成员关联不会因关闭助手被撤销。

## 6 告警页面需求

### 6.1 列表与侧栏

列表用于快速排查，提供名称、严重程度、时间、标签、调查状态、处理状态、类别、数据来源、涉及资产和负责人等信息；通过搜索、筛选和列选择缩小阅读范围。详细材料进入详情页查看。

标签与资产属性应保持统一含义。缺少资产库存关联时，可以显示来源中的主机或账号，但不能把来源对象当作已经确认的资产库存。相关告警至少显示名称、严重程度和时间，支持初步判断后跳转。

### 6.2 详情页

示例：[告警详情](http://127.0.0.1:4174/#/alerts/showcase-alert-01-1/overview)。

| 区域／页签 | 信息与功能 | 操作结果 |
| --- | --- | --- |
| 公共页头 | 名称、严重程度、处理状态、类别、可用评分；管理告警、准备调查 | 管理和进入调查分开，不因打开调查入口改变判定 |
| 所属关系 | 所属事件和关联 Case | 事件进入概览；Case 进入案件资料；缺关系明确显示 |
| 概况 | 发生了什么、解释、关键依据、待核实内容、建议、实体、IOC 与 ATT&CK | 阅读已有依据，不把建议呈现为执行结果 |
| 告警属性 | 来源、来源 ID、租户、负责人、发生时间、告警 ID、资产标签 | 支持回查；缺值保留真实状态 |
| 判定与反馈 | 真实威胁、误报、正常行为、需人工跟进及理由 | 保存人工意见；误报或符合预期的正常／授权行为应关闭告警，其他判定不自动变更状态，实际写回待接入 |
| 时间线 | 已保存的发生、处理和人工意见记录 | 按实际时间回看，最新在上 |
| 原始数据 | 来源记录与原始字段 | 可核对原文，不要求把解释正文强拆成必填字段 |
| 响应 | 响应建议、自动处理过程、查询和交付 | 无 Case 的既有自动处理仍可查看；新的人工提问进入 Case 助手 |

页签：[时间线](http://127.0.0.1:4174/#/alerts/showcase-alert-01-1/timeline)、[原始数据](http://127.0.0.1:4174/#/alerts/showcase-alert-01-1/raw)、[响应](http://127.0.0.1:4174/#/alerts/showcase-alert-01-1/response)。

### 6.3 准备调查与关联

| 条件 | 点击“准备调查” | 确认后的结果 |
| --- | --- | --- |
| 只有一个可用 Case | 打开该案助手，带入告警 | 不新增任务、Run 或正式调查记录；用户发送后才处理问题 |
| 有多个可用 Case | 先明确选择案件 | 打开所选 Case 助手，不默认替用户选第一项 |
| 没有可用 Case | 选择新建或关联已有 Case | 确认后保存成员关系并标记待更新，再打开助手 |

普通“关联到”操作只管理成员关系，不发送 AI 问题。关联已有 Case 不需要新名称；创建 Case 需要名称。关联确认后的基础调查更新遵守第 3 节，当前预览仅保存待更新状态。

## 7 事件页面需求

### 7.1 列表指标与预览

事件用于组织和阅读多告警信息，核心目标是“是什么、为什么关联、有哪些关系”。处理指标“处理中的事件”表示已开始处理、尚未解决的事件。

右侧四项指标紧凑且整体右对齐，名称保持简短，定义与范围通过右上角信息图标悬停或聚焦查看。

| 指标 | 统计口径 |
| --- | --- |
| 活跃事件 | 新建和处理中的事件，不含已解决 |
| 待分配 | 明确标记为未分配的事件；来源未记录负责人不自动算未分配 |
| 24h 有新告警 | 近 24 小时有成员告警发生的事件，按事件去重；缺发生时间不回退为入库时间 |
| 高严重程度 | 严重程度为高的事件 |

四项统计全部已加载事件，不随下方表格搜索或筛选变化。信息图标需说明范围。侧栏展示事件整体说明、成员数量、涉及资产、调查情况与已有优先级；不用单条告警评分列表替代事件整体描述。

### 7.2 五个详情页签

| 顺序与页签 | 主要信息与功能 | 跳转 |
| --- | --- | --- |
| 1 事件概览 | ATT&CK 覆盖置于“事件是什么”之前；事件说明、成员与资产、发生范围；时间线与共同线索结合 | [概览](http://127.0.0.1:4174/#/incidents/showcase-incident-01/summary) |
| 2 关联分析 | 固定当前事件关系图，左告警、中图、右详情；筛选称“数据来源” | [关联分析](http://127.0.0.1:4174/#/incidents/showcase-incident-01/attack) |
| 3 成员告警 | 组成事件的告警、严重程度、时间、状态和涉及资产 | [成员告警](http://127.0.0.1:4174/#/incidents/showcase-incident-01/alerts) |
| 4 涉及对象 | 主机、账号、IP 等对象及来源告警 | [涉及对象](http://127.0.0.1:4174/#/incidents/showcase-incident-01/assets) |
| 5 处理活动 | 人工管理与已保存处理记录 | [处理活动](http://127.0.0.1:4174/#/incidents/showcase-incident-01/activities) |

“为什么关联”应提供可回查的共享对象和实际依据；缺少归并规则时不能编造规则名称。ATT&CK 覆盖是成员告警涉及的阶段与数量，不是防御覆盖率或已确认攻击链。

事件仅在关联分析保留一个关系图，不提供跨事件探索或独立 Attack Chain／Attack Path 操作。默认范围无需常驻“仅此事件”控件。

### 7.3 处理状态与 Case 入口

| 操作或条件 | 产品结果 |
| --- | --- |
| 新建事件，或来源未提供管理状态 | 显示新建；来源缺状态仍保留，不声称后端返回了该值 |
| 分配明确负责人 | 进入处理中；已解决事件只改负责人不自动重开 |
| 人工选择解决并填写说明 | 进入已解决；不能由 Run 结束自动替代 |
| 已有一个关联 Case | 直接进入案件 |
| 已有多个关联 Case | 用户选择目标案件 |
| 没有 Case | 提供新建或关联；新建带入事件名称与全部成员，确认时整体校验并去重 |

事件管理包含负责人、严重程度、状态、标签及解决说明。对单条告警的判定在告警处理；深入分析进入 Case，不在事件页重复建立一套调查工作区。

## 8 Case 列表、基本信息与调查概览

### 8.1 案件列表指标

[Case 列表](http://127.0.0.1:4174/#/cases)帮助用户安排分配、处理和人工跟进。顶部指标统一以案件为计数对象。

| 指标 | 口径 | 用户用途 |
| --- | --- | --- |
| 待分配 | 新建或处理中，负责人为空或明确未分配；未知负责人不视为未分配 | 找出需要明确负责人的案件 |
| 处理中 | 案件处理状态为处理中，不按 Run 是否运行判断 | 查看已经接手、尚未解决的案件 |
| 高严重程度 | 新建或处理中且严重程度为高 | 优先安排高严重程度案件 |
| 待人工跟进 | 新建或处理中，至少有一项未开始或进行中的人工任务 | 找到需要人工反馈的案件 |

指标统计全部已加载案件，不跟随表格筛选变化；同一案件可属于多项指标。待人工跟进按案件去重，不能把任务数或 Run 数写成案件数。已解决及处理状态未知的案件不纳入上述待处理指标。

卡片显示名称、数量和“个案件”；信息图标说明定义。点击卡片以该指标替换当前筛选范围，保留列选择与排序，并显示范围标签；用户可继续叠加筛选。再次点击、移除标签或重置可取消指标条件。案件总数在表格工具栏查看。

### 8.2 公共页头与执行提示

页头提供案件名称、严重程度、处理状态、负责人、可用优先级及关联事件。多个事件可分别进入。严重程度、状态和负责人应有明确视觉分组；未知优先级不显示空评分占位。

公共操作包含添加告警／事件、询问 AI、管理 Case。存在活跃执行时，其他案件页面保持进度提示和当前 Run 入口；调查概览在主内容中显示一次进度，避免重复堆叠。人工任务与调查执行保持独立。

### 8.3 案件资料：默认阅读页

[案件资料示例](http://127.0.0.1:4174/#/cases/outcome-case-01/case-info)。

| 区域 | 展示要求 | 用户下一步 |
| --- | --- | --- |
| 案件说明 | 说明当前事件背景与需要核查的问题 | 理解案件后进入故事或结果 |
| 当前判断 | 结论、依据、适用范围、形成时间、作者或确认人 | 回查支撑该判断的调查与人工结果 |
| 未解决事项 | 尚未确认的事实、材料不足和影响 | 向助手提问或建立人工任务 |
| 范围与概况 | 当前成员、涉及资产、可用材料、调查记录数及发生时间范围 | 查看成员或对象证据 |
| Case 详细信息 | 状态、严重程度、负责人、关联事件等管理信息 | 管理案件或进入关联事件 |
| ATT&CK 阶段覆盖 | 与详细信息同层级的内容卡片；阶段与告警数 | 理解告警涉及的阶段，不推导完整攻击过程 |
| 主要阅读入口 | 查看 AI 调查、查看案件故事 | 标准按钮高度及图标尺寸一致 |

当前判断不能用“最近调查标题”或几条告警评分拼接。没有明确案件级判断时显示“尚未形成案件级判断”，仍可阅读既有调查。

覆盖范围必须可核查：没有进入任何已结束非仅分诊调查的成员提示尚未分析；不在当前判断范围内的成员提示尚未被该判断覆盖。这两种情况不同。某台主机的正常运维确认不能自动解释另一台主机的登录或外联。

### 8.4 调查概览：结果与当前工作

[概览示例](http://127.0.0.1:4174/#/cases/outcome-case-02/overview)。

- 有活跃执行时，显示一条 AI 调查进度，包含可用的执行信息及进入该轮的入口。
- 成员发生变化时，显示基础调查待更新及新增、移出范围；说明已有结果仍适用于原输入。
- 主区域展示已有分析结果，每项先给出结论与本轮价值，再进入详情。
- 侧栏展示人工任务摘要和待确认事项，未开始与进行中计入待办，已完成和已取消不计入。
- 提供案件故事与全部调查历史入口。概览不重复展开全部历史，也不设置与人工任务并列的调查草案区。

### 8.5 成员告警：维护正式案件范围

成员页标题在左，操作组在右；“添加告警／事件”位于操作组最右，与移动操作相邻。窄屏可换行，保持清晰归组。

| 操作 | 用户交互 | 保存结果 |
| --- | --- | --- |
| 添加告警 | 搜索、选择、确认 | 并集去重，记录实际新增范围与基础调查待更新 |
| 添加事件 | 选择一个或多个事件，核对成员 | 保存事件关联及其可用成员，并集去重 |
| 移动所选告警 | 选择成员和可用目标 Case，再确认 | 同时更新两案成员并标记范围变化；两案历史 Run 保持 |
| 管理所选 | 对明确选中的告警修改管理信息 | 影响所选对象，不隐式扩大范围 |
| 查看告警 | 点击名称 | 进入对应告警详情 |

提交不满足来源或租户范围时，说明无法关联的原因，保持现有成员不变。打开、筛选或取消添加窗口不写入。

## 9 案件故事与时间线

### 9.1 定位与内容

[案件故事](http://127.0.0.1:4174/#/cases/outcome-case-01/story)是理解全案时间顺序并提出问题的主要页面。“案件故事”保持中性，不预设所有活动已经构成攻击。

时间线包含当前成员告警、调查记录及已完成的人工任务，按实际时间倒序排列，最新在上。告警按发生时间；已结束执行按结束时间；活跃执行按开始时间；明确保存的 AI 结果按保存时间；人工结果按完成时间。缺时间的条目排在底部，不用页面刷新时间补齐。

| 条目 | 常驻信息 | 可进行的操作 |
| --- | --- | --- |
| 告警 | 发生时间、标题、战术、严重程度、关键资产 | 选择查看详情、打开告警、围绕此告警提问 |
| 调查记录 | 本轮结论、目标、主要发现、变化与影响摘要 | 查看完整结果、询问本轮结果 |
| 活跃调查 | 当前执行状态与目标 | 查看进度；不提前显示最终结论 |
| 人工完成结果 | 事项、确认结果、完成时间及相关范围 | 查看任务内容、询问该结果对案件的影响 |

不同调查条目应体现不同产出，例如“脚本用途已确认，但登录背景仍未核实”和“外联字节数不足以证明文件外传”，而不是重复显示“已完成调查”。失败也应说明未完成什么、已有结论是否仍有效。

### 9.2 阅读与布局

告警卡片紧凑排列：时间与选择入口在左；战术标签及严重程度在右上同排并对齐；标题清晰；涉及资产和提问入口在下方。战术统一使用深紫色强调，严重程度保持自己的等级颜色。ATT&CK 覆盖与故事使用一致的战术样式。

搜索可按告警名称、主机、账号等缩小阅读范围，严重程度筛选仅改变当前展示。选择告警后，右侧展示相关信息、共同对象和包含该告警的调查；打开助手后，右侧成为当前案件对话区。

用户可询问整个案件，或选择一个／多个告警、某轮结果、人工反馈作为提问上下文。选择范围和发送问题是两个动作；有历史对话时仍显示建议问题。

## 10 案件 AI 助手

### 10.1 入口与上下文

案件页头与固定助手入口，以及故事、调查结果、图谱节点等上下文入口，进入同一个 Case 的助手。它们共享该案对话，不产生互不关联的聊天窗口。

| 入口 | 带入范围 | 打开后的行为 |
| --- | --- | --- |
| 询问整个案件 | 当前成员及可用案件材料 | 展示该案历史对话、建议问题和输入框 |
| 围绕告警提问 | 所选告警及相关对象 | 显示范围，允许编辑问题 |
| 询问本轮结果 | 指定调查及其原始输入 | 明确本轮身份，不默认覆盖所有成员 |
| 询问所选对象 | 图谱中选中的可用对象及关联告警 | 带入上下文，不直接展开更多节点或加入成员 |
| 询问人工结果影响 | 指定人工事项、处理结果和相关范围 | 分析其影响，不能扩大人工确认的含义 |

案件上下文包括已有调查摘要、当前告警、人工结果及同案引用。跨 Case 切换应切换对话与范围，不能将一个案件的回答写入另一个案件。

### 10.2 对话布局与建议问题

系统回复在左，用户问题在右，使用聊天式信息层级。案件名与范围简洁显示，引用材料按需展开，输入区有明确发送按钮。无历史时可预填可编辑的初始问题；有历史时保留对话并持续显示建议。

建议由当前案件与选中材料上下文形成，措辞是用户可提出的问题，例如“人工确认改变了哪些判断？”“这些网络记录能证明外传吗？”。点击建议只填入输入框，用户可修改后发送，不直接执行。

当前示例建议和本地回答为预置内容，不代表真实模型已经生成问题或执行分析。实际建议生成与语义理解的服务接入范围见第 15 节。

### 10.3 发送与答复状态

| 状态 | 页面行为 | 约束 |
| --- | --- | --- |
| 待发送 | 输入框可编辑，显示所选范围 | 打开或填入建议不执行 |
| 分析中 | 问题进入对话，显示处理状态 | 防止重复发送；不能先显示“已完成” |
| 已回答 | 显示结论、发现、对案件的影响、限制及过程引用 | 回答范围和引用必须属于本案且可校验 |
| 失败或服务不可用 | 显示明确原因及重试入口 | 不插入假结论，不把未执行问题伪装成分析结果 |
| 等待人工事实 | 说明已经查明与仍待确认的信息 | 用户可在人工任务中记录；不要求每条问题先选“转人工” |

实际工具调用、材料读取与执行状态应由服务返回；不能仅靠前端动画宣称完成。发送涉及新的执行时遵守单活跃约束。已有资料足够时可以直接回答，不要求每次建立调查草案。

### 10.4 结果保存与引用

1. 用户阅读答复后点击“保存到调查记录”。
2. 展示可编辑的记录标题与结论，让用户确认要沉淀什么。
3. 确认后保存所选问题、回答、输入告警及所用调查、人工材料的当时快照。
4. 形成正式 AI 调查记录，进入调查历史和案件故事，并可回查原问题、回答和依据。
5. 重复保存同一答复不产生重复记录；取消保存不新增正式记录。

保存不改变成员、案件处理状态或案件当前判断，也不触发新的活跃执行。纯文本 AI 结果不替换案件图谱底图。人工任务后来被编辑时，已保存结论引用的当时内容保持不变，同时允许跳转查看当前任务。

### 10.5 案件共享记忆的边界

产品要求同案对话、基础调查和人工任务互相可见。AI 必须知道人工结果确认的是哪项事实、来自谁、何时形成，以及是否还有范围外的问题。

保存后的引用需要能复核当时的材料。全局 AI 助手可以提供统一入口，但案件上下文必须明确；跨案件记忆、长期语义记忆及权限隔离不因已有对话界面而视为已实现。

## 11 关系图与关联探索

### 11.1 三种图的职责

| 图 | 基础数据范围 | 允许的用户工作 | 结果影响 |
| --- | --- | --- | --- |
| 事件关联分析 | 当前事件成员及对象关系 | 查看、筛选、聚焦、回查 | 不提供跨事件探索 |
| 案件关系图 | 最近一次有资格提供图谱的已完成调查；无完成调查时使用当前成员关系 | 查看、实体扩展、预览线索、保存探索、加入成员、提问 | 仅正式加入告警才改变案件成员 |
| 历史调查关系图 | 当次保存的输入和关系材料 | 阅读、聚焦、查看来源 | 不在历史图内扩展并改写当次调查 |

纯文本 AI 结论不作为案件底图来源。部分交付的调查可提供已有关系，但需保留不完整状态。选定的完成调查缺图时，不悄悄借用另一轮的图补齐。

已有探索保留自己的起始调查，避免新结果到达后画布突然替换；重置探索后再采用当前可用底图。历史记录中的无 Case、跳过、缺路径等事实保留在该轮材料中，不作为当前案件图的常驻状态。

### 11.2 图谱阅读与节点详情

三栏布局保持左侧告警、中间圆形节点画布、右侧对象详情／关联线索。提供可用的严重程度、状态、数据来源筛选，分组、缩放、布局及重置视角等阅读操作。窄屏按分区排列，不遮挡右侧操作。

| 所选内容 | 右侧信息 | 可进行的操作 |
| --- | --- | --- |
| 告警 | 标题、严重程度、时间、案件归属、关联依据 | 查看告警、提问、将符合条件的案外告警加入案件 |
| 实体 | 类型、名称、相关告警与来源依据 | 以此节点扩展、提问 |
| 战术或技术 | 编号、阶段映射及相关告警 | 回查映射；不作为实体扩展起点 |
| 连线 | 端点、关系类型与保存的依据 | 回查材料；不将关联线自动解释成攻击因果 |
| 空白画布 | 选择提示与推荐线索入口 | 按当前画布范围查看推荐候选 |

### 11.3 扩展分析

1. 选择实体并点击扩展，或从当前画布查看推荐线索。
2. 在右侧列出少量优先候选，提供名称、案件归属、时间差、共享对象及排序依据。
3. 规则和时间基准按需查看。关联分数表示排序优先级，不表示恶意概率。
4. 用户先预览候选，再展开到画布。新增探索节点和关系用不同颜色区分。
5. 展开的可用实体可作为后续起点；战术映射节点不承担扩展操作。
6. 可撤销或重置探索。案外告警只有经明确确认加入，才成为成员；缺少完整可用记录时不提供假加入结果。

“关系图”和“关联告警”是同组关系的两个阅读角度：前者看如何连接，后者看哪些告警值得优先查看及其依据，成员归属必须一致。

### 11.4 三个容易混淆的操作

| 操作 | 保存或改变的内容 | 是否产生调查 |
| --- | --- | --- |
| 保存探索进度 | 探索起点、展开与选择状态 | 不生成调查草案或 Run |
| 询问所选对象 | 将所选对象带入助手上下文 | 打开不执行，发送后处理问题 |
| 加入本案 | 正式保存告警成员关系并记录待更新范围 | 产品要求后续基础调查更新；当前预览不自动执行 |

## 12 调查历史与每轮结果

### 12.1 历史列表

[调查历史示例](http://127.0.0.1:4174/#/cases/outcome-case-01/investigations)。历史应区分基础调查首次分析、成员变化后的更新和明确保存的 AI 结果。用户能通过标题、触发原因、时间、范围、执行状态及交付完整性判断该看哪一轮。

| 统计信息 | 口径 |
| --- | --- |
| 本轮耗时 | 有效开始到结束的总时长，包含等待；运行中没有最终耗时 |
| 工具记录 | 实际保存的工具条目数量，不用数量猜测工具成功率 |
| 模型调用 | 已保存的调用总量；缺记录显示未记录 |
| Tokens | 已保存的用量，明确零保留，缺值不补零 |

单阶段时长不能代替整轮时长。保存一条 AI 答复不能凭空产生模型调用数或 Tokens。

### 12.2 每轮结果的统一表达

所有调查结果共用下列阅读结构，概览、故事和详情使用同一含义。

| 内容 | 要说明什么 | 示例 |
| --- | --- | --- |
| 调查目标 | 为什么执行这一轮 | 新增跳板机登录告警后，核对是否与脚本活动有关 |
| 原始输入与范围 | 本轮具体分析了哪些成员、对象与时间 | 三条成员告警及所选网络记录 |
| 本轮结论 | 已确认、未确认或无法判断什么 | 脚本用途已确认，登录背景仍待核实 |
| 主要发现与依据 | 结论由哪些材料支持 | 进程记录、网络查询、人工确认及引用 |
| 相比已有结果的变化 | 新增输入、证据或判断的变化 | 增加登录告警和脚本用途确认 |
| 对 Case 的影响 | 哪些认识可调整，哪些仍不能推广 | 正常脚本不能解释跨主机访问，需继续核查 |
| 限制与未完成事项 | 查询失败、材料缺失、范围不足 | 无文件列表，不能证明外传内容 |

每轮结束都应有收尾说明，即使结论是证据不足、没有新增发现或补查失败。当前读取实际材料缺少结论时显示“本轮未保存结论”，不补造。运行中只展示过程与状态，不提前填入最终结论。

### 12.3 五个主视图

| 视图 | 用户问题 | 内容及跳转 | 示例 |
| --- | --- | --- | --- |
| 调查发现 | 这一轮得到什么结果 | 目标、结论、范围、依据、变化、影响、限制；询问结果或建立人工任务 | [调查发现](http://127.0.0.1:4174/#/cases/outcome-case-01/investigations?run=outcome-run-02&view=overview) |

| 查询与证据 | 查了什么、返回什么 | 参数、结果、错误、摘要和原件；准确定位同轮工具材料 | [查询与证据](http://127.0.0.1:4174/#/cases/17420/investigations?run=INV-20261024-001&view=tools) |
| 调查关系图 | 当次有哪些关联 | 静态关系、节点依据、已保存来源材料；继续探索进入案件图 | [调查关系图](http://127.0.0.1:4174/#/cases/17420/investigations?run=INV-20261024-001&view=graphs) |

执行明细为 AI 分析中的次级入口，用于复核步骤、调用和原始字段，不占额外主导航。没有原始查询或报告时使用对应空态；当前成员变化不影响本轮原始范围。

### 12.4 已保存图谱材料的含义

| 材料 | 关注点 | 阅读边界 |
| --- | --- | --- |
| Attack Chain | 候选告警关联依据、时序和排序 | 候选顺序不等于已证实攻击因果 |
| Attack Path | 保存的案件路径或对象关系结构 | 关系存在不代表完整入侵路径已验证 |
| Alert Graph | 告警邻居、对象连接和图可达范围 | 可达范围不等于确认受害范围 |

这三类材料在对应历史调查中读取；缺失、失败或当时跳过均按原记录显示。案件图负责可操作的当前探索，不重复铺陈历史来源材料。

### 12.5 响应建议与审批

每条建议在同一卡片中展示目标、理由、审批要求、审批意见和实际执行记录。报告正文保留原文。目标完整且要求审批时，用户可以对该具体动作批准或拒绝并填写理由。

批准只意味着允许执行，状态为待执行；没有实际执行回执不能显示为已隔离、已封禁或已解决。“无需审批”与“未记录审批要求”必须区分。执行记录只有明确对应动作时才归入该卡，无法对应的记录保留为独立材料。

当前页面不执行真实响应；生产审批权限、执行反馈与重试规则见第 16 节。

## 13 对象证据与人工协作

### 13.1 对象与证据

默认从对象出发：左侧搜索、按类型筛选并显示相关告警数；右侧展示所选主机、账号或资源的资料、来源告警、证据与调查材料。用户无需先理解工件分类，就能回答“这台主机有哪些依据”。

切换到按调查阅读时，以 Run 组织查询、报告和工件，选择材料进入对应调查的查询与证据。没有成员对象也应允许阅读历史材料；对象无法归类的材料不能被丢弃。仅保存摘要、原件不可用时明确说明。

### 13.2 人工任务列表与表单

[人工任务示例](http://127.0.0.1:4174/#/cases/outcome-case-01/tasks)。卡片展示事项、工作说明、负责人、期限、状态和结果，右上角提供唯一编辑入口。人工任务页不放“交给 AI”、重复的“编辑／记录结果”或不明确的来源分析按钮。

| 字段 | 产品要求 |
| --- | --- |
| 任务事项 | 必填，明确要核实或处理的事项 |
| 工作说明 | 补充背景与预期，不要求填写工具方案 |
| 负责人 | 选择负责确认的人；未分配明确显示 |
| 截止时间 | 可选，用于跟进安排 |
| 状态 | 未开始、进行中、已完成、已取消 |
| 确认／处理结果 | 完成时必填；记录事实、适用范围与未确认部分 |
| 来源调查 | 可选，说明由哪次分析引出该任务 |
| 补充参考资料 | 可选的具体证据或查询材料，供负责人阅读；不重复勾选整轮来源调查，也不是要求上传证明 |

所有状态的任务都可以编辑，包括已完成和已取消。编辑带入原内容，明确保存更新同一任务；打开或取消不产生记录。完成任务记录完成时间，进入故事并可被后续 AI 使用。

任务结果改变不自动修改历史调查。已保存 AI 结论保留当时引用快照；新的提问可使用任务当前内容，并区分它与先前引用。

### 13.3 活动、评论和附件

处理活动回答“谁在何时做了什么”，保存成员关联、管理与人工操作等实际记录。案件故事回答“事情和认识如何发展”，两者不互相替代。

评论用于交接和补充说明，已有附件可查看或下载。上传、访问权限与服务端保存属于生产接入范围，不能以现有附件列表推断上传服务可用。

## 14 产品验收要求

以下标准同时覆盖页面呈现与目标业务流程。涉及实际调度、模型、响应或服务端写入的场景，需要完成对应接入后验收，不能仅凭本地原型通过。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC01 | 打开完整、稀疏、实际保存及新建案例 | 使用同一导航与功能规则；数据缺口使用统一空态 |
| AC02 | 从单 Case 告警打开助手后关闭 | 带入正确告警，不新增任务、执行或正式记录 |
| AC03 | 从关联多个 Case 的告警进入调查 | 先选择案件，范围不混用 |
| AC04 | 无 Case 告警或事件新建／关联 | 确认后才保存；取消或验证失败不残留空案件 |
| AC05 | 添加多个事件及重复成员 | 事件分别保留，成员去重，仅实际新增触发待更新 |
| AC06 | 非法来源、租户或不可用成员 | 整次保存被拒绝，原关系保持 |
| AC07 | 移动告警到另一 Case | 两案成员与待更新范围一致，两案历史输入不变 |
| AC08 | 分配并解决事件 | 新建→分配后处理中→人工解决；Run 结束不替代解决 |
| AC09 | 阅读事件概览与图 | 能回答是什么、为什么关联、有哪些关系；不混入跨案调查 |
| AC10 | 比较当前成员、当前判断与历史 Run | 各自范围明确，新增成员不自动进入已有判断 |
| AC11 | 向有活跃执行的 Case 添加成员 | 保持原执行输入，显示待更新；生产不产生第二个并行活跃执行 |
| AC12 | 查看完成、部分、失败与运行中的调查 | 有真实收尾或状态说明；缺结论不补造，运行中无最终报告 |
| AC13 | 阅读故事中的多轮结果 | 最新在上，条目体现具体结论、变化与影响；缺时底部 |
| AC14 | 有历史对话后重新打开助手 | 历史和建议均可见，建议只填输入不发送 |
| AC15 | 发送问题并遇到成功、失败或不可用 | 状态明确；校验范围与引用后才显示有效答复，失败可重试 |
| AC16 | 回答期间切换 Case | 不将异步回答写入另一案，不串用上下文 |
| AC17 | 保存 AI 答复并重复确认 | 形成一条正式记录，问题、回答、输入、引用快照可回查，无重复记录 |
| AC18 | 保存后修改原人工任务 | 已保存依据保持当时内容，当前任务仍可编辑和阅读 |
| AC19 | 保存 AI 结果 | 不自动改变成员、全案判断、处理状态，不新建活跃执行或替换图谱 |
| AC20 | 图谱实体扩展、预览、保存探索 | 候选有依据及排序，新增节点可区分；探索不改变成员 |
| AC21 | 图谱正式加入案外告警 | 明确确认后才加入并显示基础调查待更新 |
| AC22 | 选择战术或历史调查图 | 战术仅供阅读，历史图不改写；继续探索进入案件图 |
| AC23 | 查看工具引用与缺失材料 | 定位同轮原件；不存在时明确提示，不借用其他调查 |
| AC24 | 新建、取消、完成和编辑历史人工任务 | 完成须填结果；取消表单不写入；编辑同一任务且不自动执行 AI |
| AC25 | 审批响应建议 | 许可与执行结果分开；批准不出现虚假的已执行状态 |
| AC26 | 核对案件四项指标 | 都按案件计数，待办去重，口径与点击筛选一致 |
| AC27 | 在窄屏操作主要页面 | 按钮、节点详情、助手、保存与取消入口可达且不重叠 |
| AC28 | 查看用量与缺失评分 | 未记录与明确零不同；无来源分数不合成 |
