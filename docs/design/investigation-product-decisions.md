## D07 已确认 未解决问题随调查结论展示

2026-11-12，负责人确认：“未解决问题就作为调查结论的一部分展示，不要单独做一套管理流程。需要人工确认的再由用户创建任务。”

| 位置或操作 | 已确认规则 |
| --- | --- |
| 调查结论、案件资料、概览和故事中的结论摘要 | 随对应调查结论或当前采用判断展示尚未查清的事实、证据不足及限制，保留所属调查和范围；不另外汇总成问题管理队列 |
| 未解决问题自身 | 不设置独立负责人、处理状态、关闭操作或跨轮去重／合并流程；各轮结论及来源照常保留 |
| 需要人工确认时 | 由用户明确创建人工任务并说明核实事项；负责人、期限、来源和参考沿现有表单规则填写，完成时声明结果及适用范围；不自动把未解决问题生成任务 |
| 人工任务完成后 | 沿现有任务规则保存人工结果，供后续调查引用；不增加“关闭未解决问题”的动作，也不改写历史调查结论 |
| 页面与数据交接 | 未解决问题属于结论内容，待办数只统计实际人工任务；沿用已有结论、问题和限制材料，不要求新增问题管理表或字段 |

这项决定明确了展示与任务边界，不表示页面已接通；演示原型的相关展示和服务模式缺口仍按功能清单记录。

## 11-14后续规则统一

- Case默认100条，溢出才续建并保存最初/前案/当前接收关系；创建、关联、替换新增及移入共用实际分配，回执按Case逐项返回。事件保留全部关联但只有一个active_case_id接收后续新告警；告警可属多个独立Case，无活跃Case标记。
- 关联Case列表先同串续建，再共享事件，排除自身/全分页去重并保留真实两侧来源，不改变映射。
- 定向Run/Result用targeted，综合用baseline且task.intent=synthesis；定向不可直接采用为全案判断，也不推进或停止全案自动更新。
- 事件诊断默认最近归并100条；input_selection、实际analysis_coverage及delivery分别表达。Case仍从事件完整成员分配，不等I全量诊断。实际输入超限保留已有分析、failed/capacity_exceeded收尾，不反复自动重试。
- 默认日志补查前后各1小时、单次50条，配置化；缺时/失败保留缺口。不设额外最大跨度、不裁剪、不自动拆窗，沿既有查询超时。
- 不做旧对象迁入/识别/回填/激活，不增auto_enabled，本轮不清库。窗口内已受理自动首试跨期仍执行一次但不重试；跨期重试停止，不放行新自动扩案/续建。关闭/无变化/串行仍核对，正常完成才刷新窗口。
