# 调查页面产品规则确认记录

更新于 2026-11-12。负责人已确认 **D01–D07 全部七类规则**：D01–D06 按本轮讨论中逐项给出的建议执行；D07 按负责人明确要求随调查结论展示，不建设独立问题管理流程。完整功能和实现状态见[逐页功能清单](../../deliverables/investigation-validation-20261106/frontend-feature-list.md)。规则确认与实际交付分开；D01后端实现按下表更新，页面接线仍独立验收。

## D07 已确认 未解决问题随调查结论展示

2026-11-12，负责人确认：“未解决问题就作为调查结论的一部分展示，不要单独做一套管理流程。需要人工确认的再由用户创建任务。”

| 位置或操作 | 已确认规则 |
| --- | --- |
| 调查结论、案件资料、概览和故事中的结论摘要 | 随对应调查结论或当前采用判断展示尚未查清的事实、证据不足及限制，保留所属调查和范围；不另外汇总成问题管理队列 |
| 未解决问题自身 | 不设置独立负责人、处理状态、关闭操作或跨轮去重／合并流程；各轮结论及来源照常保留 |
| 需要人工确认时 | 由用户明确创建人工任务并说明核实事项；负责人、期限、来源和参考沿现有表单规则填写，完成时声明结果及适用范围；不自动把未解决问题生成任务 |
| 人工任务完成后 | 沿现有任务规则保存人工结果，供后续调查引用；不增加“关闭未解决问题”的动作，也不改写历史调查结论 |
| 页面与数据交接 | 未解决问题属于结论内容，待办数只统计实际人工任务；沿用已有结论、问题和限制材料，不要求新增问题管理表或字段 |

这项决定明确了展示与任务边界，不表示页面已接通；演示原型的相关展示和服务模式缺口仍按功能清单记录。

## 已确定的规则继续沿用

以下不用再次确认，后续按现有合同实现或验收。

| 规则 | 应有结果 |
| --- | --- |
| 添加与移动不同 | 添加并集去重，不从别案移走；移动核两案并同步变更；来源／租户校验整体成功或整体拒绝 |
| 打开、保存、准备、启动不同 | 打开助手不发送；保存答案不再执行；准备只维护待启动；明确启动才冻结输入并执行 |
| 当前手动基础调查 | 同案一个活跃 Run，unknown 也占活跃；可以另有待启动；结束不自动接续；旧输入不重写 |
| 人工任务的完成范围与修订 | 完成须非空结果和明确范围；旧引用不可变；元数据编辑不扩大事实；冲突保留输入；负责人不冒充完成人 |
| 判断和运行状态分开 | Run 完成不等于业务解决或模型质量通过；交付完整性、覆盖、新鲜度和采用分别展示 |
| 图的边界 | 事件图只看当前事件；历史 Run 图只读；探索保存不加成员，成员加入才维护调查范围；关系不等于因果 |
| 资产等公共数据的职责 | 业务后端提供库存和用户基础资料；调查只使用所需引用，不照搬旧 AiSOC 表 |
| 更新与流式的后续顺序 | 已确认先固定流程、后更新；自动成员跟随、合并队列和 H 单独变化走 C6 是已有后置规划，不重新征求方向确认 |

- 完整攻击溯源、全局／跨案助手、相似案件和旧平台其他模块不属于本次功能补全；不以“待确认”方式变相加入范围。
