# 新版三类调查流程与当前实现差距明细

2026-11-03。按用户“分析一下当前的差距”核对。结论：当前已有固定范围的单次 Case 调查、材料冻结、Tool 查询、执行账本与历史读取；新版还要求持续维护 Case 的成员变化、基础调查更新、同案对话、人工确认、正式保存结果和当前判断。主要差距在这些业务对象的字段、关系与读写合同，另有已存字段漏读和真实报告质量问题。不能用“页面已有交互”替代后台数据具备，也不需要重建现有调查执行底座。

## 1. 对照基线和结论边界

- 产品：本设计分支的 [统一产品需求](alert-incident-case-product-requirements.md)，固定提交 `c71afb5c6c4f939bf0243b60e02f224d01c6249a`；产品第 15 节明确原型本地能力与生产未接入项。
- 后台：主工作区 `E:/aisoc/socai2` 的提交 `39f4033663bf478c7a8e8af2adb8333b45a6eb41`。本设计分支没有合入该后台检查点，以下后台结论均读取主工作区，不使用本分支较早的同名源码。
- 入口：[三类流程与页面职责](investigation-flow-alignment-20261103.md)；[本地案件资料页](http://127.0.0.1:4174/#/cases/outcome-case-01/case-info)。此原型示例数据不代表生产数据。
- 本轮为源码、迁移、产品定义和已有验收记录对照；未查询真实数据库、未执行模型／Tool／Run、未部署，未改业务代码或表结构。未刷新远端；“新版”指上述固定版本。
- 沿用用户范围：Fusion 收到数据之前的问题不追查、不补数、不列阻塞；页面功能交后端实现，本轮明确它所依赖的数据条件。报告修复仍暂停，r13 不重试。

“数据合同缺口”表示当前已核路径没有保存或关联所需事实；“流程接入缺口”表示有底层能力但没有完成产品要求的串接；“读取缺口”表示值已存但当前消费路径漏读。产品未定规则在第 6 节单列。

## 4. 存储对象到底要补什么

以下为最小逻辑合同，不是已批准的 DDL 或新表数量。可以选择现有 JSONB／工件承载，但必须有明确归属、写入时机、读取出口和幂等／历史语义。

| 现有对象／表 | 保留的部分 | 需要补齐的事实或关系 |
| --- | --- | --- |
| `aisoc_cases` | 基本资料、业务状态、当前 alert_ids | 当前判断的结构／指针及覆盖；与待更新状态的稳定关系。summary 可继续作摘要，但不独自承担采用事实 |
| `investigation_case_links` | 租户、操作幂等、选中成员／来源事件、增量回执 | 区分历史关联操作与当前成员／事件关系；多事件、移动双方及待更新范围的事务合同。是否另立成员关系表须依据写入／查询需求决定 |
| `investigation_runs/events/artifacts` | 真正执行的范围、来源、步骤、结果、用量及证据 | 基础首次／更新／问题执行类型，触发原因、比较对象、人工结果引用，必要的等待／续接状态；Case 单活跃占用。不要用真实执行表伪造“只保存文本”的执行 |
| `aisoc_copilot_conversations` | tenant、user、messages、消息 UUID／时间 | Case 绑定和问题范围、来源对象／执行关联、案件材料实际入模；现有消息 ID 用作保存来源，不同入口的请求和答复归属一致 |
| 正式 AI 保存记录（逻辑对象） | 复用已有材料保存与引用能力 | record_id、Case／消息来源、原问题／答复、确认后标题／结论、saved_by/at、输入和引用快照、可选 execution_ref、同答复保存幂等。物理上扩现有表还是独立表后定 |
| `aisoc_case_tasks` | 任务身份、Case、标题、负责人、期限、创建人、依赖 | 工作说明、结果、completed_at、取消状态、结果确认主体／时间、适用范围、来源 Run／参考项；当前可编辑，历史引用冻结，不必预先建设通用版本系统 |
| 当前案件判断（逻辑对象） | 复用已有单轮分析和来源引用 | adopted_record_ref、判断内容、依据、覆盖成员／对象、confirmed_by/at；更新保留之前采用的事实。不得由 latest_run 自动替代；具体采用流程待定 |
| 图与探索材料 | 当前图服务、单轮图工件、Case 图数据 | base_run_id／底图类型、可作底图的资格、探索保存身份／展开内容、候选来源；与当前成员分离，保存探索不创建 Run |
| Incident／评论／活动合同 | Fusion incident_id、成员、Case 评论／反馈／通用审计 | 事件业务事实及主体键；普通 Alert 评论；准确操作人、时间、before/after、完整批量目标。继续交后端承接，不在本轮实现页面操作 |

案件故事、三类历史、待办 Case 数、已分析覆盖差集等属于读取组合；原事实齐全后派生即可，不为每个页面建一张同名表。

## 7. 旧字段明细的继承及建议后续

旧 [85 项字段表](../investigation/page-field-support-matrix-20261102.md)的基准是 `48f54abd`，不能整表改标“新版全部已验”。本轮确认的变化：

1. I12 事件独立安全分类已被新产品取消，退出新增字段待办；保留旧审计作为历史事实。
2. I13/I14 优先级及评分不因原型有示例就必须造算法／填值；按有来源展示，缺来源留空，定义仍待定。
3. A36/I23 之外，新增对话、正式 AI 保存记录、当前案件判断三者的关系；不是把聊天全部归为 Run。
4. 事件自身业务事实、普通 Alert 评论／活动合同仍缺；状态映射和反馈关闭等写回不一致仍交后端处理，不能从数据结论中抹去。
5. T02/T05/T06/T08—T11 的已存字段消费缺口保持；前四批已完成修复无需重做。原 I11 的 last_seen 与 max(event_time) 不是同一个口径，仍按页面具体含义选择，不能互代。

建议后续按数据依赖推进：

1. **先定对象与范围合同。** 写清当前成员、本轮输入、判断覆盖三组范围；Case 业务状态、真实执行、正式记录、人工任务各自生命周期。为 G01—G19 标出写入者、读取者及现有表复用点。
2. **补可独立确定的数据。** 人工结果／完成时间／取消／来源范围，Case 对话绑定，正式 AI 保存及引用快照；同步补 G20/G21 已存字段读取。继续保护历史和原预算，不新增向量库或通用记忆框架。
3. **由后端落实流程依赖。** 按确定策略接入首次／更新、单活跃协调、人工续接、当前判断采用和成员移动；当前任务以提供明确数据合同为主，不替代后端实现整套页面功能。
4. **按三条真实闭环验收数据。** 新增成员→新轮固定范围；人工确认→后续分析引用；AI 问答→明确保存→修改原任务后旧引用保持。验证页面读取和数据库／工件事实对应，不能用原型模拟证明。

报告语义另保留 G22；在恢复真实报告验收前不宣称三类流程已经生产可用。本次仅增加分析与入口记录，没有提交、推送或部署。
