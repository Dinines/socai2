# Design

After a final-answer schema/reference failure, record error types/locations, currently available evidence IDs and selected member UUIDs. If one correction and model-call capacity remain, append these diagnostics and concise field rules as a user-level correction request and continue the existing loop. Do not repeat the full schema in the feedback text. This final-conclusion correction uses existing evidence only; omit Tools and reject unexpected tool_calls without dispatch. Ordinary analysis turns retain scoped Tool calls before the model chooses to answer.

The full rejected response stays in its original ledger step but is removed from the next model input. The correction uses diagnostics and original source material, avoiding repeated invented claims and unnecessary input growth within the unchanged budget.

The final-code live follow-up exceeded its remaining preflight allowance by 553. Use a concise correction-specific system instruction instead of repeating the Tool-selection instructions and field descriptions already declared by response_format. Keep source messages and Tool results unchanged. Keep complete validation feedback in the ledger, but send only error locations/types in the correction message: allowed evidence/member IDs are already declared in the schema. Preserve source-trust, history, absence/failure, member-source, correlation/causality and unresolved-question rules. This changes neither token accounting nor limits.

Do not include Pydantic raw input/context in diagnostic feedback. Do not expand budgets, retry HTTP failures, replay a saved Run, silently rewrite member IDs, or turn invalid evidence into accepted conclusions. A second invalid conclusion retains the current terminal failure. Valid responses incur no extra model call.

Use a 60-second HTTP response timeout (10-second connect) for the existing 3000-output-token model call. The outer 120-second analysis deadline still cancels work, so this does not extend total Run duration.

The real follow-up hit the input allowance after an invalid reference. For model input only, omit the previous report's generated timeline/member coverage tables and explicitly list omitted fields. Preserve the full H1 evidence and original report in PG. This avoids unnecessary repeated data while retaining narrative, findings, member judgments, relationships, gaps and open questions; it does not raise the token budget.

For final-conclusion correction, or an initial context with no offered Tools, derive `response_format.json_schema` from AnalysisConclusion. Require all declared fields (defaulted arrays may be empty), disallow additional properties, and enumerate current evidence/member IDs including earlier Tool results. Never combine this response_format with native Tool definitions: the configured model's fictional-data comparison returned no Tool call with schema and the expected call without it. Save the exact response_format (null during normal Tool-capable turns) in the preparation step and count its UTF-8 bytes in preflight. Do not silently drop the contract on HTTP rejection. Local validation remains authoritative even if a gateway ignores schema constraints.
