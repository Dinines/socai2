## 1. 执行约定

每组的正常、边界或失败变体分开记录，例如`TC-C08/no_changes`。不得用其中一个变体通过代表整组通过。各行已给出前置、操作及程序可判定的预期；执行时把逻辑ID解析成服务真实身份，并附该版本的入口/请求Schema、配置和证据。尚未交付的入口标依赖缺失，不编造可调用URL。

统一用例记录：`case_id / variant / requirement_refs / scenario_id / layer / profile_ref / preconditions / input_refs / operation / expected / actual / assertions / status / blocked_by / evidence_refs / issue_ids / model_quality`。状态使用`not_run / blocked / passed / failed / deferred`；新变体初始为`not_run`，阶段8–10及暂停功能为`deferred`。当前运行基线见总计划7.1；待实施的新能力不能借旧版本通过来核销。

统一证据E：保存实际输入及hash、主体和task/attempt/Run/Result映射、操作键与请求/回执、执行前后直接相关持久化快照、同一对象HTTP读回、逐条断言及失败定位。只读操作另比对涉及记录的前后摘要；不得借全库对账扩大检查。模型路径追加输入视图、提示/Schema、配置、请求/原答、校验/补答、装配和用量；未知用量不写0。无Run的操作明确记录`run_id=null`及相关查询结果。

“判失败”通则：任何指定业务断言不成立、身份错配、历史被覆盖、未执行却宣称完成、查询失败充当查空或写入未知盲重投，都判程序/数据/环境失败。正文判断不好单独保留`model_quality=NOT_PASSED`；格式或关联无效导致正常链未完成时，**正常用例仍失败或阻断**，可另外判对应失败处理变体通过。模型输入的筛选、原文和事实传递属于程序功能验收，不因正文质量后置而免验。

层次遵循L0准备→L1规则/组件→L2单模块真实依赖→L3真实TCP合同→L4相邻集成→L5代表性整链。表中列多个层次表示同一业务断言在相应层验证：开发离线/受控时钟/明确替身证据可复用；21正常业务链中实际进入的模型环节必须真实请求。HTTP适配直接检查应使用核心真实返回类型，不能仅用字典替身证明结构化RunView/ResultView可序列化。
