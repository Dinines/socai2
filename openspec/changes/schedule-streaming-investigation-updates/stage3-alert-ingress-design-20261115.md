# 第3步：新告警自动分诊接入

2026-11-15，承接已本地验收的任务生命周期与统一调度。本轮只推进原任务2.2/2.3的A分支和2.7对应必要接线；事件/Case真实执行器、周期更新和知识队列留后续步骤。原任务仍2/11，不用新增复选任务树代替整体完成条件。

## 目标与当前缺口

新告警经现有Fusion保存/投影进入socai2后，自动得到一份首轮alert_triage任务；生产者只保存，不等待模型。统一调度取得任务后使用现有A流程查询、分析并保存分诊/解释、模块IO和模型原答；原task_id、attempt、Run及结果能通过已有查询关联。相同入站重放不能新增首轮分诊，新的A3只分析自己。

现状：`Socai2AlertSink._write`已在短事务保存原告警、材料、对象和事件关系，但不登记task；生产projection提交偏移在保存之后。`AlertBasicExecutor`目前自行begin并执行，尚无“创建Run时同事务绑定已领取attempt”的入口，所有异常统一记unknown会丢失已确定未发出的临时连接失败分类。projection的topic/group/时间限额和状态路径仍有硬编码，需随受影响路径配置化。

告警公共字段/含义和原入站消息合同保持，不新增同告警原材料版本接口或重新分诊。现有材料重放/版本保存行为保持，首轮登记只对应真正新建的告警，不能因为重放或后来原材料变化又生成新首轮。没有扫描历史对象/回填任务或数据库清理。

## 实施顺序与必要接线

1. **保存与受理原子完成。** 在原生Fusion sink新告警分支，告警/材料/事件成员保存后、同PG事务内插入initial任务及subject_state。首轮operation_key由告警UUID稳定派生，任务策略读取显式生命周期配置；不调用Redis/模型。不同应用包之间使用一个仅负责A首轮登记的asyncpg适配，request_hash与核心受理方法的语义一致并直接验证。重放直接保留原记录。任务登记失败使这一入站事务失败，projection不提交该消息偏移，不悄悄跳过。
2. **现有分诊执行器接调度。** 注册alert_triage的load/execute适配；load读取当前A业务输入，execute将选定材料送到现有StageResultService.begin。同事务创建真实Run/输入/策略并绑定领取的attempt，之后才允许工具/模型调用。每次自动重试沿task派生不同执行键，保留每次Run。复用现有字段选择、提示/Schema、有限引用纠正和保存规则，不重做模型输入设计。
3. **正确收尾。** 分诊成功沿现有A结果/解释保存和指针规则；已知尚未发出的ConnectTimeout/PoolTimeout等临时故障记failed并进入既定有限重试，读响应超时等仍为unknown且不自动重试。程序/格式/引用质量失败不进入通用重试。原始模型/工具回执照常保留，任务与Run状态必须相符；已提交成功不因后续保存回执异常被重派。知识同步沿已有配置，本步验证显式关闭外部知识写入，不提前建设第10步知识任务。
4. **运行配置。** 调度工厂使用调度器同一任务服务/session配置生成实际A适配器，每次执行独立创建模型网关；只注册A。新装/升级发布片段同步sink、核心、projection及配置。production_projection/ingress读取显式profile，相关topic/group、路径、连接/SQL/轮询/健康时限全部配置；held日志含可定位topic/group/partition/offset/error，修正原因后从已保存offset接续，不跳位或加入恢复平台。生产旧Agents消费者继续关闭，正式环境本步不部署。
5. **对外边界。** HTTP侧负责目标版本删除E36手动告警同步启动路由，保留内部A执行能力及已有查询。先给出真实handler和保存来源证据，再由HTTP侧执行最小联验；事件/Case POST继续等待其各自步骤，不提前激活。核心不依赖对外HTTP包。

## 本步直接验证与完成证据

- 使用新批UUID/隔离租户，调用现有正常sink/投影保存入口，以真实PG核告警、材料、事件关系、首轮task同事务可读；同告警重放只有一份initial任务，A1/A2后再来A3不重分析旧成员，没有I/Case任务。用一次指定登记失败核本次入站回滚，消息不提交；不建设故障矩阵。
- 真实隔离Redis/PG，通过实际A适配器配可控网关验证：Run/input/policy/attempt绑定先于外部调用、同task有限重试的新Run/旧失败、unknown收尾释放、公共结果关联和入站重放不再调用。复用第2步N/队列证据，不重跑全部调度矩阵；现有A持久化与边界用例只选择受影响分支。
- 用当前显式模型配置对一条新合成告警走正常保存→自动领取→真实A→保存/读回，使用既有预算和有界纠正规则，不追加质量采样。保留实际输入、请求/Schema、工具回执、模型原答、结果/失败及配置；已知模型正文问题按原后置规则记录，不追认质量通过。
- 与HTTP侧对同task/Run/result做必要告警详情、分诊、任务和Run目录读回，核E36从目标OpenAPI移除；告警公共DTO保持。真实入站源数据库/PG、Redis、Kafka消息替身或真实代理、模型及厂商来源分别标明，不以函数替身证明生产Kafka已自动消费。
- 模型批次保存快照后沿既有工具更新本机4177并保留已有批次；strict、受影响配置/构建、Ruff、文档交接作为程序闭环的补充，不能代替业务与模型质量判断。证据归本步新目录，失败原件保留。

完成后更新tasks/PROGRESS及交接，指出本步已验与未部署边界，再进入第4步事件自动诊断。本步不提交、推送或零散发布，不把A分支完成勾成整个2.2/2.3/2.7完成。
