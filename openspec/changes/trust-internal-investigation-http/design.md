# 内部可信 HTTP 对接

## 阶段目标和效果
业务后端直接调用独立18024的71操作，无需登录、Token、API Key、scope或角色。未完成AI对话仍501；请求业务参数和返回字段不变。调查核心继续接收明确tenant_id和Actor，配置指定的操作人用于历史关联，不宣称是真实登录者。

不改内部调查、主API其它路由、Kafka或工具认证，不新增角色/权限体系，不改数据库和业务关联校验，不启动模型/消费者，不混入11-14并行调查修改。租户和操作人不是调用方认证信息；由明确配置文件提供，缺配置启动报错，不回落到演示租户。

## 依赖及步骤
1. 本轮只完成“外部默认可信接入”闭环：在独立应用装配配置上下文，替换其权限依赖，移除登录路由和OpenAPI认证声明；保留旧主API对同一路由的认证依赖。旧路由内一次直接cases读取检查通过相同可信上下文处理，避免漏网。改动仅HTTP适配器/运行装配，配置JSON包含tenant_id/actor_id/actor_name；租户过滤和保存关系保持。文档及联调脚本同步到候选合同，无Token示例；正式运行版本注明尚未切换。
2. 第1步通过后，下一步统一部署与交接收口：基于当前已发布独立API冻结运行目录，仅叠加本项文件，分别保留本机/21数据库和架构；独立结束审计后统一发布服务与Swagger，再只读核实际版本、旧数据和配置，补回执及归档。发布按本轮授权另行推进，不把历史发布授权自动延续。
