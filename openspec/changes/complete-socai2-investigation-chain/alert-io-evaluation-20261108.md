# 告警模型边界三组实测（2026-11-08）

本轮验证了性能收益，但模型正文质量仍未通过。仅整理输入使平均输入 tokens 减少 58.7%、模型 HTTP 耗时减少 20.2%；再采用五字段合同后，相对现版分别减少 62.8% 和 39.7%。没有观察到按合成标签计算的良恶方向反转，但仍有查询状态、历史统计和证据含义错误，不能宣布判断更准确或上线替换。

目标固定为：判断**这一条告警**是恶意、真实但正常、描述不成立的误报，还是证据不足待复核，并提供依据。程序负责身份、版本、查询事实、引用定位和结果关联；模型不重写完整存储对象。当前实现是结构/业务块呈现原型，尚非覆盖所有厂商字段的自然语言模板。

## 性能和格式结果

以下每组均为 12 次请求，三个旧样例各重复两次；均值具有本批样本权重，不代表实际告警分布。HTTP 耗时不包含 SSH 传输和完整业务落库；未测首 token 时间或可靠 P95，未配置价格，不报金额节约。

| 指标 | current | input_only | input_output |
| --- | ---: | ---: | ---: |
| 平均输入 tokens | 4,299.1 | 1,773.9 | 1,599.9 |
| 平均输出 tokens | 536.3 | 429.9 | 322.8 |
| 平均总 tokens | 4,835.4 | 2,203.8 | 1,922.8 |
| 平均 HTTP 秒数 | 10.77 | 8.59 | 6.49 |
| HTTP 中位数秒数 | 11.24 | 8.77 | 6.99 |
| 发出 Schema 校验通过 | 12/12 | 12/12 | 12/12 |
| 核心输出通过现有业务解析 | 9/12 | 9/12 | 12/12 |
| 核实建议总条数 | 20 | 22 | 15 |

input_only 相对 current：输入减少 58.7%、输出减少 19.8%、总 tokens 减少 54.4%、平均 HTTP 时间减少 20.2%。input_output 相对 current：输入减少 62.8%、输出减少 39.8%、总 tokens 减少 60.2%、平均 HTTP 时间减少 39.7%。性能收益部分来自少写解释及建议，不能全部视为无损优化。

现版与仅精简输入组都在 S1/S5/S6 出现 `alert_decision_basis_not_direct`：主要依据混入来源标签角色。它们有直接证据，也有名义标签一致的原始判断，但不符合现有“basis 全部直接来源”要求，核心被拒收；合法片段另存。五字段组在生成时已按确定性判定限制引用枚举，随后仍走原解析器，未放松接收规则。12/12 仅表示格式及关联合同有效，S6 的错误理由同样通过了校验。

三例旧输入正文分别从 8,822/14,821/20,674 B 变为 3,484/4,945/6,799 B；这不是前期删掉历史理由的 90% 压缩初稿。当前候选保留唯一历史理由、建议和描述，合并同一记录的匹配关系；未知原始业务块保持原值。输入整理单次约 0.12–0.51 ms，仅作本机参考。12 项离线适配检查通过，覆盖历史原文、0/false、未知业务字段、非空资产/情报及人工正文、冲突、坏引用等；这些不是实际工具非空结果的端到端验收。

## 判断变化和正文问题

表中为模型原始判定；“拒收”另由上一节说明，不能把它当待复核。两个重复轮次判定一致；A2 五字段组只有建议措辞变化。A2/A3 在五字段组的待复核置信度由 0.65 提高到 0.85，这是模型自评变化，不是准确率提高。

| 样例 | current | input_only | input_output | 主要判断 |
| --- | --- | --- | --- | --- |
| A1 登录 | 待复核 | 待复核 | 待复核 | 五字段组新增按命名推测监控用途，理由中未标明缩写地截短账号/主机名 |
| A2 PowerShell | 待复核 | 待复核 | 待复核 | 仅精简输入仍把 TI 未查写查空；五字段组历史/本次 TI 措辞仍含混，并按账号日期猜临时会话 |
| A3 网络连接 | 待复核 | 待复核 | 待复核 | 仅精简组的本次 TI 建议引用历史分析，引用合法不代表来源支持准确 |
| S1 已批准的云操作 | 良性 | 良性 | 良性 | 原始判断相同，前两组主要依据角色不合合同而拒收 |
| S2 MFA 连续请求 | 待复核 | 待复核 | 待复核 | 合成作者标恶意；待复核可接受，但不能算识别恶意成功 |
| S3 管理代理清点软件 | 待复核 | 待复核 | 良性 | 转为非恶意方向，作者标签却是误报；须先统一良性/误报语义 |
| S4 大量外传上传 | 待复核 | 待复核 | 待复核 | 作者标恶意；精简组减少了把离职身份当授权背景的推断，仍未确定识别 |
| S5 凭证窃取邮件 | 恶意 | 恶意 | 恶意 | 前两组依据角色拒收；五字段组无核实建议，需单独评估建议功能 |
| S6 客户表读取 | 良性 | 良性 | 良性 | 三组都扩大了历史无失败范围；五字段格式通过不等于该理由正确 |

关键错误及归因：

1. **A2 查询状态并未解决。** current 把 `not_queried` 写成未命中，且把实际匹配历史说成查空；input_only 已正确说历史有匹配，但 TI 仍写查空。input_output 将“上游分析”与“威胁情报查空”放在同段，可能引用历史登录查询，不能直接断言是在描述本次 TI；表达仍无法清晰区分。三组输入都有真实状态，未找到该问题由候选漏传状态造成的证据。
2. **仍在补写材料没有证明的内容。** A1 五字段组按名称猜账号用途并截短实体名称，A2 猜临时会话。它们是推测，尚未导致定性反转，但不是减少上下文后自动消失的噪声。S3 五字段组以零网络连接扩展为“未尝试外传”，超出该字段能证明的范围。
3. **S6 是明确的范围扩大。** 原文为 `180 prior runs` 与 `no failed statements in the preceding hour`，没有说明 180 次全部成功。input_only 和 input_output 都明确写“180 次无失败”；current 也把“运行180次且无错误”连写并把计划时间当作实际时间。输入未改写这两项原值，不能通过程序合并字段来给错误结论背书。
4. **有改进，也有功能权衡。** 仅整理输入后，A2 不再说历史查空；S4 明确离职状态不等于授权。五字段组少写重复解释和 basis，减少角色错配，但 S5 不再提供核实建议；建议可空符合合同，是否足够支持业务仍要单列验收。不能将少写内容全部认定为质量提升。

名义六个合成标签中，三组良恶方向反转均为 0；待复核分别为 3/6、3/6、2/6。原始精确标签一致均为 3/6，五字段组另有 S3 的“良性/误报”差异。前两组的三个一致原答全部因为 basis 角色被拒收，不能据原答宣称取得三个可采用的正确结论。该小样本不构成误判率/准确率结论。

## 测试材料自身的限制

- **S3 标签含义不一致。** 语料作者将正常管理代理的编码 PowerShell 标作 false_positive；本阶段合同却将 false_positive 定义为“告警描述不成立”，而标题是编码 PowerShell 执行。不能事后把标签改成 benign 再宣布全标签命中；下轮先审定标签口径。
- **S6 新时间与原计划未对齐。** 生成器将活动时间设为 03:06 UTC，原文仍是 `nightly 02:10` 且没有计划时区。当前材料不足以证明本次符合计划；这是夹具制作的问题，三组共同受到影响。保留本批原件，下轮先固定一致时间/时区或明确该项未知，不能用这个样例证明高置信度授权判断可靠。
- 六个新实例把已有结构化证据作为原始文本块输入，不代表已经覆盖完整厂商嵌套字段、实际资产/TI 非空查询或故障分支。开放字段语义字典、上游投影前已经遗漏的信息及全部来源合同仍未验证。
- 五字段组同时改变任务说明和 Schema，不能将 S3 定性变化或解析改善全部归因于“只少三个字段”。本轮没有独立结束审计，也没有生产保存/读取、新鲜度、API/4177 接入验证。

## 后续决定

保留“先确定目标，再选上下文；程序管理关联，模型只给判断”的方向。本批允许确认性能收益及所测合同兼容，**不批准生产替换或整体质量通过**。下一候选先修测试标签/时间，补足业务块语义与未知字段规则；把历史判断、本次查询事实以及观察范围表达清楚，并明确建议是否为必需产物。随后用固定新材料验证正文事实及有依据的判定，不能仅靠 Schema 通过，也不在程序中改写模型错误正文。任务 3.23 保持未完成；旧 Run、初稿、原答和本批失败均保留。
