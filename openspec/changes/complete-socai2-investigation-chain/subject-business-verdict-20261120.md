# 事件与 Case 的结构化业务判定（SF04）

## 范围与业务效果

事件诊断和 Case 综合分析已有结论原文。新增可独立读取的 `business_verdict`，让调用方直接知道该轮对行为性质的判断。它和原结论、可信程度、严重度、处理状态及采用状态同时存在。事件诊断据本轮冻结选入且已分析的成员作出判断。Case 综合分析据本轮结论所声明的原成员范围、证据和待核问题作出判断。模型使用现有 I 与 C6 请求，既有正文和来源字段承载理由及证据。程序校验枚举和关联，沿原轮次保存，不增加模型请求。

| 值 | 语义 |
| --- | --- |
| `malicious` | 本轮证据支持行为构成安全威胁 |
| `benign` | 本轮证据支持所见行为正常或已授权 |
| `false_positive` | 本轮证据表明检测或归因的前提不成立 |
| `needs_review` | 已作业务分析，现有证据不够定性或存在未解决冲突 |
| `null` | 本份已存记录没有可返回的模型判定，例如旧记录、系统收尾、该字段缺失/无效 |

模型按各自职责、范围和证据输出，不由程序从文字、等级、确定性、人工 `classification`、成员投票或未查询/查空推算。恶意与否不修改原告警分诊五字段、事件/Case状态或人工分类。历史记录保持，人工采用模型结果时保留模型来源。人工自身判断沿既有采用记录，本步没有新的人工定性流程。

## 生产、保存和读取

1. 现行 I/C6 结构化 Schema 增加必需的枚举单元，提示词说明各自的判断范围。使用现有原答及单元接收。缺失、非法或重复的字段按实际记录为部分交付，保留原答及独立有效正文，不补成 `needs_review`。业务判定只有在对应诊断或 Case 模型结论可保存为真实结果时才进入业务记录。执行未知、结论不可用或系统交接只留原执行角色。旧输出与原回执继续可读，未提供判定的旧写入重放保持原哈希。
2. 增量 134 在 `incident_diagnoses` 与 `results` 分别增加可空文本列及枚举/发布状态约束，无默认值或历史回填。事件走原诊断完成更新，Case 走原 Result 发布事务。Case 采用不复制一份判定，只有已采用判断的唯一有效模型 Result 来源可提供其判定。列表、指定轮次与当前记录沿各自原指针读取，未知或多个来源保留空值，不找另一轮代替。
3. `GET /incidents/{incident_id}` 返回当前诊断的 `business_verdict`，现有事件列表同型。诊断目录 `GET /incidents/{incident_id}/analysis` 的 `current.result.business_verdict` 和指定轮次 `/incidents/{incident_id}/analysis/runs/{run_id}` 的 `result.business_verdict` 分别按当前指针与指定轮次读取。`GET /cases/{case_id}/results/{result_id}` 和现有调查历史的 `result.business_verdict` 按 Result 读取。`current_assessment.business_verdict`、`page-data.assessment.business_verdict` 及采用历史/预览与各自冻结来源一致。告警交接、现有路由和采用资格规则保持。
4. 4173 已有事件详情和指定轮次、Case 当前与本轮结果按上述字段显示「模型判定」。4177 已有结果和当前采用区使用同一口径。已存记录只从同主体/版本恢复，不更改旧导出。本步不加页面、登录、路由转发设施或 SF07 来源/轮数展示。

## 顺序与直接验收

1. 先完成变更范围、规格增量与本方案，运行本 change strict，再改代码。仓库实际工作分支按现场核对，正式服务暂沿原版本。
2. 验证实际 I/C6 Schema 和接收器。用受控答案覆盖四个合法值、无字段、坏值和重复值，核对独立有效正文、回执与采用资格。补同主体的诊断/结果出入库，在新隔离 PostgreSQL 上先确认旧记录可读，再应用增量并核对旧列及原结果保持。
3. 在同一隔离库走正常 I/C6 生产接口或执行器接收受控答案。比对原答单元、表字段、现有 HTTP 的当前/历史/指定轮次、Case 采用及错误主体路径。有两份有效记录时检验按指针取值，系统/人工结论与原业务分类不代替模型判定。核对警报现有接口合同不变。定向页面检查核对呈现字段和空值口径。用实际保存和读取结果记录通过证据，代码/夹具/真实PG/真实模型分开记。
4. 交付文档注明字段语义、路由、需要的 134 增量和正式验收前置。通过后这一轮只收口 SF04。下一步按现有 HTTP 接告警取数并核相关点击跳转参数与响应，人员/资产/文件由业务后端提供合同。正式版本统一与新选真实告警的一轮分析一起做最终验收。当前受控测试不冒称最终真实告警批或模型质量通过。业务值、响应和原答留私有证据，公开只记结构与检查结论。
