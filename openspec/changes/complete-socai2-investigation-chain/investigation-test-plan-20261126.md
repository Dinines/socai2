## 1. 本阶段交付与依据

2026-11-26，负责人要求先以 4173（C173）需求页面理清调查模块功能，再确定每项功能的数据、覆盖范围、测试方法和接口。本阶段交付规划及逐项矩阵，不生成或投递新数据，不新建 Case/Run，不调用模型，不修改生产逻辑或部署。主机安全多行为场景是候选输入包，需服从本规划，不能代替调查全流程数据。

范围包括 Case 工作区及告警、事件、Case 共用的调查运行视图。告警/事件为调查提供正常上游输入，既有自动处理保留；不重做已通过的告警/事件整套验收。案件助手、定向问答、真实响应审批/新执行及业务后端文件字节上传下载联调沿既有决定后置，仍列在总清单中，不冒充已覆盖。附件引用和元数据能力与文件字节联调分开。

本规划遵循：先完成一个正常业务步骤，再核对同一输入的处理、保存、读取和页面；已有证据有效且合同未变时复用。88 项不等于要建 88 套数据或执行 88 轮模型。

### 2.1 先理解页面，再安排迁移

负责人进一步指出既往迁移经常漏功能且保留旧样式。后续不得以“接口接通”“组件编译通过”或单个卡片完成来认定整页迁移完成。本轮先产出逐页理解和差异表，不开始迁移代码。

[逐页迁移理解清单](investigation-page-migration-checklist-20261126.md)已按17组页面列出目的、进入/返回、正常流程、全部区域及浮层、两侧组件/样式位置和具体差异；每页四项验收要求与88个F编号对应。

以下页面职责必须先区分清楚：

- **案件资料**回答当前采用什么判断、覆盖哪些材料、依据有无变化；**调查概览**回答当前在做什么、还有什么待启动或待人工处理；**调查历史**回答之前每一轮实际做了什么。最新尝试不能直接取代当前采用判断。
- **案件故事**串联事实发生和认识变化；**成员告警**管理当前正式范围；**案件关系图/探索**供阅读和发现候选，探索操作本身不等于正式入案。
- **人工任务**保存核查事实及适用范围；普通评论不自动变成人工事实，任务完成不自动变成采用结果或结案。
- **当轮调查运行**以冻结的 Run 为范围，五个主视图分别是调查发现、AI分析、查询与证据、调查关系图、报告与响应；执行明细位于AI分析下。历史图、原输入和引用不能被当前案数据覆盖。

每页迁移前必须填齐以下内容，发现差异先写进清单再实施：

| 理解项 | 必须说明的内容 | 完成证据 |
| --- | --- | --- |
| 页面目标与范围 | 谁使用、要做什么决定、当前案/当轮Run/选中成员分别是哪一个范围 | 页面职责、入口/出口及对应F编号 |
| 全部信息与控件 | 页头、指标、页签/次级页、列表/图/卡片、侧栏、弹窗、操作入口；含有数据与空态 | 4173逐区清单，不能只盘主内容区 |
| 完整操作流程 | 每个按钮点击后去哪、是否写入、影响哪些主体、成功后何处重读、失败如何结束 | 正常业务流程和动作结果；仅打开/预览不得悄悄执行 |
| 数据与接口 | 字段来源、空值、成员/版本/任务/Run身份、实际方法/路径、平台转发 | 每F项接口和保存读回矩阵；旧客户端不当成当前合同 |

| 整页验收 | 默认正常页面及关键侧栏/弹窗/状态；默认视口内完整可读，正常滚动/缩放有用 | 实际8181逐区对照4173，记录通过项和剩余差异 |

已明确的业务规则优先于原型演示的偶然行为；例如原型本地重绘、占位按钮或固定样例数不能当成正式服务能力。4173与已确认需求存在差异时标明原因和处理口径，不能借此任意换样式或省掉功能。筛选集等清单外的原型额外能力另记待定，不悄悄扩充本期；原型演示数据选择器不作为产品迁移需求。

### 2.2 每页完成必须同时满足四项

1. **功能完整**：该页普通范围的F项和所有关联入口有去向，后置项明确，未连接项不冒充完成。
2. **交互一致**：页签、侧栏、弹窗、选择范围、动作反馈和返回路径按4173及后续确认规则工作。
3. **数据真实**：来自当前正式合同，提交后能读回；保存字段、页面值和范围一致。
4. **视觉对齐**：整页布局和组件样式逐区核对，包括原来容易遗留的页头、工具栏、图标、表格、侧栏和弹窗；保留旧实现的每个差异须有明确产品依据。

以一个边界明确的完整页面为实施步骤，完成实现、必要接线和直接验收后再进入下一页。共享组件修改需同时核直接受影响的既有页，不借迁移重构无关平台模块。没有通过四项的页面保持未完成，不能只按文件修改数或接口数报进度。

迁移前已有具体源码差异：4173的案内导航是左侧分组，8181使用横向页签；案件列表预览图标相对标题的位置也不同。这些都必须进入逐页对照，而不是默认沿用8181现状。图标位置若已有负责人后续统一决定，以该决定为准并记录来源。源码定位之后，还需要在真正迁移该页时以相同视口和对应业务状态核实际布局，不能把本次源码盘点写成视觉验收通过。

## 3. 数据准备原则

### 3.1 数据分为三层

1. **业务输入**：OCSF 告警、独立认证/进程/文件/网络活动、原生资产、人工确认及正常业务附件。按现有入口准备；不写入预期结论。
2. **流程产生的数据**：成员关系、任务、Run、冻结材料、步骤、查询回执、模型原答、结果、采用记录、报告。由正常业务流程产生；不能为了页面展示直接伪造一笔“成功”。
3. **验收预期**：结构关系、应查询的上下文、可支持/不可支持的结论、字段来源及页面预期。与输入分开冻结，不投递到 Kafka，不加入模型材料，不让被测程序读取答案。

旧正常/失败/部分交付批次只读复用，保留旧原答与失败。单纯展示状态可用现有离线组件用例；离线替身不得记作 21、真实模型或 8181 端到端通过。没有适用旧证据的状态标记未覆盖，不为了补齐状态主动制造线上故障。

### 3.2 候选主机安全场景

沿 [主机上下文候选方案](host-context-scenario-20261126.md)，准备两台逻辑主机、必要账号角色、两条检测告警及少量独立活动，覆盖认证、父子进程、文件变化、持久化线索和网络访问；有事前、事中、事后上下文，并有时间接近但会话/进程链不同的正常运维对照。11-26候选规模为2条finding、15条activity；11-27负责人明确要求多元告警及非空ATT&CK标签、Case更新与多轮执行，当前按[两轮方案](host-context-scenario-20261126.md#2026-11-27-两轮案件更新测试)核旧mock模板，优先4–6条告警分两段并配必要活动，具体由当前合同和关联需要收敛，不以数量凑覆盖。

当前调查取证能力主要为认证、进程、网络三类；文件/持久化专用查询、标准认证语义和部分网络语义仍需确认/补齐。可以保存某条原件不代表模型取证工具已能查到它。逻辑上两组行为不强制等于两个实际事件；自动归并结果应按现行关联合同核对，不手写事件成员迎合场景。

输入应覆盖以下方面：

| 方面 | 数据要求 | 验收关注点 |
| --- | --- | --- |
| 身份与作用域 | 每条输入唯一 `metadata.uid`；设备、账号、会话、进程实例有稳定关联；明确来源/租户 | 告警与活动不混用；同主体可关联，不同范围不串案 |
| 时间与版本 | 事前/事中/事后及一组窗外记录；首轮冻结之后再准备后轮补充材料 | 当前结果与旧输入各读各的；首轮不得读取尚未产生的未来材料 |
| 行为角色 | `device`、源/目的端点、父/子进程、认证结果和记录来源职责明确 | 不把目标主机当执行主机；不把进程名称或命令意图当已完成影响 |
| 证据强弱 | 有直接观察的行为、只能支持线索的行为、缺少结果的行为分别设计 | 明确结论有证据；不足部分留下具体待核项，不强造确定结论 |
| 战术与置信度 | 检测源标签/源置信度有明确来源；AI 推断独立保存 | 不把检测标签当 AI 分析或攻击成功证明；空值按合同展示 |
| 正常对照 | 有可核的正常运维上下文，与异常主线存在表面相似性 | 不能仅因相同工具名、账号或时间邻近就判恶意或强行归并 |
| 原生资产 | 对应逻辑主机在既有 `public.assets` 准备最小原生记录 | 页面读真实资产；不靠 IP 对象补值、样例分支或新增匹配规则 |
| 可追溯性 | 输入原件、材料、查询行、引用、Run/步骤/结果关联可核 | 从结果能返回当轮原件；同一来源的复制不当成两份独立证明 |

### 3.3 主机日志之外还必须准备的流程状态

单靠增加活动条数不能覆盖下列功能，需通过正常 Case 操作和已有记录补齐：

- **首轮 Case**：明确成员、初始材料、任务受理、冻结输入、实际 Run、保存结果及报告。
- **同案后轮**：一次有业务意义的新增材料或人工完成版本，形成新依据；保留首轮，比较两轮范围与结果，核当前采用关系。
- **人工协作**：一项待办、一项正常完成及修订历史、必要评论，分别核待办数、活动、适用范围和后轮输入。
- **成员与探索**：一个案外候选及一个可编辑的目标测试 Case；扩展/撤销/恢复探索不改变正式成员，显式加入/移动后才改变双方成员。
- **历史状态**：复用已有正常、失败、部分交付、查空、未查、结果未知等有效记录。没有记录时保留未覆盖，不增加故障注入。
- **已有文件与响应**：已有报告、可回查材料、已有响应回执；附件字节和真实响应执行按各自依赖保留边界。

源数据、人工版本、保存结果不可互相替代；主 Case 与目标 Case 是不同职责，不能为了减少用例而移动只读历史验收数据。

### 3.4 七类数据包与最小组合

这些是同一业务流程的不同材料，不要求分别建七套数据。每个 F 编号使用哪些包，已在逐项矩阵中对应。

| 数据包 | 最少准备内容 | 主要验证功能 | 是否需要新增数据 |
| --- | --- | --- | --- |
| `PKG_FROZEN` 既有冻结记录 | 已结束的 A/I/Case Run、原输入、正常/失败/部分交付及查询状态 | 历史、运行目录、五个运行视图、原件与状态区别 | 优先只读复用；缺状态保留未验，不重派 |
| `PKG_HOST_CANDIDATE` 主机上下文 | 两主机、首段/追加段的多元finding与必要activity、非空ATT&CK源标签、原生资产和独立预期 | 首存、关联、取证、标签、跨记录分析、正常对照 | 11-27新指令进入M0模板/合同核对与准备；独验后分段从Kafka接入 |
| `PKG_CASE_WORKSPACE` 工作区与成员 | 一个主案、一个可编辑移动目标案、初始与追加成员、管理版本 | 列表/指标、资料、管理、成员、移动、变化提示 | 正常操作产生；目标案优先复用，列表不为凑分页批量造案 |
| `PKG_HUMAN` 人工协作 | 两个普通任务：一完成、一待办；必要修订、一条评论 | 待办、完成范围、来源、人工版本、故事、后轮影响 | 最少正常新记录；既有版本冲突证据复用 |
| `PKG_RESULT_EVOLUTION` 结果演进 | 首轮、一次有实际变化的后轮、固定比较基线、合格候选/当前采用结果 | 冻结、比较、覆盖、人工影响、采用、旧结果回查 | 正常流程产生；不得直接写结果来凑正例 |
| `PKG_EXPLORATION_EVIDENCE` 探索与证据 | 案外候选、真实对象/索引/原件、一个探索保存状态 | 推荐、扩展/撤销、恢复、正式加入、当前/历史图 | 可复用候选第二条 finding；需确认实际同源对象能匹配 |

## 4. 按正常业务旅程执行

本表为后续执行顺序，每步先验收再进下一步；不是本轮执行授权或已通过记录。

| 步骤 | 要完成的业务效果 | 最小操作与必要验证 | 通过证据与停止边界 |
| --- | --- | --- | --- |
| P0 功能与合同核对 | 每项功能知道入口、输入、读写关系和实现状态 | 核 88 项；检查实际路由和源码合同；标出 4173/8181 差距及历史证据适用版本 | 本规划、逐项矩阵、覆盖审查；路由存在只记接口存在 |
| P1 复用记录验普通读取 | 用户能读懂已存调查及实际交付，引用可达 | 先用已有明确身份的记录核历史、目录、五个视图、原输入/步骤、查询、图、报告与已有回执 | 同 Run 原件/引用及实际页面；旧验收记录不直接等于当前8181通过，缺状态不新造故障 |
| P2 必要输入与主案首轮 | 有可查询上下文和原生资产，正常输入支持首轮保存展示 | 先冻结数据及定向离线校验；原生资产走既有入口；上下文可用后投递 finding；核自动 A/I；建案读 `initial_task`，绑定 Run 后核结果 | Kafka→材料→任务→Run→步骤/结果→HTTP→8181/4177；202 不等于完成；字段/工具不足则停本步修通用阻断 |
| P3 管理、人工任务与附件引用 | 普通协作正确保存，人工事实有明确范围与版本 | 逐项正常管理、评论和读回；创建两个任务、完成一项；核已有附件引用和元数据，文件字节联调仍后置 | 管理活动、待办数、修订、适用范围；文件保存与关联分开记录；不额外手动派发模型 |
| P4 探索、增量、后轮与采用 | 新材料/人工完成能影响新轮次，旧轮次保持冻结 | 案外候选扩展/撤销、保存/恢复；正式加入；按正常策略执行一次有新依据的后轮，核完成修订、固定比较和合格结果采用；无变化检查在下一次版本编辑前进行或复用旧证据 | 探索不隐式改成员；后轮有真实变化、旧引用不漂移；采用不改变处理/执行状态；不重复自动/手动派发 |
| P5 移动、管理收尾与独验 | 两案成员、当前范围和历史都正确，供负责人看页面 | 移动一次至可编辑目标，读回两案与旧历史；按现有合同核关闭/重开；统筹独立核保存/HTTP/8181，核心另核正文质量；更新4177 | 逐项通过/未过/未验/后置；新待更新按实记录，重开不冒称已重跑；再交负责人看8181，不宣称整个change自动完成 |

模型使用以最小正常流程为目标：主案首轮和一次有新依据的后轮。若已有等价有效 Run 可复用，则减少新调用。建案自带首轮任务，不能建案后再无理由提交一次 rerun；新建移动目标 Case 也可能触发首轮，优先复用明确可编辑的目标测试案，不能将其隐含调用记作零。告警/事件既有自动任务及实际模型调用另列清单，沿当前 profile 的单 Run 限制，不增加多模型、多轮采样对比。

### 4.1 页面迁移与业务测试的配合

页面迁移不能等到投递新数据后才发现基本合同不通。先以已有记录和已完成的理解清单，按以下依赖选择一页：公共布局/导航与Case列表 → 案件资料及调查概览 → 成员与人工任务 → 故事和历史 → 当前关系图/探索及对象证据 → 运行目录及五个主视图。评论和附件元数据随所属页面处理，后置能力保持边界。这个顺序是依赖安排，每次只推进其中一个可直接验收的页面。

每页先核原型完整信息、交互与状态，再核当前接口；明确所需数据之后才实施。正常读取可用既有Run，保存类再按P2–P5的正常操作补证据。两种顺序分别解决“页面怎样完成”和“业务数据怎样产生”，不要求为了核一个布局就新跑模型。视觉对照核布局和状态，真实业务值按保存/API核验，不要求复制原型示例数值。

## 5. 每项功能怎样判通过

### 5.1 页面与数据

以同一主体、同一输入版本/Run 做对照，依次核 **保存结果 → HTTP 返回 → 8181 展示/操作后重读**。4173 决定页面信息层级、交互和含义，真实字段与空值取现行合同；不复制原型里的样例数字。4177只用于看实际步骤和原答，不能替代8181产品验收。

- 读功能：数值、成员、来源和范围对应，原件入口可达；已有记录与“未提供”、空结果、加载失败有明确区别。
- 写功能：一次正常提交返回成功后独立读取；只更新本次明确作用的主体和字段，刷新后仍一致。各模块沿自身已确认合同，不把告警最后保存规则擅自推广到人工任务修订。
- 异步功能：受理、排队、执行中、Run绑定、保存结果分开核。提交成功不得立即显示“调查完成”，缺失 Run 不能拼出假链接。
- 版本功能：旧轮次输入、证据、图、人工引用保持原范围；新材料只影响新轮次/当前提示。最新尝试、最新保存结果和当前采用结果分别展示。
- 导出/下载：沿实际已有接口核内容范围和已有文件；未接文件字节服务时注明元数据/路由检查和真实下载的差别。

### 5.2 调查正文质量

程序功能通过与模型分析质量分开记录。核心核对：结论是否回答本轮目标；引用是否存在且属于当轮范围；是否综合上下文和正常对照；是否把来源标签、历史判断或人工陈述误当独立事实；是否把企图说成成功、把未查说成查空、把建议说成执行。缺证据可以待核，但要指出缺什么。

不要求模型输出与预期文件逐字一致，不用有报告/HTTP 200/Schema通过代替业务质量。已确认后置的正文质量问题保持原结论和原答，不再反复采样；新发现的程序阻断仅定向修复和复验。

### 5.3 状态和范围

覆盖正常有数据、正常空、未提供、已有失败/部分交付/未知以及新旧版本差异，但不作笛卡尔组合。不复测权限体系、压力、恢复、极端竞争、全库或全接口。代表性状态来自已有有效证据或既有离线测试时，在矩阵中注明证据等级；不能把离线状态显示验收写成真实服务验证。

### 6.1 已定位的迁移与接口差距

以下为当前源码/已审合同的差距，不是本轮真实功能测试失败统计；修复必须作为对应页面的正常产品接线，不引入测试专用路径。

| 差距 | 影响功能 | 处理责任与验收落点 |
| --- | --- | --- |
| Case仍有旧prepare/start调用，而现行服务使用异步investigations与任务读回 | 建案、检查更新、启动、状态提示 | 前端/平台后端对齐HTTP；沿initial_task/status_url到实际Run，核受理与完成分开 |

| 案件故事仍有旧offset/kind等参数及旧投影 | 时间线、过滤、来源回查 | 前端/平台后端按q、severity、limit、cursor等现行合同对齐 |

| 共用步骤/工件代理当前只支持已核告警Run | 事件/Case的执行明细、查询与原件 | 平台后端/HTTP按主体实际支持接线；事件内部定位不能冒充所有主体已接通 |
| Case对象/资产汇总、统一响应聚合并无对应完整原生路由 | 对象概况、已有响应读取 | HTTP明确现有成员/索引/工件取数；真实缺项按产品需要补通用能力，不拼假数值 |
| 主机认证/网络字段语义、文件/持久化工具存在缺口；A提示/Schema/证据角色已有未完项 | 上下文查询、标签和模型判断 | 调查核心按功能目标逐项处理；来源标签贯通不等于AI标签修复 |

文件字节、助手问答和新响应执行的后置边界继续保留。以上普通功能差距应在对应页面的数据运行之前解决；不能先大量造样例、反复跑模型，再用前端补偿掩盖接口问题。
