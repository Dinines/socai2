# C3 当前输出内容与职责讨论

2026-11-14。本文供第1阶段讨论C3输出内容使用，核对当前代码、配置及11-14三案实际请求。以下“当前要求”描述清单核对时的生成合同，“调整建议”是待讨论方案；清单核对本身没有修改提示词、Schema、业务程序或输出额度。后续负责人确认保留七部分先做真实测试，并允许提高额度；见[直接验证方案](c3-capacity-validation-20261114.md)。

C3负责根据固定Case成员及现有材料形成初步解释，供C4决定和执行补查、供C6复核综合。当前一次C3模型回复必须包含七个顶层部分：`summary`、`members`、`findings`、`questions`、`domains`、`conflicts`、`followups`。七个键都必填，其中部分列表可以为空。

原提示中的“最多3个核心发现”指第三部分 `findings` 的分析要点数量。负责人随后确认放宽为**最多5个核心发现**，不要求填满；当前提示/Schema尚未修改。一个发现可以关联一条或多条告警；每条告警仍须在 `members` 中交代。四个领域来自同一次模型输出，由程序分别保存工件，不是四次独立分析。以下当前实现及历史样例保留当时数值，最新实施目标见[阶段1方案](stage1-problems-and-plan-20261114.md)。

## 当前七部分输出

| 部分 | 当前要求模型输出什么 | 数量与主要规则 | 用途和初步判断 |
| --- | --- | --- | --- |
| 案件概述 `summary` | 一段Case初步解释 | 必填文本；没有单独的引用字段 | 方便阅读总体判断。可保留短概述，避免重复逐成员事实、五问答案和全部限制；结论措辞仍由模型负责 |
| 逐成员说明 `members` | 每条告警的分析状态、摘要、证据和限制 | 每个固定成员恰好一项；本批C01/C02为3项、C03为1项 | 防止只分析部分成员。身份和结构覆盖由程序核实，业务摘要仍是模型判断；事实复述可与发现部分讨论合并 |
| 核心发现 `findings` | 观察、推断或未决要点；涉及成员、支持、反证、替代解释及限制 | 提示词最多3个，实际Schema最多24个；列表可为空。直接观察的正文已由程序生成 | 承载可引用的分析要点，供领域、冲突和后续分析使用。保留实质发现；统一数量合同，减少与成员摘要、五问重复的表达 |
| 固定业务问题 `questions` | 五个指定问题各自的状态、回答、证据和限制 | 必须恰好5项，且各问题只出现一次；answered须有依据 | 明确初步调查回答了什么、还缺什么。问题维度有价值；可讨论引用已有发现、只写该问题新增解释 |
| 领域判断 `domains` | 身份、云、钓鱼、内部威胁四个领域分别是否适用、原因、范围、相关发现及限制 | 恰好4项，即使领域不适用也必须填写；非applicable还要求限制 | 用于领域视图及工件。属于优先讨论的结构负担；可考虑仅适用/待核领域展开，但“未输出”不能由程序直接解释为“不适用” |
| 发现间矛盾 `conflicts` | 哪些发现互相冲突、是否解决、解释和依据 | 可为空，最多12项；每项至少关联2个不同发现，并有符合要求的原始观察支持 | 真正互斥事实需要保留。缺证据或不同可能性不应填成矛盾；程序可核结构和来源，不能机械判断自然语言是否矛盾 |
| 必要补查 `followups` | 针对哪个问题、查谁、采取什么方式、查什么、需要什么证据及优先级 | 可为空，当前生成和接收均最多2项；有可用候选才能选择query | 是C4的业务输入，应保留明确目标和证据缺口；绑定已确定的参数及固定空值可评估交由程序恢复 |

## 各部分字段

下表对应模型实际要写的字段，而非包含程序装配内容的最终保存对象。

| 部分 | 字段及含义 |
| --- | --- |
| `summary` | Case初步概述文本 |
| 每个 `members` 项 | `alert_id`：成员短号；`state`：analyzed/unresolved/not_analyzed；`summary`：本成员说明；`evidence_ids`：依据编号；`limitations`：限制。未分析或未决须有说明，程序检查完整成员及来源归属 |
| 每个 `findings` 项 | `id`：本轮发现号；`state`：observed/inferred/unresolved；`statement`：推断或未决正文，observed分支不输出；`alert_ids`：涉及成员；`support_ids`：支持；`counter_ids`：反证；`alternatives`：其他可能解释；`limitations`：限制。observed只能选相应直接观察，inferred需支持，unresolved需限制 |
| 每个 `questions` 项 | `id`：固定问题号；`state`：answered/unresolved/not_applicable；`answer`：回答；`evidence_ids`：依据；`limitations`：限制。后两种状态须有说明；当前生成Schema尚未完整前置answered非空依据条件，接收端会校验 |
| 每个 `domains` 项 | `name`：领域；`applicability`：applicable/not_applicable/undetermined；`reason`：适用判断理由；`alert_ids`：本领域关注成员；`finding_ids`：相关发现号；`limitations`：限制。发现保留自己的原始范围，不随领域范围缩小 |
| 每个 `conflicts` 项 | `id`：冲突号；`finding_ids`：参与矛盾的发现；`state`：resolved/unresolved；`explanation`：矛盾及解决情况；`evidence_ids`：原始支持。引用至少覆盖各参与发现的实际成员和原始依据 |
| 每个 `followups` 项 | `question_id`：要补的问题；`alert_ids`：涉及成员；`mode`：query/deep/graph/human；`objective`：目的；`required_evidence`：缺什么证据；`source_ids`：为何提出该需求的已有依据；`object_keys`：涉及对象；`binding_id`：query选择的可用绑定，其他模式为null；`priority`：decision_critical/supporting |

一般文本字段为1–1200字符；普通来源引用列表最多32个编号；每处`limitations`最多12条，发现的`alternatives`最多8条。大部分限制是上限，不要求填满。列表即使为空，当前对象仍要求对应键存在。字符限制与输出tokens配额是不同计量。

## 五个问题和四个领域

| 固定问题 | 当前实际提问 | 重复风险或分工 |
| --- | --- | --- |
| `detection_facts` 原始事实 | 原始记录支持哪些行为和对象 | 容易再次复述members和observed findings；事实路径和值可由程序呈现，选择哪些事实支撑初步解释仍需模型判断 |
| `member_relationships` 成员联系 | 成员告警之间有哪些已证实的行为联系 | 保留“共同对象/时间邻近”与“有证据的行为连接”的区分；前者可程序提供，因果解释不能程序推定 |
| `behavior_nature` 行为性质 | 恶意、正常或误操作等解释分别有哪些依据和反证 | 核心模型职责；容易和findings的alternatives、总summary重复 |
| `authorization` 授权范围 | 谁确认了哪些行为、对象和时间的授权 | 核心模型职责；程序提供原文、角色、对象和时间，不能自动把陈述升级成授权事实 |
| `impact` 实际影响 | 哪些影响已经观察到，哪些只是待核的可能影响 | 保留动作、结果、影响的区别；程序可呈现真实动作/结果，模型解释仍须有据 |

四个领域分别为：

- `identity`：认证、MFA、会话、权限及授权范围。
- `cloud`：云控制面、资源、IAM、配置及影响。
- `phishing`：邮件身份与邮件头、链接或附件、投递、点击和执行。
- `insider`：数据访问或外传、数量、目的地、时间、行为基线及授权。

当前无论案件主题是什么都须输出这四项。领域`reason`和`limitations`在不适用/证据不足时容易重复。例如C02的phishing写“无邮件、链接或附件相关记录”，限制又写“无相关数据”。缺少领域证据究竟表示“不适用”还是“尚不能确定”仍需保留明确判断，不能统一由程序填默认值。

| --- | --- |
| 第六问 `coverage` | 模型仅答上述五问，程序按输入可见成员、材料读取/查询回执、实际保留分析状态、矛盾和补查数量补第六问；保存读取仍为六问 |

## 优先讨论的调整方向

以下1–4项保留最初输出职责讨论的备选方向，不是阶段1已经决定实施的删减或重构。后续已确认保留七部分、8192及引用质量后置；本阶段以[整体方案](stage1-problems-and-plan-20261114.md)为准，不继续把缩减七部分或改准引用作为实施前置。

1. **保留业务判断和必要依据。** 初步解释、行为联系、性质、授权范围、实际影响、反证和补查目的需要模型处理；程序仅凭字段存在无法替代判断。
2. **先审成员说明、发现、原始事实问题的重复。** 可考虑事实只表达一处，其他部分引用对应发现；逐成员覆盖、逐主张依据及范围必须仍可核对。短号、固定成员目录、计数等可由程序恢复，不能把“输入有材料”当成“模型已分析”。
3. **再审固定四领域和重复限制。** 可讨论保留简短适用性判断，仅对相关或待核领域展开；对同一问题反复出现的通用限制减少重复要求，真实业务限制和反证保留。现有保存/读取所需结构由明确适配维护，不能用默认理由凑旧合同。
4. **补查保持可执行的最小描述。** 目标、缺什么证据、问题/成员范围和优先级保留；query选定绑定后已冻结的主机、成员、窗口由程序恢复，必要对象选择仍须准确。非query的固定`binding_id=null`可作为内部输出精简候选；已有SQL/执行参数本就由程序处理。
5. **落实已确认的七部分、8192额度与最多5个发现。** 同一冻结C02请求的4096/8192对照已完成，负责人确认采用8192输出上限，保留一次回复七部分，并补充确认最多5个核心发现。C3数量合同及C6预留随最终实施对齐；引用问题后置且保留原结论的决定已明确，回答缺项或截断后按可靠边界最多一次只补缺失字段，显式重带同Run上下文；详细规则已写入阶段1设计，尚未修改运行配置。

## 8192确认与引用问题实例

2026-11-14，负责人确认“先按8192，保留一次回答七部分”，并要求先看本次引用/范围失败实例，再讨论处理方式。此处记录已确认输出方案与待讨论问题；未改变程序或原测试结论。

本次C02：A1为登录、A2为出站连接、A3为PowerShell进程启动。来源编号及归属来自[冻结计划](../../../docs/operations/evidence/c3-capacity-20261114-01/plan.json)，输出见[8192原答](../../../docs/operations/evidence/c3-capacity-20261114-01/C02-8192/answer.txt)。

**成员条目中的跨告警引用。** A1摘要原文为“记录06:38:27登录成功，人工反馈未确认其授权，仅确认后续PowerShell启动。”它的23项依据中，8项属于A3，例如`N3_S68=powershell.exe`、`N3_S69=powershell.exe -NoProfile -Command Get-LocalUser`、`N3_S70=process_start`。当前接收器对成员条目执行“每项来源必须覆盖当前成员”的规则，因此报`source_member_mismatch`。这证明违反了现有合同，不能仅据此断定跨告警引用本身就是事实错误：摘要确实提到了A3，可能存在合理的背景用途。但A3进程记录不能替代A1登录本身的证据，也不能充当人工授权的原文依据。当前一个引用列表未区分支持哪一项主张，需要讨论如何表达和校验；不能简单把所有跨告警引用删除或改变来源归属。

**发现范围与所选依据不一致。** F1标记为`observed`，声明`alert_ids=[A1,A2,A3]`，但32项支持引用去重后只有30项：14项归属A1、16项归属A2，0项归属A3。A3原始进程记录已经在输入中，且在其他输出条目被引用；问题是F1没有选用这些依据。此类观察正文由程序按所选来源装配，不能凭F1声明的范围补出A3观察。究竟是漏选A3依据还是多声明A3，需要保持判断和引用对应，不能由程序任意补引用来过校验。该错误继续影响依赖F1的领域和冲突条目。

Case联合分析应容许合理跨告警背景和关系判断，同时保留来源的原归属及角色；程序可核对来源存在、归属、重复和覆盖，语义上支持哪条主张仍需明确表达。后续处理以负责人确认的局部清理、问题记录及结论保留原则为准，具体Schema和程序装配仍待细化。

## 已确认：记录问题并保留分析结论

负责人最终澄清：**引用正确性作为独立质量项后置处理；引用不对不代表结论不对。** 保留模型原结论、原判定及分析正文，另行记录引用问题。前述“只保留通过引用检查的结论”或“引用缺口就把结论标待核”的理解不适用；不能以引用校验替代业务判断。

1. **原答和问题均保留。** 原始回复保持不变；派生结果记录问题位置、来源编号、归属/范围、处理原因、处理前后值及复验结果。错误不被修剪动作核销，保留问题的关联及查阅入口。
2. **引用清理不改结论。** 完全重复的引用可确定性去重；明确不适用的引用可从有效引用集合剔除并记录。此类清理不删除对应结论，不自动改变原业务状态，也不随意补造引用或改变来源归属。具体引用准确性、空引用及范围匹配优化归入后续质量工作，不作为当前结论保留的前置。
3. **保留原结论和原业务判定。** 成员说明、发现、问题回答、整体摘要等继续保存、展示及供后续分析使用，引用问题作为并列质量信息提供。不能仅因引用错配、漏引或空引用将结论判错、改成待核、清空或替换成通用占位话；模型本来判待核的仍保持待核。只有对业务内容的独立判断才可能改变业务结论，不能由引用校验结果代替。
4. **问题不沿依赖变成结论删除。** F1有引用问题时记录F1及依赖条目的相关提示，不因此删除F1的模型分析、领域判断、冲突解释或其他独立结论。程序生成的原始观察仍按实际可解析来源装配，不编造未选用的原字段；实际引用覆盖与模型声明范围分别记录，不由此推导模型业务判断错误。
5. **质量与交付分开。** 七部分完整性、模型原业务判定、引用质量和采用状态分别记录。引用质量未通过不单独使整份分析rejected/unavailable，不作为当前功能推进或结论保存展示的硬门槛；也不自动改变原有业务采用流程。不为已后置的引用问题新增模型纠正或反复采样，既有真实失败、unknown和原始回执保持。

现有能力核对：[analysis_review.py](../../../services/api/app/socai2/analysis_review.py)已经按成员/问题/发现等单元保留通过检查的子集，C3可继续使用该子集。此次8192[离线校验记录](../../../docs/operations/evidence/c3-capacity-20261114-01/structural-review.json)已保留A2/A3说明、F2/F3、五个业务问题、phishing领域及一条补查；A1/F1及依赖F1的部分被排除或替换为占位说明。F2保留的结论包括“A3进程启动获人工确认授权，但该授权未覆盖A1登录和A2外联”。这是离线保留结果，不是本批已新增保存/展示或证明正文全部正确。

上述现有逻辑描述的是当前实现与旧试验结果，尚未满足最新决定。阶段1只处理结论与引用质量分开保存、展示和继续流转所必需的合同衔接；引用准确性改进后置到阶段6，不继续以“修准引用”作为交付前置。JSON不可解析、主体身份无法确定或实际保存读取失败仍属于程序交付问题，不能伪装成功。无需新建通用语义评判或质量框架。本轮仅更新方案，程序和运行配置尚未修改。
