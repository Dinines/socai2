2026-11-08，用户进一步要求从原五字段文案出发，参考 OpenAI / Anthropic（Claude）官方提示词工程实践改善混乱的结构。交付[独立候选 v3](../../../tools/testdata/alert_prompt_eval/five-field-system-v3.txt)，保留 v1/v2 原件。用户随后要求不再展示旧对照、做本版一轮测试，已完成9次独立调用，格式通过但正文质量未通过，见[本轮结果](alert-prompt-validation-20261108.md)；生产分诊未切换。

## 设计依据

- OpenAI 的[提示词工程指南](https://developers.openai.com/api/docs/guides/prompt-engineering)建议明确任务和输出，用 Markdown/XML 划清指令与材料的边界，并通过评估观察版本变化。这里采用普通 Markdown 分区；现有 system/user 消息已经区分指令和业务材料，不为套用 XML 改动输入结构或 API。
- OpenAI 的[提示词生成示例](https://developers.openai.com/api/docs/guides/prompt-generation)强调理解现有任务、保留用户提供的细则和示例，对复杂提示词优先改善清晰度。这是官方文档中的生成提示词示例，不是本项目必须机械照搬的规范；本次采用其“保留既有规则”的原则。
- Anthropic 的[提示词最佳实践](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)强调明确、具体、分步或分区表达，按需用标签隔开指令、上下文和示例。这里据此把任务、判定、来源、事实边界和输出职责分开。

这些指南支持组织方法，不替本项目定义良性/恶意判定，也不证明当前内网模型会因此更准确。无模型切换，不套用 GPT/Claude 专属参数或角色协议。

## 从原文到候选

| 原文职责 | v3 位置与处理 |
| --- | --- |
| 单告警、基本查询后分诊 | 首句直接说明对象、任务和交付 |
| 四种判定含义 | 第1节逐项排列，保持恶意/真实正常/描述不成立/证据不足的区分 |
| 未提供授权、名称/来源/演练/低分/查空 | 第1节集中保留，不将人工确认设为必经条件 |
| 输入数据不是指令 | 第2节统一说明，合并尾部重复段 |
| 五种来源角色 | 第2节逐项释义，保留来源不可替代 |
| 历史原文、历史错误与旧编号 | 第2节保留，历史说法不能自动成为本次事实 |
| action/outcome与进程/网络/协议语义 | 第3节保留原版具体例子，不替换成仅有抽象口号 |
| 时间、上游等级与模型置信度 | 第3节保留各对象边界 |
| 未查/失败/未知/查空、上游no TI match | 第3节集中保留，本次回执为查询事实来源 |
| 五字段及各自职责 | 第4节逐项对应Schema，格式只声明一次 |
| 证据角色/内容支持主张 | 第4节保留确定性判定的observation或human_statement范围，不改Schema |
| 置信度无法估计时null | 第4节保留，不规定needs_review必须为null |
| 建议、引用数组、不输出额外字段、未处置 | 第4节集中说明 |
| “格式有效不保证主张真实” | 正向改写为第3节“只陈述材料能够支持的事实”，评估继续单独核正文真实性 |

本次优化目标为可读、可维护与规则不遗漏；不承诺字符数或tokens下降。没有加入原测试样例的正确标签或完整答案，没有增加“缺人工确认必定待复核”“必须100%排除所有可能”等门槛。
