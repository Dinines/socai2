## G1 底图与身份

1. 无显式原轮时先 GET `/cases/{case_id}/exploration`。有 snapshot 则读其 `base`、`expanded_links`、`expanded_sources` 和支持的 `view_state`，保持保存时基线；不能用最新 Run 替换。`snapshot:null` 才 GET `/cases/{case_id}/exploration-base`。请求失败不能当 null 或空图。
2. E67 无参优先该案最近 completed baseline；没有完成轮时返回 `kind=members,graph_state=members`。显式 `run_id` 只接受同案 completed baseline。前端只提供合同支持的选择，URL 或选择变化必须清旧选择和工件。没有额外“强制当前成员”接口，不伪造该选项。
3. 调查图固定 `run_id/result_id/graph_artifact_id`；`graph_state=unavailable` 保持原身份和缺图说明，不能借其它轮或成员图冒充该轮。失败轮、AI 轮或同轮其它 Result 的已存图沿原固定结果 E14→E15，在已有调查历史入口阅读，不通过 E67 改造支持范围。G1 不迁移该固定 Run 图正文。
4. 成员图只用 E67 的 `sources.alerts/objects`，以实际 `alert_id/material_id/namespace/object_type/object_key/source_path` 建节点和 observed 关联，沿已有通用映射合并相同对象。不从文本、IP 样例或当前其它材料猜边。调查图保留原工件的节点、方向、关系类型、依据和限定；快照展开只用它实际保存的匹配与来源。
5. 标题、底图类型及原调查身份清晰；需要开始时间/标题时按明确 Run 从既有读取取得，不串入全案历史目录作为默认读图前置。原轮入口复用 `/cases/{case_id}/investigations?run={run_id}&view=graphs&result={result_id}`，无 Result 时省略该参数。材料/工件只在点击后按原身份读取，不为所有图节点预取。

## G1 展示与普通接线

原型来源为 `investigation-workspace.js`、`investigation-graph.js/css` 和 `case-exploration.js`。采用左告警与检测、中画布、右选中节点/边详情，圆形图标节点，自动/列式布局、相似节点分组、缩放和重置。容器宽度决定三栏：普通宽屏约 195px/自适应/290px；900–1080px 约 160px/自适应/270px；更窄按原型折行。不能硬套截图视口导致右栏溢出。默认适应全部当前可见节点，保留现有主题。

右栏只显示选中项有值的说明、真实关系及来源入口；无选中有简短操作提示。原始对象不伪装为已登记资产，不显示空对象资料或重复整份告警列表，不把 JSON 字段路径当业务描述。左侧点告警与图内选择互相定位，分组选择仍可追溯实际成员。加载、确实无图/无边、缺工件和读取失败分开显示；失败不把残余节点数当完整图。

平台仅新增 E67 GET（可选 `run_id`）和 E69 GET（无参数）的正式注册与公开 DTO，接入 28085 现有 Case 读取客户端和配置中的 64875。保留普通登录、权限、UUID/重复与未知查询参数校验及原生错误透传，沿用现有 Story/History/list/fallback。E68/E66 不在本步改写。前端使用生成合同、Case 局部适配，不改事件/告警共享行为。
