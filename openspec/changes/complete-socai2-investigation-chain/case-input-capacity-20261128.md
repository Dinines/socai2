## 首步依据与选择规则

源码 `services/fusion/app/services/lake_alert_receiver.py` 的接收器将 OCSF 对象保存到 `raw_event.ocsf_event`，并将保留格式的原始字符串保存到 `raw_event.source_ocsf_json`。两者属于同一次材料保存，字符串副本有原文追溯用途；它本身不是另一条独立观察。

`case_input_text.material_entries` 按已识别 RawAlert 外壳遍历材料；`case_c3_input_selection.select_rows` 已处理 `raw_text`/`raw_data` 的部分重复，但未覆盖上述命名镜像。`case_followup_selection.records` 复用冻结记录和 C3 的结构筛选，C6 的判断职责与原始依据要求继续保持。

| 输入结构 | 判断用途与处理 |
| --- | --- |
| `ocsf_json` / `raw_json.raw_event.ocsf_event` 的已选字段 | 当前业务事实或检测标签，按现有类型、角色、来源及范围保留；同材料已有去重继续使用。 |
| 已识别外壳的 `raw_json.raw_event.source_ocsf_json` | 只有严格解析为结构对象，且与配置指定的同材料 OCSF 对象完全一致时，才能作为重复镜像省去。规则路径走 Case 配置；使用完整结构和类型比较，不做字符串相似度或字段关键词判断。 |
| 含不同、额外或缺失字段的镜像 | 保留原字符串及原 `source_label` 角色，不把差异猜测成冗余，不提升为观察证据。 |
| 无效 JSON、重复键、非结构 JSON、未识别外壳 | 原样沿既有材料路径处理，不能用解析失败掩盖材料或直接当空值。 |
| 被有效前序、人工材料或后续依赖明确引用的镜像 | 保留所引原文及原引用；完整材料/祖先容器引用亦不可因本规则静默失去依赖。 |

类型、数组次序和字段路径参与等价判断。`0`、`false`、有效空列表及未知业务字段保持各自含义。只改变模型视图；材料原件、引用目标和原存储不改写。省略台账记明原因和对应结构来源，沿既有工件保留，不把台账正文重新塞入模型。

### 唯一实施落点

接收器在 `field_metadata.lake_ingress` 保存 Schema/库定位、湖来源引用、来源主体及事件标识，用于定位和追溯；这些信息不参与 C3 的行为解释或 C6 的最终判断。现有 Case 顶层 `material_backend_paths` 只精确匹配 `$.raw_json.field_metadata`，通常展开为子字段后不命中；当整个父对象因不可寻址键被保留时，又可能误删未知兄弟。不能把此规则直接扩大成对全根的前缀过滤。

候选按 Case 配置明确选择 `$.raw_json.field_metadata.lake_ingress`，仅在已有结构确认 RawAlert 外壳时应用，匹配完整路径或其后代边界；其余位置的同名字段保持。旧全根规则应收窄，空管理外壳沿可选空值规则处理。无法按既有路径安全拆分的非空父对象保守保留，不构造额外路径解析或投影框架。

使用已有依赖保护机制保留前序、人工、整材料及祖先/后代引用，保留原角色/路径/成员关系。该保护只用于本步新增选择，不扩大其他已配置字段的选择范围。A/I、M0c 镜像比较、输出/存储合同、预算和执行链不变；C6 从相同冻结表示接收结果。
