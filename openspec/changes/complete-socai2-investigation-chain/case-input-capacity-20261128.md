# Case 输入容量：按用途选择材料

本阶段属于 `complete-socai2-investigation-chain`。负责人要求先排除明确的 unmapped 材料，使用近期冻结输入核对效果，再按条件提交本轮修改；单告警提取事实及按需检索作为后续方案。此次交付包含过滤所需的既有镜像/后台字段选择及计量依赖，不更改公共告警合同、数据库、旧 Run 或服务部署。

## 目标与步骤

1. 在同一份材料内部识别完整 OCSF 文本镜像，仅在严格解析、结构和值类型完全一致且无明确依赖时省去副本。其他正文保持原有处理。
2. 已识别 RawAlert 外壳中的 `field_metadata.lake_ingress` 属于后台入站台账，按完整路径边界留在后台；未知兄弟字段、其他位置同名字段及明确依赖保持。
3. 执行下面的 M0f 过滤，核输入构造、JSON 保存读回、后续阶段及观察正文装配。
4. 对冻结材料使用已有 tokenizer-only 入口，按原目标、配置和预算核实际请求；原件、原答及失败保持，结果留私密文件并按 AGENTS 数据边界处理。
5. 统筹独审及直接验证完成后，按负责人本批分阶段授权交付 V1.1。真实模型、数据库与页面业务验收另行推进，不能以字符或 token 减少代替业务质量。

## 第一步 M0f：Case 材料的 unmapped 选择边界

新 C3、Deep、C6 输入排除配置声明的 `$.ocsf_json.unmapped` 和 `$.raw_json.raw_event.ocsf_event.unmapped` 容器及后代。只改变模型业务视图，不删除后台原件，不全局按同名键或样本值筛选。

固定序列化入口包括 OCSF `raw_data`、材料 `raw_text` 和自有 RawAlert 的 `source_ocsf_json`。仅严格解析并证明为同材料完整对象或已排除容器副本时投影/省略；先处理容器副本，再处理外层 OCSF 镜像。无法解析或无法证明同源的任意正文保留既有检查，不宣称已经过滤。

明确前序引用不能豁免 unmapped 边界。已知 C1/C4 工件回取沿已有不可见依赖语义处理，其他有效支持与反证保持。发生过滤的材料父对象使用可见观察值装配程序观察正文，防止后续阶段借前序正文恢复原件；原始值仍留后台。

已映射字段、原角色、来源路径、成员关系，以及其他业务位置的同名键、未知扩展、有意义的 `0`、`false` 和空列表保持。省略台账供后台校验，不逐字段加入模型正文。不按测试数据、厂商、主机或内容大小增加特判。

## 必要实现与配置

- `case_c3_input_selection.py`、`case_input_text.py`：精确字段选择、严格同源镜像、保留原件与可见观察值。
- `case_followup_input.py`、`case_program_output.py`：后续依赖及程序观察正文应用同一边界。
- `case-input-v1.json`、`runtime_policy.py`：Case 配置 v7 及限定路径验证。按现有 profile 加载，未提高预算或停用内容检查。
- `token_budget.py`：复用本轮计量所需的已确认协议口径。已识别的纯文本 `chat_completions` / `vllm_grammar_v1` 请求按实际聊天模板、安全余量和输出预约判断窗口；服务端 Schema 封装仍计入后台回执及保守累计预约。未知协议/格式/扩展继续保守处理，实际窗口及各项限制保持。

以上源码及配置一起交付。此次不引入数据库迁移、不改公开接口、不启停 21 服务。当前服务和旧 Run 不会因本次 Git 提交自动变化。

## 直接测试与独立核验

生成结构覆盖同材料已映射字段与 unmapped 共存、严格同源包装、明确引用及已知工件依赖；沿 C3→JSON 保存读取→Deep/C6 核最终消息，并将实际装配的观察正文作为前序输入核不回流。检查原件、来源角色、成员范围及有效值保持。直接受影响的既有镜像/后台选择、计量及容量入口测试复用，不开展全仓回归或并发矩阵。

调查核心完成实现，统筹未参与产品修改，另行完成源码审阅及独立生成结构交接核验。统筹从 Git HEAD 导出普通临时目录，只叠加拟提交产品/测试/工具；84 项必要生成结构检查通过，Ruff、diff 格式及 OpenSpec strict 检查通过。[工程证据](../../../docs/operations/evidence/case-input-unmapped-m0f-20261128-01/README.md)记录范围和未验边界。

## 冻结输入的容量入口

`docs/operations/measure_case_input_capacity.py --config <本机配置路径>` 使用同目录的 JSON Schema 校验。必须显式提供固定快照/策略及 SHA、Run 与工件选择、候选 Case profile、既有 tokenizer 的本机转发地址、独立输出目录和 C3/C6 阶段；不静默选最新记录、回落环境或伪造前序成功。

入口按生产构造器生成最终请求，仅向明确配置的 `/tokenize` 地址发送计数请求，不调用生成、不写数据库、不恢复旧 Run。每批独占执行声明，所有请求、异常及实际计量保存为私密文件。SSH 连接由本批受控方式建立并收尾，不由此工具修改全局连接或远端配置。

同冻结材料的另批操作已执行，临时连接已收尾。负责人审阅脱敏后只允许当前统筹会话读取限定统计与校验；原件、消息、真实结果和数据派生核验不纳入 Git。本文件记录实施与验证方式，不复制私密结果或把入口成功等同业务通过。
