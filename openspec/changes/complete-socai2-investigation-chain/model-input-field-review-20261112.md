## 1. 每个模型只承担本环节判断

| 环节 | 为什么需要模型、要完成什么 | 应提供的材料 | 不默认继承 |
| --- | --- | --- | --- |
| A | 解释一条告警的行为、性质和必要待核项 | 当前告警业务事实；相关资产/情报/历史业务结果；有效人工陈述 | 原始对象整包、查询执行台账、全量历史 |
| I | 解释既定事件的整体行为、成员意义和待核项 | 本事件成员业务事实；同材料有效 A 判断及必要依据；相关人工信息 | A 的所有查询参数、所有命中历史；不重新归并成员 |
| C3 | 提出本案解释、证据缺口和必要补查 | 当前材料；有效 A/I；适用人工材料；与问题有关的知识；可用工具的最少业务能力说明 | 数据库对象、全部回执、无关历史与知识 |
| Deep | 回答一个指定问题 | 该问题、已有回答、支持与反证、相关业务记录和知识、可选补查能力 | 因问题范围覆盖全 Case 就复制整个 C3 输入 |
| C6 | 结合本轮调查形成结论、影响、建议和待核项 | 当前必要事实；C3/Deep 的有效分析及其原依据；新增业务结果；相关人工材料和知识 | 各阶段请求、工具目录、执行参数、完整过程台账 |

选择不能只看模型之前引用了什么：当前业务事实、相关反证与相互矛盾的材料仍须保留。前序判断不是独立事实，不能用一段旧总结代替其必要依据。

## 4. 当前行为材料

| 来源字段 | 业务用途与规则 |
| --- | --- |
| `time/start_time/end_time` 等活动时间 | 保留实际活动时间及必要单位，帮助排列行为；不同含义的时间不互相替代 |
| `activity.action/outcome` | 保留行为及对应结果；结果只属于该动作 |
| `actor.user/user/device/src_endpoint/dst_endpoint` 中身份与地址 | 保留谁、在哪台主机、源/目的对象；从业务字段确定角色，不从对象索引猜测 |
| `process.name/cmd_line/file.path/pid/uid` | 有助解释进程行为和关联时保留；命令行不证明命令输出或完成 |
| `parent_process/session` | 有助关联才保留实际标识/属性，不重复整层父对象；不得据共同标识自动断言因果 |
| 端口、协议、流量、文件、邮件、云资源、权限变化 | 按本环节行为提供实际业务字段；`0/false/[]` 若表达真实结果需保留 |
| `class_uid/ocsf_class_uid` | 用于程序解释记录类型；已有业务类型名称时不再重复内部编号 |
| `raw_text/raw_data/ocsf_json/raw_json` | 禁止将这几份同一材料原样并排传入。结构化内容按字段选择，重复值共享展示；字段未覆盖的独立业务内容才进入业务视图 |
| 非结构化描述、命令输出、说明正文 | 按字段用途选择有用的完整内容，保留所选原文；不由程序编造摘要，不为了缩短而截掉反证 |
| 未知业务字段 | 先判断所在结构和任务用途；不能因旧模板没见过就丢弃，也不能以“未知”为由把整个原始对象透传 |
| `detection.rule_name/rule_id/tactics/techniques` | 理解检测含义时作为标签提供一次；与原始观察分开 |
| `confidence_state/score_source/labels_provided/dictionary_version/policy_sha256` | 程序计算、映射和版本信息后台留存；不作为模型业务证据 |
| `source_scope.kind/complete/truncated/received_count/retained_count` | 原材料选取台账后台留存；I 第30行的 `explicit_sources/true/false` 不应单列为业务材料 |
| `enrichment` | 只提供其中实际业务结果；融合会话、旧工件引用、采集过程外壳留后台 |
| `material_state`、读取 `state` | 模型只需知道材料可用/不可用/未知；逐字段 not_provided、原件 ID、投影统计留后台 |

## 5. 查询只给结果

这条规则适用于 A/I/C3/Deep/C6；无需让模型理解工具执行情况。所属告警/问题由业务块标明，程序仍保管完整查询范围并执行引用范围校验。

| 回执字段 | 模型看到什么 | 后台保留什么 |
| --- | --- | --- |
| `tool_name` | 简短业务名称，例如“威胁情报” | 原工具名 |
| `state/outcome` | 未查询／查询失败／结果未知／无结果／有结果 | 原始状态与结果枚举 |
| `rows[].record`、补查返回业务字段 | 按字段选择的业务结果，保留事实原值和角色 | 完整返回及行关联 |
| `reason/statement` | 不提供，也不改写成解释性尾句 | 跳过/失败等原因和原执行说明 |
| `actual_args.scope/window_start/window_end` | 不提供查询时间窗或范围 | 实际执行参数 |
| `selectors/object_keys/source_scope/namespace` | 不提供查询对象清单或来源范围；结果中的真实业务对象另行提供 | 匹配与绑定依据 |
| `limit/returned_rows/truncated/truncation_reasons` | 不逐项提供执行统计；状态不能把未知误判为无结果 | 精确数量、上限和截断信息 |
| `limitations` | 不提供回执限制列表或共享限制段落 | 原限制说明 |
| `other_parameters.selection/priority/eligible_members/paired_query_members` | 不提供 | 查询调度与选择台账 |
| 知识查询 `facets/filters/profile_sha256/candidate_limit/score_threshold` | 不提供 | 检索参数、配置与排序来源 |
| `purpose/purpose_label/use` 查询描述 | 不重复整段检索提示；知识正文按本环节用途选择 | 完整检索主题与用途映射 |
| `elapsed/usage/request_id/retry/trace/schema_version` | 不提供 | 执行与费用记录 |

I 原输入第154行的目标展示为 `[原引用短号] 威胁情报：未查询`。不附加“不能称为无命中”等尾句，不改业务数据，不修改原回执。失败和未知不合并成未查询或无结果；这些区别由程序确定，模型只接收确定好的状态。

## 14. Deep：回答一个指定问题

## 16. 工具返回较多记录时的简单处理

当前已有查询数量、保留字节和完整请求容量限制：A/C2 最多200行，C4普通日志补查最多50行并额外取一行判断是否还有结果；实际取数按冻结主机/时间/类型，不是“最相关50行”。超过保留容量时按完整行留下有限结果及后台截断记录，不声称保留了源端全部数据。模型视图已筛字段、目录历史和可选知识；必要材料仍超限时停止派发，原输入/失败/待核状态可查。当前不增加自动翻页、动态缩窗、日志摘要模型或复杂排序。

本步只补普通补查结果的直接缺口：结构化字段仍逐行重复 `record_key/name/value` 外壳，事件ID等内部身份也进入模型。按已知字段名将纯内部身份留后台，前序明确引用的字段优先保留；业务时间、行为、对象、结果、真实冲突和未知扩展/0/false/有效空列表保持。对于同一冻结查询、同角色/范围、同字段及完全相同的业务值，可以共享一次正文，但逐一列出原记录号和来源号；不同值、不同查询、不同角色不能合并，不把50条记录压成“一次事件”。原回执、逐记录关联及来源映射不改，查询只显示结果，不增加执行限制说明。

直接验证复用已有补查字段检查，增加少量合成记录检查共同字段、差异/反证和原引用恢复；不做压力矩阵。随后复用一条已有正常 C3→Deep补查→C6 的真实隔离库保存/读取检查，模型及外部工具明确使用替身；它只验证程序接线和存取，不核销真实模型质量。固定流程/真实结论缺口继续保留，HTTP及数据库表合同不变。
