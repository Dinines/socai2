## 当前目标与边界

负责人先要求完成整个调查模块的功能与测试规划，该规划及88项功能矩阵已形成；2026-11-27进一步明确测试案件更新和多轮执行，要求调查核心配合构造多元告警并包含ATT&CK标签，可复用此前本地mock作为补充。当前进入下述“两轮更新测试”阶段，先核模板及当前合同，再准备独立私密数据包，逐步通过后进入正常Kafka、存取和真实调查。此前冻结OCSF组、已完成源标签批次与旧失败保持。当前授权不自动包含新的生产代码发布、Git或扩展其他调查功能；必要普通来源/查询配置随本步核对。数据准备通过不代表真实调查质量通过。

示例以一条主机异常行为主线为核心，最多涉及两台逻辑主机和必要账号角色，包含认证、进程及父子关系、文件变化、持久化线索和网络访问；补足事前正常使用/运维、行为发生时、事后可观测结果。保留一组不应因时间接近就被关联的正常对照。调查核心先按现有OCSF类别、解析与查询能力确认具体类别，不能猜class_uid或把各类活动都伪装成告警。初步规模限制为少量告警和十余条活动，数量以覆盖直接功能为准，不扩成压力数据集。

## 实施步骤与必要验证

1. **先完成全部功能与数据规划，再审本场景和现有能力。** 以总规划的逐项矩阵确认本包能覆盖的功能，以及人工任务、后轮/采用、探索、报告等还需要哪些正常流程状态。调查核心给出行为角色/相对时序、支持的OCSF类和字段、告警与活动分工、实体关系、可查询证据及预期业务效果。列明实际映射或查询缺口，不通过篡改场景或新生产分支掩盖。逻辑上可关联的事件组不直接写入生产关联表；实际自动归并数按现有合同验证。
2. **再构造一个独立私密数据包。** 使用独立批次和确定性生成方式，冻结全部UID、时间及输入哈希。建议分为告警JSONL、活动JSONL、原生资产种子、独立预期文件和清单；最终名称由模块回执确认。source/connector_type沿lyc中性前缀，主机、账号和业务观察不使用该前缀。只写惰性的合成日志/命令字符串，不在主机上执行这些行为。
3. **直接离线验证并独立复核。** 复用已有OCSF校验、入湖投影、接收选择及材料组装入口，核告警/活动各走正确路径、全局UID唯一、主体与时间关联、父子进程/文件/网络关系可追溯、关键上下文没有在投影时丢失、原始记录保持。按现有工具合同确认后续查询键；不能把离线匹配推演写成真实数据库查询通过。统筹独立核对应关系和预期边界，不重跑全仓或多模型测试。
4. **按总功能矩阵记录本包直接覆盖证据。** 将告警分诊、事件归并/诊断、材料/对象/资产查询、Case调查和调查执行分别对应到已存在接口和本数据中的证据角色。标明每项正常输入、保存/读取关系和可见结果；当前未实现的接口、工具或映射保持缺口，不用构造已成功回执代替执行。不能以本场景的少量告警/活动代替全部88项功能的数据准备。

## 预期与证据规则

- 检测源战术标签、AI推断和独立场景预期分开保存。检测标签不是攻击成功证明；预期判断/答案不进入发布数据、模型提示或可查询的业务材料。
- 有直接证据才预期明确结论，只有企图/命令记录时不宣称已造成影响；缺少动作结果则保留待核事项。正常运维对照不能仅因工具名称或战术标签被预设为恶意。
- 前序结果按实际主体/材料/Run引用，不能预造后端分诊、事件诊断、Case结论或执行回执。后续调查指令必须区分建议、已提交、实际执行及结果，不在本数据准备中触发真实响应动作。
- 当前已确认A提示、映射证据Schema/接收角色不一致，以及事件仅汇总检测源标签的设计边界保持记录；新场景不能绕开这些缺口宣称AI标签已修复。
- 业务字段值、正文与完整样例留 `.local` 受控文件。Codex交接只输出结构、角色、字段名、工程布尔和哈希；公开记录不放身份键字典或原始行。完整真实样例外传按AGENTS另行处理。

## 2026-11-27 两轮案件更新测试

### 业务目标与当前落点

沿总规划P2/P4及 `PKG_HOST_CANDIDATE`、`PKG_RESULT_EVOLUTION`，用一个独立主机上下文Case验证首轮与一次有实际新成员的后轮。告警应覆盖可解释的不同认证、进程和网络行为，并由标准检测字段提供非空ATT&CK源标签。后轮应能读到新材料，冻结比较基线指向实际首轮，旧Run/Result及原答不随当前范围变化；8181可读取前后轮与当前采用，4177可回查实际输入、查询及模型交付。

当前M0a的I输入审计已完成，数据准备结果与尚待实施的最小缺口见下节。实际已准备4条告警分成两段，配套11条独立活动和少量正常背景，不凑类别或扩大压力规模。先核清本环节需要哪些信息、为何需要和如何表达，再决定最小修正。首段与追加段已在生成时冻结，但追加段必须在首轮结束后才发布，首轮查询不得提前看到后轮输入。

### 数据与源标签要求

- 只复用明确合成且可追溯的旧mock行为模板；按现行OCSF、材料与查询合同重新生成独立UID/批次/时间。旧原组与旧输出不改写，不直接导入预制模型结论、Result或成功回执。
- 告警用 `finding_info.attacks[].tactic.uid/name` 提供源战术，技术字段按现有合同和真实语义映射。主场景需有非空标签且不止一种行为/战术；标签与原观察分别保留。AI是否识别标签独立验收，不以检测标签冒充模型已证实攻击。
- 告警、独立活动、原生资产种子、独立预期和发布清单分开。预期、答案、模板控制身份及后台来源不进入模型业务输入。业务观察和原答仅留受控文件，公开证据只包含结构与工程核对结果。
- 新包不携带 `synthetic_page_data` 测试标记，不靠测试来源或页面字段提升证据角色。认证/session、文件/持久化及查询scope等已知缺口逐项核当前能力；不加legacy字段或生产特判使样例通过。真实通用阻断另收一个小步修正，未覆盖能力如实登记。

### M0a 先审I输入用途，再确定简单合并

负责人进一步要求：先解释哪些信息必要、有用，以及用什么方式提供模型，再做多告警共同信息的简单压缩。本步明确收敛为一个事件多告警的I最终messages审计，复用[既有字段用途与I标准](model-input-field-review-20261112.md#11-i按事件诊断整理成员和历史)。C3仅核已有共同对象能力，不扩展到全部A/I/Case实施。

I的任务是解释既定事件的整体行为、各成员的意义和必要待核事项，供事件诊断展示及后续Case使用。成员选择、身份归并、状态/数量/时间计算和查询执行由程序承担，不让模型重做。审计逐项记录：实际可见字段、判断用途、必要/条件/后台分类、当前表达、来源及适用成员。覆盖事件范围与关联依据、共同主机/资产、逐条行为/时间/结果、检测标签、有效A及人工原文、相关查询业务结果与缺失状态。

调查核心交现状与缺口、推荐输入结构及最小修正；统筹独立核实际最终渲染、引用和原件边界。复用已有多告警事件冻结输入与本批结构，完整正文只留私密目录，公开只记录字段/角色/工程结果。不新增真实模型、数据库写入或压力矩阵；本步先交审计，不以压缩率代替信息完整与判断质量，也不把建议记成已实现。审计结束后再确定是否实施下列候选规则。

规则范围限于当前模型业务视图：

1. 同一稳定对象、同角色及相同业务字段值，只展示一份公共主机/资产信息，用已有对象或来源别名列明适用告警；不同来源身份只留后台映射，模型可按别名区分，不能用同名就推断为同一对象。
2. 每条告警的发生时间、行为、结果、差异字段与来源关联仍独立保留。两次相同行为不合并成一次，冲突值不取最后一条覆盖。共享信息仅减少重复表达，不增加攻击因果或判断。
3. 已核实的`$.raw_json.field_metadata.lake_ingress`后台来源/租户信息应从已识别RawAlert显示路径移出模型提示，保留原件、对象关联及引用恢复；后台data中已不进入messages的namespace不算泄漏。按字段路径和结构处理，不按lyc或本批字符串删改，不全局删除同名字段，不做自由文本改写。
4. 复用现有`case_input_text`对象别名与同源分组、`case_input_hierarchy`共同值/事实去重等能力；I与Case各自保持阶段目标和作用域。已有规则足够的部分只核实，不为“压缩”重新包装整包数据。

必要验证只覆盖本批冻结包及受影响正常例：公共信息只出现一次且引用成员齐全；差异/冲突与重复行为仍可区分；source/tenant未进最终messages；旧原件与保存/读取合同不变。沿已有直接测试补最少缺项，用同包前后字节或重复项数验证变化，不追加模型采样或复杂压力矩阵，也不以体积降低认定业务质量通过。候选通过独审后才安排必要运行更新，再返回M1/M2。
