# 五字段任务指令对照：v2 不采用

2026-11-08，用户要求优化五字段指令并继续。独立批次 `alert-prompt-comparison-20261108-01` 已完成24次调用、24份原答、46,676已报告tokens，0重试。两组均通过Schema和现有核心解析，但候选新增事实错误、确定性判断减少，耗时上升；**不采用本次v2，不切换生产**。五字段方向仍可继续，原五字段本身也未通过整体语义质量验收。

## 比较方法

- 原9份材料冻结：3个已有告警各2轮，6个合成例各1轮，两组各12次。
- control完整复用原五字段请求，candidate仅替换system正文；用户正文、输出Schema、证据映射、解析器、模型路由、temperature=0、输出3000及300秒时限保持。
- 两组均为新调用，交替先后顺序。原36调用批次已结束，没有重派、覆盖或修改原件；83份旧证据文件指纹保持。
- 前后运行配置/模型路由保持，0业务Run、0业务库写入。配置与候选来自 `tools/testdata/alert_prompt_eval`，资料展示与生产调查分开。

“新增/退化”相对于原五字段对照；A2动作扩大、S3厂商归属混淆在早先八字段也出现过，不能称为整个系统首次出现。S3作者误报/良性分类口径、S6时间与计划未对齐仍是原材料限制，不因转待复核就判定新版错或对。

按已确认口径，转待复核不计良恶方向误判；本批不能报告准确率。S5失去明确恶意识别及多处正文矛盾说明新稿不适合替换，格式通过不证明判断有据。

## 原因与后续

已能确定本次只有system正文变化，不能把退化归因于输入删减或Schema变化。模型多次把人工确认当成必需条件；抽象动作边界也未守住进程启动语义。具体是哪一句造成这些行为尚未通过单句实验确认。

用户随后要求参考OpenAI/Claude官方实践，从原文改善结构。已形成[保留原意的整理说明与v3候选](alert-prompt-restructure-20261108.md)，该候选尚未调用模型；不把v2的测试当成v3的结果。后续应保留关键字段语义、分离判定依据和待核建议，并用新样例验证，不反复试探已结束批次。
