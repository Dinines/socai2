Q15 运行路由已有参数透传和原响应返回。候选只同步该操作的单项声明、响应组件和生成类型，以正式已存 Schema 对照，保留平台登录、转发权限及其他操作声明。正式平台当前声明和 8181 实际 GET 均有读回证据。

本次查询由正式服务在同租户、同来源的已保存告警及双方当前材料对象上取三类匹配的并集，排除起点。页面显示服务端的实际窗口、不可用规则及匹配依据。游标取 `next_cursor` 原样续页，累计候选按 `alert.id` 去重，匹配数使用正式 `total`。结果的名称、等级、发生时间、处理状态和当前判定从 `items[].alert` 读取。对象对及共同战术从 `matches` 读取，起点和候选原件各用其自身的 `alert_id`、`material_id` 链接到原始记录。同案或事件成员按服务器返回的身份回查。

F03-05 已确认的三规则合并检索、实际时间范围、原件回查及人工复核可沿 E70 完成。旧 UI 继承的单规则和任意共有对象选项保留为暂不可选，并给出接口限制。若后续要求这些选项可用，需要全量候选查询接受规则条件（例如 `rules`）并让 `total`、分页游标及游标指纹对所选规则生效。任意共有对象还需单独定义可匹配对象和来源范围。当前已载入页的过滤不能提供这些语义。Case 候选保留各自客户端和筛选行为。

## 后续告警步骤与验收

| 步骤 | 输入、处理、保存及读取 | 直接验收及依赖 |
| --- | --- | --- |
| 原始数据无富化 | 告警 ID 和材料版本 → 读取已保存材料的富化字段 → 由实际响应决定入口。 | 用已有无富化正例核 OCSF 可读且入口隐藏。已有有富化读回作参照。 |
| 相关告警有值 | 当前材料对象 → 服务按同来源/类型/对象键查询已存对象索引 → `records/related_alerts` 读回真实同对象告警。 | 由后端提供共享对象正例，核表格和同 ID 跳转。E71 另按同主机合同核。 |
| 独立评论 | 告警 ID、正文和操作者 → 服务验证并持久化告警评论/活动 → 同告警独立读回。 | 先核正式写入和读取合同，再用隔离或已授权数据核单独评论保存、刷新及活动。随分配的评论是另一项回执。 |
| 历史材料和来源 | 告警 ID 和历史材料版本 → 查已保存版本及其来源 → 页面按所选版本读取原件/来源。 | 需要版本目录与版本来源合同，核当前和历史两版不串读；已有指定版本原件读回复用。 |
| 源 UID 独立查 OCSF | 源 UID 与来源范围 → 调查服务定位已保存湖记录和版本 → 返回 OCSF 原件。 | 需服务端给出 UID 查询及版本口径，核 UID 命中、无记录及同源。现有材料 URL 已验的是版本链接。 |
| 告警详情关联读取 | 告警 ID、当前分诊的 `source_run_id` 或关联主体 ID → 服务读取已存 Run、步骤/工件、来源与结果 → 页面读取指定版本并回链。 | 沿已有分诊和关系样本核深链、刷新、原件归属、响应建议和回执状态。使用必要的正式 GET 转发；跨主体关联查询和审批回执各凭实际合同验证。 |
