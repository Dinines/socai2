# 告警分诊 ATT&CK 映射

本步使单条告警在检测方缺少标签时仍可从本轮有依据的行为分析获得 ATT&CK 映射。用现有 A 分诊调用、冻结材料和已有查询业务视图。检测标签作为来源标注，行为证据可来自本轮材料或查询。事件诊断、Case、入站检测映射、风险等级和处置流程在本步范围之外。

## 输出和采用

- 新分诊 Schema 额外要求 `attck_mappings` 数组。项含 `tactic_id`、`technique_id` 和本轮 `evidence_ids`。两个 ID 至少有一个，均有时须符合词表的对应关系。缺少足够证据用 `[]`。待核事项沿用 `recommendations`。
- 只做一次已有证据别名解析。采用可解析到本轮观察或人工陈述的映射，用固定版本的 MITRE ATT&CK Enterprise 词表核 ID、关联和显示名称。逐项记录引用/结构不合格以及缺失；本单元的缺失或无效独立于原分诊判定、发布和升级决定。引用有效只证明能追溯，语义正确性另行验证。
- 有效映射和词表版本写入同一次分诊的解释工件，保存可读回的证据引用。列表和详情的 `triage.attck_mappings` 返回最新已发布分诊同一轮的映射。明确无映射返回空数组，旧记录缺该字段或无可用映射单元返回空值。`derived.tactics` 表达检测材料的标签。前端用已保存的 AI 战术优先、检测标签兜底，自行展示名称和来源标记。

## 本地验证与交付

先按现有 OpenSpec 变更校验设计。用本地合成 `lyc` 告警覆盖结构化输出、同一材料和 Run 的保存、列表及同 ID 详情。核有行为证据而检测未给标签、明确空数组、无效 ID/引用、旧结果及失效分诊。用模型替身核输出接线，用隔离 PostgreSQL 和现有 HTTP 核存取。对照原五字段判定和升级决定的直接用例。通过后只提交并推送本步。真实模型语义质量与正式服务采用另按实际证据记录。

本地验证通过 34 项分诊输入、Schema、引用及提供方约束检查，以及两项隔离 PostgreSQL 验收。第一项核模型替身、有标签与空标签、坏引用和 ID 的局部拒收、旧结果、材料更新后失效，以及同 ID 列表和详情与解释工件一致。第二项核坏映射时原有未升级决定仍按原规则写入。首次回归发现新数组被旧接收器计为未知段，调整为同次解析后独立验收，再复验通过。

校验使用随服务分发的 MITRE ATT&CK Enterprise v17.1 元数据。来源、原始包摘要和许可随词表保存。

## 合成类别样本复验

本轮生成独立的 `lyc` 合成告警，覆盖有行为证据且无检测标签、有行为证据且检测标签不同、只有检测标注的空映射。按当前随包 ATT&CK Enterprise v17.1 词表预先登记预期战术和技术。预期单独保存，模型请求只使用告警事实和既有业务视图。

先在独立本机 PostgreSQL 保持同一告警材料，沿已有 A、管理 PATCH、列表和详情验证两轮完成后的状态变化。分别核每轮 `freshness`、Run 状态、冻结工件及同材料前序分析可用性。再按当前运行配置检查项目内网模型路由，以同一模型和既有 A 请求合同验证新样本，逐条记录预期命中、空映射、引用校验和同 ID 列表、详情的 HTTP 合同读回。输入、实际请求和原答留在本机受控批次内。样本命中只作为该批结果。

本机两轮对照通过。首次改变 `handling_status` 使原先的 A 快照判旧。经受控入口在同一材料上冻结第二轮，再把告警恢复至第一轮的状态，第一轮读为 `current`，第二轮读为 `stale`。两个 Run 始终 `completed`，材料和冻结工件一致。事件输入的 `change_view` 一致，Case 同材料配对继续可用。该对照使用模型替身。

五条新样本经同一项目内网真实模型运行 A，在隔离 PostgreSQL 保存，列表和同 ID 详情均与各自的解释工件一致。无行为证据的对照按预期返回空数组。四条正例的活动证据均进入模型请求，三条原答为空数组，一条映射因证据引用不可用未被采用。四条均未命中预设的战术及技术。检测标签读回沿原值。模型语义验收仍未通过。

### 告警快照的创建条件

告警分诊的 `input_snapshot` 在 Run 开始时冻结。现行流程有两种创建情况。

1. 新告警首次自动分诊实际启动 Run，为该轮创建一份快照。
2. 分诊任务的已知故障满足调度重试条件，且重试实际启动新的 Run，为新一轮创建一份快照。[分诊调度范围](../schedule-streaming-investigation-updates/proposal.md)

同一操作键始终读取对应的 Run 和快照。处理状态、负责人、管理标签、人工判定及当前材料指针各自独立保存。公开读取依据每轮冻结的告警字段、该轮材料及其对象、人工反馈与当前对应输入计算 `freshness`。输入有差异时，该轮读为 `stale`。分诊及解释产物的指针、行版本和更新时间排除在比较之外，发布 AI ATT&CK 映射本身不会触发判旧。

独立快照对照的九项检查通过。首次执行保存一轮一份快照及可读映射。改处理状态、负责人、管理标签和人工判定逐项保存成功，原 Run、材料和快照全文及摘要保持一致。四项编辑后沿原操作键重发，仍返回原 Run 和快照，模型替身的调用数保持一次。受控执行入口启动第二个 Run 时，只为第二轮新增一份快照。隔离夹具换用第二版材料后，公开分诊从 `current` 读为 `stale`，两轮已保存的快照、Run 和旧材料保持一致。重试条件沿调度代码核对，第二轮直接验证共用的建 Run 与冻结入口。

本机批次 `attck-corpus-20261123-01` 保留输入、预期标签、模型原答及 `state-result.json`、`snapshot-result.json`、`model-result.json`。本机调查工作台静态副本新增七个告警主体和九个 A Run，原有 71 条登记均通过保留核对。

## 最新分诊与人工判定的展示

负责人确认，同一告警只展示最近一轮已发布的 AI 结论和该轮 ATT&CK。负责人变更、人工四选一及其他令快照判旧的变化发生后，列表、预览和概况继续显示已保存的 AI 判定。列表的 ATT&CK 类别和概况的战术、技术均取同一轮分诊。人工判定读 `feedback` 的判定、理由与记录人。只有告警行判定的旧数据沿已有已保存判定展示。
