# 告警分诊 ATT&CK 映射

本步使单条告警在检测方缺少标签时仍可从本轮有依据的行为分析获得 ATT&CK 映射。用现有 A 分诊调用、冻结材料和已有查询业务视图。检测标签作为来源标注，行为证据可来自本轮材料或查询。事件诊断、Case、入站检测映射、风险等级和处置流程在本步范围之外。

## 输出和采用

- 新分诊 Schema 额外要求 `attck_mappings` 数组。项含 `tactic_id`、`technique_id` 和本轮 `evidence_ids`。两个 ID 至少有一个，均有时须符合词表的对应关系。缺少足够证据用 `[]`。待核事项沿用 `recommendations`。
- 只做一次已有证据别名解析。采用可解析到本轮观察或人工陈述的映射，用固定版本的 MITRE ATT&CK Enterprise 词表核 ID、关联和显示名称。逐项记录引用/结构不合格以及缺失；本单元的缺失或无效独立于原分诊判定、发布和升级决定。引用有效只证明能追溯，语义正确性另行验证。
- 有效映射和词表版本写入同一次分诊的解释工件，保存可读回的证据引用。列表和详情增加 `triage.attck_mappings`，仅返回与有效的当前分诊匹配的映射。明确无映射返回空数组，旧记录、失效分诊或无可用映射单元返回空值。`derived.tactics` 表达检测材料的标签。前端用有效 AI 战术优先、检测标签兜底，自行决定展示名称和来源标记。

## 本地验证与交付

先按现有 OpenSpec 变更校验设计。用本地合成 `lyc` 告警覆盖结构化输出、同一材料和 Run 的保存、列表及同 ID 详情。核有行为证据而检测未给标签、明确空数组、无效 ID/引用、旧结果及失效分诊。用模型替身核输出接线，用隔离 PostgreSQL 和现有 HTTP 核存取。对照原五字段判定和升级决定的直接用例。通过后只提交并推送本步。真实模型语义质量与正式服务采用另按实际证据记录。

本地验证通过 34 项分诊输入、Schema、引用及提供方约束检查，以及两项隔离 PostgreSQL 验收。第一项核模型替身、有标签与空标签、坏引用和 ID 的局部拒收、旧结果、材料更新后失效，以及同 ID 列表和详情与解释工件一致。第二项核坏映射时原有未升级决定仍按原规则写入。首次回归发现新数组被旧接收器计为未知段，调整为同次解析后独立验收，再复验通过。

校验使用随服务分发的 MITRE ATT&CK Enterprise v17.1 元数据。来源、原始包摘要和许可随词表保存。HTTP 接线已通过本地验证，正式运行和真实模型标签质量待独立验收。

## 最新分诊与人工判定的展示

负责人确认，同一告警只展示最近一轮已发布的 AI 结论和该轮 ATT&CK。负责人变更、人工四选一及其他令快照判旧的变化发生后，列表、预览和概况继续显示已保存的 AI 判定。列表的 ATT&CK 类别和概况的战术、技术均取同一轮分诊。人工判定读 `feedback` 的判定、理由与记录人。只有告警行判定的旧数据沿已有已保存判定展示。

本步范围限告警读回和对应页面。列表和详情沿 `latest_triage_id` 读取最新已发布评价，并在该告警的同一已完成 Run 读取解释中的已校验映射。`freshness` 及 `valid_for_current_input` 继续表示快照比较和采用资格。页面展示已有评价时直接使用 `triage` 及其映射，人工操作、快照冻结、评级、事件及 Case 下游继续按各自既有合同工作。兼容旧评价缺映射字段、显式空数组、无结论以及后续执行等候或失败。字段名、类型、空值和路由沿现有接口。

先验证规格，再用新的合成告警和模型替身走分诊保存与隔离 PostgreSQL。用实际管理和人工判定 HTTP 写入验证改派及四个选择，核每次 `feedback` 变化以及同 ID 列表、详情、分析目录中的 AI 判定、映射、Run 和材料来源一致。再对照切换材料后的读回、实际发布第二轮后的最新指针、较新执行未产出结果时的读回、空映射和旧评价。页面沿同一字段分别显示 AI 与人工结果，定向核标记判旧后列表、预览、概况和同轮技术显示。以 A 的存取和页面联验回执记录本步结果。

本机批次 `attck-display-20261123-01` 通过现有映射正例、明示空数组、旧评价、无效单元的执行器回归和九项直接读回核验。改派及四种人工判定实际写入，AI 结论、标签、冻结快照和 Run 关联保持一致。夹具更换材料后仍可读旧轮结论及映射，第二轮发布后列表、详情和目录一致切到第二轮，较新在途及失败尝试均继续展示第二轮。8181 对应告警源码的 14 项页面测试及 TypeScript 通过。此次候选验证使用新合成告警和模型替身。
