# 调查链设计

## Context

当前服务端交付为 A/I/Case 的输入、执行、保存与读取，最近已核验的发布为 21 r6。Case 来源范围、Finding 角色生成及有限纠正已交付；真实知识使用、正常 HTTP 写操作与自动消费仍按任务推进。模型正文质量仍未通过，读取通过不能替代质量结论。

结构为 29 表、462 列；当前合同与配置从[前后端交接](../../../FRONTEND_BACKEND_HANDOFF.md)、[执行账本](../../../docs/investigation/current-execution-ledger.md)、[模型输入输出](../../../docs/investigation/model-input-output-current-20261109.md)查阅。发布及本机转发事实以 [PROGRESS](../../../PROGRESS.md)最近核验记录为准；已完成审计及本次程序交付共同作为后续依据。

## Goals / Non-Goals

- 每个已收到的业务字段可追踪到冻结材料、阶段输入、输出、保存关系及读取出口。
- 沿 A/I/C/H 的实际职责完成正常业务闭环，保留身份、来源、范围和失败；Q 执行与更多平台功能继续后置。
- 功能优先，只补直接受影响的验证；不新增通用语义评判平台、复杂测试或可用性体系。

### 冻结、并发和人工反馈

同案领取与冻结在事务内完成。尚未领取的 pending 可合并范围变化；已领取 Run 保持原输入，active/unknown 占槽时不能启动第二轮。后续 pending 不自动接续。结果基于冻结输入保存，只有满足范围、输入新鲜度和当前判断保护条件才采用，历史结果不回算。

显式事件关联与成员集合分别保存；成员移动保留两案历史来源与冻结 Run。source_namespace 表示数据身份命名空间，不能代替业务环境事实。实际关联、指针和历史身份以字段字典及现有事务实现为准。

H 保存不自动创建 Run、采用结论或解决 Case。只有已完成、非空、范围合法且仍适用于本轮成员的版本作为 human_statement；范围不适用时保留原件及限制。用户显式 prepare 后再启动调查，领取时冻结所选 H 版本。人工反馈的正常 HTTP 闭环与真实影响继续在 3.7/3.16 验证。

### 数据与页面交接

[数据交接](../../../docs/investigation/socai2-page-data-handoff-20261106.md)、[字段字典](../../../docs/design/socai2-field-dictionary-20261103.md)和 [OpenAPI](../../../docs/design/socai2-independent-api-v2.openapi.json)是字段、关系及读取合同入口。本地整理不修改它们或迁移脚本。

执行状态、交付完整性、待复核、业务判定、当前采用和模型质量分别表达。GET 只读取实际保存内容；未查、失败、查空和未记录分别显示，未知用量不补零。4177 提供真实步骤的提示词、输入、输出、错误与原件，不能代替产品页面或正常写操作验收。

配置由明确 profile 提供，调用容量和时限以当前实际加载策略为准，历史批次数字不成为新的默认值。必要读写接线随功能处理，不另设权限专项前置；告警交接字段确需改变先列影响，数据库设计依项目规则确认。

### 按环节目标设计模型调用的共同原则

<a id="12-18按环节目标设计模型调用的共同原则2026-11-08"></a>

1. **先明确功能目标和调用预期。** 每一步说明要回答的问题、模型必须作出的判断，以及该判断供哪个后续环节使用。程序计算或已知信息不另设模型调用；没有明确业务产物的调用不加入流程。
2. **确定输入形式。** 任务指令、业务材料、来源角色/编号和输出要求分开。稳定结构可以转换成业务文本，枚举/工具选项等适合结构化的部分保持结构化，不为统一格式强制全JSON或全自然语言。
3. **按业务含义选择必要材料，再做通用模板转换。** 先理解字段含义、单位、对象、时间和来源；模板按结构路径配置，不按样例名称、主机或厂商值筛选。空字符串/null可按字段规则省略；0、false、表示“查询完成但无结果”的空列表以及未知非空业务字段不能视作无用。未知类型保留原值/来源的回退形式。已有分析、人工正文和描述原文不经程序语义改写。
4. **复杂任务按可交付子问题拆分。** 每次只做当前需要的判断；明确子问题范围、依赖、停止条件及由谁汇总。拆分不是为每个字段多调用一次；后续携带相关原始依据、有效前序结论、限制和新增材料，不把上一轮结论当事实，也不假设独立请求自动记得前轮。事实有矛盾时回到原始依据，不能只传越来越短的总结。
5. **要求明确结论，并确定输出内容。** 输出必须回答本环节的问题，不能只给背景、复述材料或一段通用建议。工具决策应明确查/不查、所选工具和要补的证据；告警给明确分诊判定及依据；事件给整体解释和待核事项；Case按初步判断、单问题答案、最终案件结论分别定义。明确不等于强行确定性：证据不足须明确当前无法确认什么、为何不足、缺什么。再据此确定字段、类型、枚举、引用及缺值规则，不以固定“五字段”套所有模块。
6. **程序掌握事实和执行，模型负责需要推理的部分。** ID、冻结版本、成员目录、执行时间、查询状态/行数、系统评分及关联由程序管理。模型只选本轮短编号和业务范围，程序映射回原件；程序不能替模型编理由、授权事实或“已分析”状态。
7. **来源、范围和不确定性随内容传递。** 原始观察、检测标签、历史分析、人工陈述与执行回执不可互相替代；同一日志的多个字段不是多份独立证据。引用有效不等于主张为真，跨成员发现保留其原范围；活动成功只说明相应action，查空不证明安全，前序失败不代表原始材料不存在。
8. **优化模型边界，保持业务数据和读取合同。** 输入投影不删除DB原件；输出适配回既有字段/引用/报告/图谱所需结构，不靠填空或复制旧结论凑兼容。分别保存原件、实际请求、模型原答、校验和装配结果，能核查每次变化来自哪一步。
9. **校验和纠正分层，保留真实结果。** 分开检查格式、编号/归属、业务依据与语义质量；已确认可纠正的引用问题给具体原因和一次有界纠正，保留原答及新增调用，不能以降门槛修好数字。局部错误按依赖排除并保留独立有效部分；执行成功、交付完整、待核、事实质量及当前采用状态分别表示。并非所有模块已实现所有纠正路径，实施须逐项验证。
10. **同时验证必要信息、质量和消耗。** 同材料对照分别测输入变化与输出合同变化；若用历史参照，写明时间、查询、前序等差异。检查关键事实/0/false/非空描述/未知类型/冲突是否保留，记录判定与引用变化、输出截断、拒收/待核、输入输出tokens和耗时。字节减少不等于tokens减少，更不保证准确或提速；没有独立真值不报准确率。
11. **配置与实际版本可核对。** 模板、字段映射、提示、工具说明、输出合同、容量和超时通过配置及版本管理进入部署来源；按实际完整请求容量规划，并给最终阶段保留资源。验证执行进程真正加载的配置，不仅看文件已上传；测试页展示真实请求和真实结果。

下一项沿既有 `knowledge` 来源接通一份适用的非空知识：先核现有知识记录、检索条件及来源，选一个具体调查问题，确认检索→本轮输入→引用如何影响补查或解释。优先使用已有真实可检索知识；若只有测试材料，必须明确测试用途，不能把知识当本案观察或业务授权。无合适源时记录缺源，不伪造实际使用。

### 每项功能的交付方式

1. 先写清用户能完成的操作、输入、预期结果和沿用字段，只设计本功能必需的内容。
2. 本地实现后仅运行直接受影响的既有检查及必要反例，再走一条代表性正常路径；同一条实际流程复用为数据库、模型、保存与读取证据，不分开重复跑同义流程。不设测试数量或覆盖率目标，不以多模型/多轮比较作为前置。
3. 达到本功能验收即停止加测。具体失败先定位、修复，再定向复验；新 Run 保留原失败。只测到 HTTP 成功、或未经过修改环节，不能算业务完成；缺证据只补该处。影响本次目标的问题修到位，无关问题登记后置。
4. 保存这条路径输入/输出和关键读回，更新受影响交接及原有 4177 工具；不复查全表列、全部 API/页面或构建新验证框架。仅文档规划做 OpenSpec/链接检查，不触发模型、数据库或服务测试。
5. 每个 change 实施后保留一次限定于该变更的独立结束审计，复用已有全面审查结论；随后统一发布获准服务，核实际版本/配置和本功能读回，补回执后归档并一次推送子仓库/父项目。发布不默认附加一轮同义模型重测。

当前不开展冗余可用性开发、压力/故障/恢复矩阵或新测试平台，已有保护保留，只有本次修改实际触及或正常流程被具体故障阻断才定向检查。规划不恢复消费者、不扩大额度；未验范围和质量结论继续如实保留。

## Risks / Trade-offs

程序校验接受、有效保存和模型正文质量分别判断；不能通过改写原答、补造授权或把查空当安全来收口。历史失败、unknown 和原始引用保留；没有独立真值不报告准确率。当前手动链、实际知识消费和自动处理各自有未验范围，按原任务继续跟踪。
