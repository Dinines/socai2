## 1. 目标与已确认决定

阶段一解决[原评审](../../../docs/investigation/investigation-current-review-20261114.md)RV01的结论/质量存取衔接、RV02的C3完整交付、RV04的补查能力匹配和RV12的结论展示，并补齐整个模块的输入输出留存。引用准确性及正文质量改进归[六阶段规划](../../../docs/investigation/investigation-implementation-plan-20261114.md)阶段六，不以反复采样追求通过。流式调度、自动建Case、自动建人工任务及响应操作不在本阶段。

| 决定 | 实施目标 |
| --- | --- |
| C3正常输出 | 一次回答七部分；输出上限8192；最多5个核心发现，不要求填满 |
| 回答截断或缺项 | 可可靠识别完整字段时保留这些字段，最多一次只补未完成/缺失字段；不常态拆成七次调用 |
| 补答上下文 | 程序显式重带同Run冻结的模型业务输入和必要已完成分析；当前接口没有服务端会话续接 |
| 引用与结论 | 保留原结论、原业务判定和正文，引用问题独立记录；不因错配、漏引或空引用删除、降级或整份拒收 |
| 确定性去重 | 同一引用列表内相同编号保留首次和原顺序；原答、处理前后值均保留，不跨主张或改写正文 |
| 补查 | 有实际来源则查询；已有材料需进一步分析可用Deep；取不到的材料记录待补，已有结论保留 |
| 输入输出 | 实际取得的原件优先完整保存，保留模块输入、实际请求、原始返回、程序处理和最终输出；超限存取随本阶段处理 |
| 展示与采用 | 原结论、运行、交付完整性、引用质量、材料缺口和当前采用分别展示；既有采用流程及新鲜度/人工选择保护保持 |

这些决定适用于新版本执行。旧原答、拒收、unknown、采用事实和质量NOT_PASSED不回写，不为补记录重派旧Run。告警前后端字段的名字、类型、枚举、含义及关联保持；本设计不授权改动冻结告警合同。

## 3. C3业务输出与配置

C3根据本Run已冻结成员事实、适用H、必要前序和知识形成初步解释及补查需求，供C4和C6使用。程序已能确定的身份、实际查询状态、数量及coverage仍由程序装配；输入沿用既有业务视图，不因扩大输出额度增加无关材料。

| 顶层字段 | 业务职责与数量合同 |
| --- | --- |
| summary | 本案初步解释，保持模型原文 |
| members | 每个固定成员恰好一项，原分析状态/摘要/限制保留；不受5发现上限替代 |
| findings | 最多5个有价值的核心发现，可少于5或为空；observed正文仍由程序依实际来源装配 |
| questions | 固定五个业务问题各一项；程序另补既有第六问coverage |
| domains | identity/cloud/phishing/insider四项，保持领域关注与发现原范围的区别 |
| conflicts | 可为空；不为完整性编出矛盾，既有数量边界保持 |
| followups | 可为空，最多2项；目标、成员、方式、所需材料、优先级及绑定保持既有合同 |

C3发现上限由Case输入profile的单一配置值生成提示和Schema，并用于接收，实施时删除提示中的固定3及隐含24口径；不直接改共享类型使Deep/C6跟着变5。输出上限来自运行策略C3=8192，补答同样使用C3上限，不要求生成8192tokens。完整答复若超过5个发现，记录结构数量问题及原答，不静默删成5个，不为此增加引用纠错或额外全量重答。

正常调用与补答共用原Run的6次模型、4次工具、131072累计tokens及现有时限，C6预留保持。每次派发前用实际后端tokenizer计完整请求、Schema、协议包络、安全余量和输出预约，再核次数、总tokens、剩余时间；补答不是免费调用，不另建Run、不自动加额度。分段补答上限通过版本化profile配置为1，C3模型边界版本、解析/合并版本和配置指纹随Run冻结。部署核对实际加载profile属于后续交付。

## 4. 接收、引用诊断与结论流转

### 4.1 分开判断的问题

| 检查类别 | 处理 |
| --- | --- |
| 实际调用与存储 | 无回复、协议失败、用量未知、未知执行、真实保存失败按原事实收口，不能标成完整交付 |
| 结构与主体 | 字段、类型、成员身份、定义ID唯一性及数量边界按本轮合同检查；C3可恢复缺项按第5节，主体歧义不猜测 |
| 引用与范围诊断 | 重复、未知编号、错配、空引用、角色不适用、发现声明范围与实际依据不匹配分别记录，不据此改模型业务结论 |
| 执行绑定 | 错租户、错成员对象、未提供的binding及不可用来源不能执行；保留建议及已有分析，不把未执行记成已取证 |
| 正文质量 | 原主张和原业务判定保留；引用合法不证明正文正确，质量仍后置NOT_PASSED，不新增语义裁判或采样 |

来源数组按能读取的结构化字符串列表接收，再独立诊断；不能让来源枚举、非空依据等旧校验在更早层次重新删除业务正文。成员本身未知/重复与成员引用另一个已知成员材料须区分：前者可能无法确定主体，后者记引用范围问题。正常生成仍要求按本轮材料作答，记录诊断不扩大工具范围。

### 4.2 原答、派生结果与诊断

先保存原始回复，再产生派生结果。模型原结论、原状态、摘要、成员分析、问题回答、发现、领域理由和冲突解释均不因引用问题置空或替换为占位话；本来是unresolved的仍是unresolved。程序observed只使用实际可解析观察，不能按声明成员补造未选中的事实；模型声明范围、实际引用覆盖分别记录。

复用现有校验/工件元数据，版本化记录以下内部内容，不增加对外告警字段：原答工件ID、模块/步骤/尝试、字段路径、问题类别与代码、原编号/原范围、解析所得来源归属、处理动作及前后值。动作区分同列表去重、引用无法绑定、质量提示及结构未完成；未检查内容记not_checked。原答hash与派生结果hash可分别核对。

同列表完全重复编号只保留第一次；不跨字段删引用，不因不同编号内容相似而合并。未知编号保存在原声明/问题记录中，不造来源记录；实际来源链接只绑定可解析原件。跨成员来源的原归属保持。确定不适用的引用可从有效链接集合剔除并记录，但相应正文和原判定继续保留；缺失链接不触发模型纠正。

### 4.3 保存、后续输入、报告和采用

A/I结果、C3/Deep分析、C6结论及报告均从同一派生版本保存与读回，不能只在页面原答区保留正文而后台结论仍空。装配器逐项解析引用，无效单项不得导致KeyError丢掉整份业务结果。程序计数和执行coverage按实际材料/活动计算，不把引用通过率当作已分析成员数。

后续模型按任务读取原分析及必要事实/反证，附相关简短质量说明；前序分析仍为prior_analysis，不升级为独立观察，也不因引用问题自动作废。质量台账留后台，不把整份执行台账塞回模型。

采用沿既有预览/提交及自动采用流程执行：同主体、完成状态、原范围、输入新鲜度、当前人工选择和原业务覆盖条件保持。模型明确分析/判定的成员范围与实际证据链接覆盖分开，纯引用错误不能换算成无结论或未分析来阻止采用；真实缺成员、主体不明、stale或unknown仍按原条件处理。引用质量及NOT_PASSED随候选可查，不因采用变为质量通过。保存原分析本身不自动覆盖当前判断。

冻结告警HTTP字段及含义保持，内部诊断通过既有Run/工件关联读取；不能用model_response工件指针冒充实质业务依据。若实现中发现必须改冻结字段才能表达，先列具体字段与兼容影响，不能静默重定义或用假引用填必填项。

## 5. C3缺失部分的一次补答

### 5.1 触发与边界识别

适用于已收到实际C3答复、执行与用量已知，因长度结束或缺必需顶层字段未形成完整输出的情况。初答仍一次要求七部分。对[旧C02截断答](../../../docs/operations/evidence/c3-capacity-20261114-01/C02-4096/answer.txt)只读解析已识别六个完整顶层值，followups在字符串中停止；这仅是结构定位证据，没有新模型调用或原批成功追认。

解析按JSON字符串转义、嵌套及完整值边界识别顶层字段，不用关键词搜索、不假设键顺序、不为半截字符串补引号猜值。只保留身份/类型/数量结构明确的完整字段；引用质量不影响字段是否完整。空findings/conflicts/followups是已完成回答，不视为缺失。重复顶层键、未知主体/定义ID歧义或不可识别损坏不进入自动补答；已知结构错误也不能伪装成只有尾部截断。

需要有可可靠保留的完整部分和明确待补字段集合。截断在followups内部时请求完整followups，不从半句话续写；更早截断时一次请求该字段及其余缺失字段。七字段均完整、仅缺最后外层闭合符时，可按完整解析字段重建派生对象并记录结构装配，不新增调用；原回复length状态保持，结构完整不替代质量检查。

### 5.2 请求与上下文

当前[TenantChatGateway](../../../services/api/app/socai2/baseline_analysis_model.py)每次显式发送messages，不能假定模型进程或连接还在就自动记得上次输入。程序自动构造同Run补答请求：

1. 沿用原C3已筛选的冻结业务输入、成员/来源/对象/工具绑定映射；不读latest、不重查材料、不把数据库对象整包传入。
2. 携带与待补任务有关的已完成分析，保持原文/状态/范围并标为前次模型分析；按明确字段依赖恢复必要支持与反证，不用新摘要替代。例如补followups需五问、发现/冲突及相关限制，不能只给“继续回答”。
3. 指令明确已完成字段由程序保留，只交付待补字段。Schema只要求待补顶层键及原子结构，限制额外字段，保持原来源短号及数量/绑定合同。
4. 对实际补答wire重新计量，初答用量不清零。重带上下文计入输入和总预算，不称作服务器原会话的免费续写。

### 5.3 合并、失败与执行

在同一C3阶段记录一次新的model尝试，关联初答ID、保留字段、待补字段、补答Schema/配置及实际用量。最多一次补答，总额度或C6余量不足时不派发。无回复、超时、unknown不触发补答，不以新Run绕过限制。

补答必须完整、只包含请求字段且身份结构合法。成功时按字段合并，不覆盖已保留字段；再核七部分、全成员、五问、四域、最多5发现、最多2补查及交叉ID关系。引用错误独立记诊断，不作为补答失败理由。补答返回多余键、替换已完成内容或仍缺项时记录不合格，不追加第三次调用、不自动全量重答。

初答、补答及合并后的模块输出分别保存，每个顶层字段能追溯到原答；不得将两次回答标成单次模型原答。合并并通过实际执行绑定检查后才派发C4计划；未形成完整计划不执行半条动作。补答未完成时保留可确定的前序分析和缺项，C6在资源允许时用实际材料收尾；无可用最终回复沿原system/system_only合同记录，不能宣称C3完整或伪造模型结论。

## 6. 整个模块的输入输出留存与读取

| 模块 | 输入与输出至少关联到什么 |
| --- | --- |
| A | 同次材料/反馈版本、实际查询、模型视图/请求/原答、装配、分诊及采用回执 |
| I | 固定成员和配对A结果、事件模型输入/原答、成员/总诊断及保存读取 |
| C1 | 成员、材料、前序、H、指定比较及profile；冻结快照和来源映射 |
| C2 | 实际来源/参数、原始返回、业务投影及查询状态，未查与查空区分 |
| C3 | 业务视图、提示/Schema、初答、补答、诊断/去重/合并及最终七部分 |
| C4/Deep | 原计划项、绑定、工具请求/返回、问题级输入/原答、执行/交接结果 |
| C5 | 构图实际材料、保留来源与图产物，不当作新增取证 |
| C6 | 实际事实/前序/H/原计划/比较、请求/原答、报告/Result及采用回执 |

按主体、Run、阶段、步骤、调用/尝试和工件关联。阶段直接input_artifact_id为空时检查已有Run输入和子步骤来源链，不能据空指针断定原件丢失，也不能读最新材料补出历史输入。复用不可变原件，不重复复制大份材料；关联须能还原内容，只留路径或hash不算完整。

第一版沿既有PG工件content_json/content_text、size/hash、source_refs和步骤关联保存原件，不新建日志平台或独立对象存储服务。受影响写入路径先保存实际工具返回，再生成模型业务视图；已取得行不能仅为满足产物1 MiB限制被静默裁掉。上游限量或未返回内容明确说明，不额外翻页补采。

运行配置分开模型准备/上下文限制、查询数量、原件存取及页面预览长度；max_artifact_bytes不能同时充当原件丢弃门和模型准入依据。默认详情按元数据/折叠内容展示，展开原件时沿现有工件读取合同完整读取并核size/hash，不因超过旧预览阈值仅返回unavailable。保持原字段和内容类型，不以截断正文冒充原content_json；配置示例、新装/升级及部署来源随实施更新。真实存储资源不足仍如实失败，不能报已完整保存或绕过unknown保护。

实际模型提示、业务视图、Schema、参数和输出正文完整留存；凭据、私钥和隐藏推理不进入普通记录，受控排除及缺失原因可查。不要求记录模型服务内部推理或未收到的token。原答、清理结果、最终输出分别命名，失败/截断/补答均可查，旧批不重派回填。

### 第六步实施安排：原件、关联与读取

本轮承接步骤1–5，只落实第6节。目标是A/I、C1–C6和Deep已实际取得的输入、请求、原答、处理及输出能按同主体/Run/步骤/尝试还原；超过旧1 MiB阈值仍完整保存、按需读取并核验size/hash。模型业务视图与原件分开，不改变冻结告警交接字段、查询范围、行数、模型额度或C6预留，不重派历史Run。

按以下顺序实施和直接验证，完成后汇报停止：

1. 核对各模块的Run输入、父子步骤、input/output_artifact_id、source_refs及正文内不可变ID；复用已有实际原件，缺直接阶段指针时沿Run/子步骤恢复。记录失败、截断、补答、未调用及历史缺失的实际区别，不用最新记录补历史。核查发现旧Run只有策略指纹和额度，故新Run另存所选运行策略及输入profile完整快照并关联输入工件；仅后台留存，不进入模型视图，不保存环境/凭据，不回填旧Run。
