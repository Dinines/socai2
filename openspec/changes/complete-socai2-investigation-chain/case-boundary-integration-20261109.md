## 本次行为

1. **C1 冻结真正配对的 A 查询回执。** 在读取告警、当前分诊指针的同一 SQL 语句内，取得对应已完成 A Run 的工具步骤 output 工件。副本附在各告警下，保留原 ID、版本、租户、Run、步骤、hash/长度和 scope；引用指向本轮 Case 自己的 C1 快照。扩展版本为 `socai2.case-queries.v1`，旧 `socai2.baseline-context.v1` 无扩展时不补读新材料。
2. **C3 读取结构模板生成的文本。** 原材料、有效告警分诊、事件发现与问题、同 A 查询和 C2 背景查询分别标角色；保留 I 每一项原声明范围。输入适配不推断行为含义，不改写原文。短成员号、对象号、配置指纹、完整映射/省略账本随输入保存；每次实际请求同时保存工具目录呈现账本。完整请求仍经过现有容量和输入检查。
3. **输出恢复既有七类内容。** 模型仍输出本环节的整体解释、成员、问题、发现、领域、冲突和补查。程序只恢复结构化短号；绑定 Schema 与接收端均校验真实工具范围。原答保持原短号，恢复后进入原保存合同。空引用最多反馈纠正一次；反馈与上一份答复均使用同一短号，局部拒收保留独立有效结果。
4. **扩展新鲜度保护。** 应用侧把原 V1 检查和回执扩展检查组合，统一供当前判断读取、结果采用、系统收尾和证据目录使用。未知版本或已选回执集合变化不能判 current；原数据库函数与迁移不改。隔离验证证明，即使基础函数仍 current，新增同次回执也会得到 stale 并阻止采用。

新配置为 [investigation-policy-case-v1.toml](../../../deploy/local-investigation/investigation-policy-case-v1.toml) 的 `case_io`。C1 固定规则及业务字段 profile 指纹，生成时不静默切换。没有配置这一节时继续旧路径；C3 新视图使用独立 `socai2.case-model-input.v1`，Deep/C6 所需旧 JSON 视图另外保存，避免把文本交给旧 JSON 解析器。
