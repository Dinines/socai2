# M0g 接收前阻断：分离扫描执行限额与冻结选择绑定

本文件是 [M0g 单批真实验证](case-input-capacity-20261128.md#m0g过滤修正后的-kafka-起点单批真实验证)中的一个必要修复步骤。当前只解决原生 delivery 扫描在接收前被执行限额阻断的问题；已完成的发布和落湖继续使用原回执，不再发送原件。

## 目标、范围与业务效果

`LakeDeliverySource._scan` 在读取当前 tenant、database、source_namespace、mapping_version 的完整原生范围前，先核去重后的记录数是否超过 `selection.read_limits.max_records`。这项检查必须保留，不能通过 UID 筛选、删除保留项、静默截断或绕过扫描解决。

现行 `binding_digest(selection, receive)` 对整个 `selection.body` 和 `receive.body` 求摘要，包含选择配置里的 `read_limits`。直接改这个字段会改变已有账本绑定。修复后，调用方可以在现有 delivery 配置中显式设置本次扫描执行限额；选择规则、身份、来源范围、原有选择配置与账本绑定保持原样。没有新增配置的旧调用继续使用原来的选择读取限额。

范围限于程序扫描的记录数、结果字节、查询超时、连接超时和收发超时。告警交接字段、原始材料、选择语义、接收策略、模型输入和模型预算均不属于本步变更。不会迁移数据库、重写旧 digest、创建新库、改换连接或自动重跑失败模型。

## 唯一实现方案

1. `DeliveryPolicy` 接受可选的顶层 `read_limits`，其字段与 `SelectionPolicy.read_limits` 相同，必须完整给出且都是正整数。未知字段、缺项、布尔值、非正值仍拒绝。复用同一小型结构校验函数，不增加通用配置框架。
2. 有显式 `delivery.read_limits` 时，本次投递使用该完整配置；缺省时完整沿用 `selection.read_limits`，不逐字段拼接，不回落到其他环境。
3. `LakeDeliverySource` 接受独立的执行限额，`_scan` 用它设置条数、字节和查询时限；范围与版本去重、完整性核对仍取原 `SelectionPolicy`。现有构造调用不提供此参数时保持原行为。
4. `open_delivery` 将同一组实际执行限额用于 ClickHouse 客户端的连接/收发超时和 `LakeDeliverySource`。`receiver.selection`、`store.selection`、`SelectionPolicy.digest`、`binding_digest` 算法及旧账本均不变。
5. 同步 delivery 配置示例与使用说明，写明兼容行为和显式字段的用途。部署仍加载文件，不将本批规模或配置值写入业务源码。

受影响入口仅为 `services/fusion/app/services/lake_alert_selection.py` 的限额结构校验、`services/fusion/app/services/lake_alert_delivery.py` 的配置和扫描、`services/fusion/app/workers/lake_alert_delivery.py::open_delivery` 的接线及对应示例/直接测试。既有独立投递 CLI、测试调用和本批接收入口均走同一通用路径。

## 部署与恢复边界

只以实际 Fusion 源码为基线叠加本步已审文件，不复制整个脏工作区。本次优先由同一现存 Fusion 容器中的全新独立子进程，在导入目标模块前将精确候选目录加入 `app.services` / `app.workers` 的进程内包路径；目标只含这三个模块，先核候选字节 SHA，再核实际导入文件及 SHA。其余依赖继续使用该容器原源码，包括与工作区不同的 receiver；实际绑定仍按原选择和接收文件计算。该过程不覆盖容器原文件，也不影响已运行服务的模块路径；子进程退出即结束临时加载方式。

精确文件包、入口、实际加载及恢复记录先交统筹独核。若该方式无法实现，不擅自换成原路径覆盖；仅在明确原文件/属性恢复清单及其他进程影响后处理。既有原库、连接、来源和选择/接收配置保留，不重建环境或恢复其他自动消费者。

本批显式 execution 配置和规模留在 `.local`，发布前后的数据只在私密证据中比较。旧失败意图/回执保持，恢复接收另存新意图，并引用已经确认的 Kafka ACK 与落湖回执。完成本步后按既有窗口恢复临时源码/候选；恢复须核原字节及文件属性，不反向清理本批新数据，也不重置 topic、缓存或业务表。
