# 告警相似历史复核

## 已有产品依据
`ui-discussion-principles.md` §4 区分详情同主机最近7条和反馈复核最近5条；后者按“同主机且同战术，或同IP/文件哈希”。本次只实现后者 F03-05。原型只过滤已加载记录，本服务查询真实库。规则沿真实对象和检测标签，不调用模型或向量检索。

## 输入及范围
GET `/api/v1/socai2/alerts/{alert_id}/review-candidates`。查询参数只有 time_from/time_to（同时提供、带时区、前闭后开）、limit（默认5，1–100）、cursor（最多4096字符）。默认以当前告警 event_time 为终点，回看配置30天，即 [event_time−30天,event_time)；起点时间未知必须明确给时间窗，不能用入库时间替代。调用方可明确使用其他时间范围，响应标为 explicit，不声称仍限定在起点之前。无匹配返回空页，不证明安全。
同租户、同告警 source_namespace；对象 namespace 也必须相同。只用各告警 latest_material_id 下的对象及 detection.tactics。排除当前告警；可跨事件/Case，保留原归属，不以关闭或已反馈状态排除。候选发生时间未知不进入时间窗。

## 匹配和来源
三个规则取并集，告警去重但保留全部匹配依据：
1. host 对象 normalized_value 完全相等，且两份当前材料 detection.tactics 中至少一个非空字符串标签完全相等；大小写、编码与名称不互转，不从技术编号推战术。战术标签不是攻击事实。
2. ip 对象 normalized_value 完全相等。
3. hash 对象明确算法规范化后相同且哈希值相同：复用 E66 的 MD5/SHA1/SHA256/SHA512 格式校验，大小写不敏感。没有算法、错误长度/内容均不匹配，不按文件名匹配。来源只有hash时不额外断言文件身份或恶意性。
不支持其他对象类型。起点无主机/有效战术、IP或合法hash时分别列出 unavailable_rules；非法hash和不支持对象在 excluded_objects 列出。返回原对象ID、原值、规范值、材料ID、source_path；同主机规则再给共同战术原值及双方 detection.tactics 数组路径。客户端 E28 打开候选详情，E30/E31回查，确认后 E48 单条或 E49明确勾选批量反馈，本查询不写反馈。

## 顺序、分页和兼容
按候选 event_time 倒序、alert_id 倒序，优先最近记录，不按匹配数量计算威胁分数。SQL先过滤、告警去重统计，再取limit+1。游标绑定租户、起点/最新材料、实际种子对象及战术、时间窗；改变范围/起点返回409，坏游标422。单次 REPEATABLE READ READ ONLY；跨请求不是冻结结果集。缺源告警404；未知/重复查询参数422。
新包络复用原 AlertFacts/ExplorationObject；不修改旧69操作、145运行schema或任何告警表字段。对外路由依赖独立端口，核心不依赖HTTP，E30/E66/C5及内部查询不改。新配置 alert-review-query.json 明确默认回看天数，不借Case探索窗口。

## 直接验收与发布
独立本机合成批覆盖：主机与战术同时成立、仅主机/仅战术不命中、IP、合法hash、重复匹配、命名空间隔离、旧材料排除、真实时间窗/分页/缺时错误、E28/E31回查及读取前后原行不变。旧69合同和HTTP依赖边界定向验证。文档和未参与实现者审计后，一次更新本机/21 API及Swagger；21仅查既有记录，0模型/0生产业务写入。保留独立同主机近期展示未实现和AI对话暂缓状态。
