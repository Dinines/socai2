# 历史知识如何进入调查

## 现状与目标

`baseline_enrichment_sources.py` 的 `history` 用冻结对象与 Case 时间窗查询 `socai2.alerts/alert_objects/alert_assessments`；结果已有分诊和人工来源角色。`knowledge_source.py` 按两个目的查询 Qdrant 后回读 PG，C3 建立来源别名，Deep/C6 复用冻结输入。保留这两条路径，增加一个知识目的及显式历史入库入口，不建设另一个通用记忆平台。

## 1. 入库内容与真实性

`POST /api/v1/kb/alert-experiences` 接收 `alert_ids`。服务端按当前租户读取告警当前材料及指向的分诊/人工反馈；无材料、无历史判断、无事件时间等情况逐项返回未入库原因。没有业务核实证据时始终标记 `not_independently_verified`，人工反馈只是 `human_statement`，不能自动成为授权或真值。

每个告警形成一个不可拆散的 JSON 知识卡片，保存在既有 `aisoc_kb_documents.content`，`doc_kind=other`、专属 purpose tag。结构包括：

| 部分 | 来源与用途 |
| --- | --- |
| source | 告警/材料/分诊/反馈 ID、材料 revision/hash；原记录链接及身份可核验 |
| event | 原标题、事件时间、命名空间、厂商及原等级；来源标签 |
| observations | profile 指定材料路径的原值/角色/路径，保留 0/false/有效空列表；不是本案观察 |
| objects | 当时材料的有类型/命名空间对象，用于说明相似及差异，不扩大本案实体 |
| triage | 原分诊理由、结论、建议、生产者、时刻及材料对应状态；prior_analysis |
| feedback | 原人工判断/理由/建议、操作者及时间、材料对应状态；human_statement |
| limitations | 未独立核实、部分材料、旧判断不代表本案、建议不代表已执行；没有字段的误报条件/处置结果不由程序猜补 |

正文不语义改写，不静默切片；超配置大小返回未入库原因。相同源内容生成稳定文档 ID，重复入库返回同一卡片；源版本变化产生另一卡片，原材料和原快照保留。`GET /api/v1/kb/alert-experiences/{document_id}` 读取完整卡片；`/kb/index` 显式索引，核卡片与数据库源内容相符；手工打标签不能使任意正文冒充程序快照。卡片来源真实不等于历史判断正确。现有导入/查询接口不改语义。

## 2. C2 按目标检索

profile 可选 `historical_case_reference`，有独立模板、tag、类型、limit、阈值和历史回看天数，沿用 qwen3-embedding:0.6b/1024 及现有专用集合。嵌入内容由历史标题/原观察和判断组成；查询仍从本轮冻结材料构造，不让模型补事实。

历史检索限定同租户、专属目的、事件时间位于 `[Case.window_start-lookback_days, Case.window_start)`，排除全部当前成员。没有明确时间窗不生成该目的查询。查询条件、真实时间范围和过滤保存。技术解释/取证指导不套用历史时间窗。

向量命中回读原卡片/hash，核来源身份；返回历史版本及与当下源指针是否一致。版本不一致标明旧快照，不冒充最新判断。相似分只用于检索/4177，不作为模型置信度。共享内容不成为独立的多份证据，查询绑定保留而记录主体始终是原历史告警。

## 3. 模型消费：先比较，再参考

| 阶段 | 交给模型的信息 | 要解决的问题 |
| --- | --- | --- |
| C2 | 生成/保存卡片检索与回执，不调用生成模型 | 查到什么、为何进入候选、实际状态是什么 |
| C3 | 本案原材料 + 历史卡片的来源、原观察、原判断/人工正文及版本/适用限制 | 哪些历史解释可作为本案假设，缺少哪些相同条件；最多两项新问题约束保持 |
| Deep | 已冻结且进入前序输入的知识与当前问题、实际工具结果 | 哪种验证方法可复用，当前结果支持到哪里；不从历史经验发明工具参数 |
| C6 | 本轮证据及前序结论 + 同一冻结历史参考 | 明确相似与差异、未验证条件及建议，不沿用历史 verdict 作为本案判定 |

卡片整体为非观察来源；分诊/人工正文各自有独立引用路径和原角色。历史记录归属是原告警，不能通过本案查询成员绑定改成当前告警事实。既有 V4 输出和合法候选/程序校验保持，模型正文仍可能误用历史，实际原答和质量结论必须保留，不新增语义重写/评分系统。

## 4. 4177 与存储

不加调查表列、枚举或 tool_response 顶层字段。查询参数进既有 `actual_args`，卡片进 `rows[].record`，调用/索引信息进 C2 summary 的 `source_metadata`，引用沿 `source_map` 保存。右侧 C2 知识面板增加“历史案例参考”：查询范围、历史告警/材料/判断版本、原观察/分诊/人工正文、版本状态和真实空态/失败。C3/Deep/C6 面板关联卡片及其子字段的可见/引用状态，不显示“已证实”或“已采用”推断。

## 5. 验证、交付与后续顺序

1. 直接检查：卡片原值/版本、重复入库、缺判断/时间不造卡；检索排除本案/未来记录；模型来源角色和卡片字段引用；复用已有知识测试。
2. 一次本地链：显式历史样本入库→索引→一轮 C2/C3/Deep/C6→保存/GET→4177。真实 PG/向量/嵌入/分析调用分别记录；历史样本若为演练须明确标注，不能冒充已核实业务授权。已有模型问题不导致反复重跑。
3. 更新交接及问题、一次独立结束审计；整轮验收后统一发布 21 一次，读回后归档、Git/父项目同步。无需重做压力/恢复/权限矩阵。
4. 后续再做 P01–P04 产品页面接线及自动消费。A/I 知识、Deep 动态再检索、知识自动抽取/淘汰和真实处置执行不混入当前 change。

回退只关闭本 profile 的历史目的，保留已有两个目的、历史文档和数据。新入口未入库的原因与未证明的模型效果留在验收记录，不将有卡片等同知识质量通过。
