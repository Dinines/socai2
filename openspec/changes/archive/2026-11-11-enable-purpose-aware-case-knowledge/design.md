## Context

主调查的[知识使用位置](../../complete-socai2-investigation-chain/design.md#知识库使用位置与本地嵌入)已确定 C2 检索、C3 分析、Deep/C6 复用。本次补上按目标区分的实际合同及 4177 展示。本文描述目标实现；未勾任务不是已部署能力。

当前代码入口：

- `baseline_enrichment_sources.selectors/selection_plan`：C2 来源选择，知识仅取告警标题；`baseline_optional_sources.QUERIES`：英文全文查询 runbook/playbook/sop。
- `baseline_enrichment.BaselineEnrichment`：工具预算、步骤、输入参数、结果工件和 citation_roles；继续复用。
- `case_model_boundary.build` 与 `case_followup_loader`：C3/Deep/C6 本轮材料输入；不新增并行调查器。
- `knowledge_base.ingest`：PG 文档分块；索引与查询沿该原文档身份关联。
- `processing_audit_flow.py`、`processing_audit_inspector.py` 与 `update_processing_audit.py`：左侧流程、右侧节点详情及实际批次发布；不另建页面系统。

## Decisions

### 1. 按业务目标设计检索

共用本地嵌入服务和文档存储，查询模板、资料类型、返回用途及适用条件分别配置。阶段名称不能替代检索目标；同一阶段允许有不同目标。同一片段重复命中保留目的和成员查询归属，以 `record_id/content_sha256` 识别重复，不把多次命中当作独立来源；本次仍保留逐查询行，未合并模型输入中的重复正文。

| 使用位置/目标 | 查询依据 | 优先知识内容 | 所需返回及用途 | 本次状态 |
| --- | --- | --- | --- | --- |
| C2 → C3：技术解释 `technical_explanation` | 冻结记录中的命令/产品/事件类型/动作；检测标题或技术标签单独标为检索线索 | 技术参考、行为/协议/命令说明、ATT&CK 技术说明、带适用条件的案例 | 功能、前提、常见场景和不能由该观察直接证明的事项；帮助形成待核解释 | 实现 |
| C2 → C3/Deep：取证指导 `investigation_guidance` | 同一技术主题及已有材料类型，明确要求如何区分可能解释；已有待核问题若适用，带原问题来源 | 调查 SOP/runbook、检测/取证方法、所需日志和字段说明 | 待补证据、查询方向、预期可观察结果和局限；供 C3 提出补查、Deep 解释实际返回 | 实现；不得把知识建议直接转成可执行任务 |
| C4 新问题：定向方法补检索 | 已接受的问题、当前实际证据与缺口 | 与该问题直接相关的方法片段 | 单问题需要的证据/方法；与原始结果一起再分析 | 后续扩展，本次只消费已有相关片段 |
| C6：处置依据 | 已有调查结论、受影响对象与待核条件 | 适用的处置 SOP/回滚/执行确认方法 | 建议、适用前提及执行确认方式，不能称已执行 | 本次仅引用本轮已有且适用的知识；不另发独立处置检索 |
| A：分诊知识 | 特定检测规则、原始行为与组织分诊目标 | 规则释义、已核实误报条件、分诊 SOP | 支持该告警的分诊解释 | 后续按实际缺口接入 |
| I：组合行为解释 | 冻结成员、已知时间/实体关系和待核关联 | 行为组合、攻击模式及适用条件 | 提出可验证的事件解释，不代造因果/关联 | 后续按实际缺口接入 |

C1 冻结、C5 关系图、H 保存、执行状态和程序派发/落库本身无需知识检索。知识不能推导真实授权或代替查询结果。

### 2. C2 的输入、处理、输出

1. **输入**：只使用本 Run 冻结材料及允许字段路径，保留 alert/material/路径和原角色；程序提取技术主题，按两个目的配置生成实际检索文本，不额外调用生成模型改写原始事实。不用本轮模型尚未产生的问题冒充已有问题。
2. **触发**：来源已启用、目的存在适用主题、资料类型已配置，并处于既有 C2 工具预算/时限内。缺主题或未获调用额度记未查询；不强制每案命中，不提高 Run 总额度。多个目的的内部检索次数和条数有配置上限并记录，不用单个工具步骤隐藏无界调用。
3. **检索**：文档和查询使用同一显式嵌入模型/原生维度；按目的筛选资料类型/标签，再进行语义召回。精确技术标识的补充匹配若启用需明示来源；不在语义源失败后静默换一种检索并声称原检索成功。
4. **输出**：每个目的保存实际查询、来源路径、过滤条件、模型/维度/集合、执行状态、命中片段及原文标识/来源/hash、相关度和截断情况。聚合工具状态与各目的状态分开可解释；未查、失败、查空分别保存。
5. **落库与后续**：复用 `run_steps.actual_args`、`artifacts(tool_response)` 及 C2 汇总的 `sources[].source_metadata` 保存内部信息；`tool_response` 顶层仍遵循冻结的 tool_exchange 合同，不增加顶层字段，沿用知识的非观察来源角色和限制。C3/Deep/C6 只引用本轮可定位的片段；不改告警字段、枚举或 V1 表列。

### 3. 本地嵌入与文档索引

- 优先复用既有 `qwen3-embedding:0.6b`/1024 维部署记录，实施前核实际可用服务。地址、模型、维度、集合、超时、条数、文本限额、目的模板/过滤都由显式 profile 提供；私密凭据引用受控文件。
- 通过既有 `/kb/ingest` 保存有来源的文档，再由明确索引入口对指定文档块建立向量。原正文以 PG 为准，索引保存文档块 ID、tenant、内容 hash、模型空间与分类信息；索引失败与文档已保存分别报告。小量已有资料按需要接入，不全量重建已有集合。
- 命中后回读 PG 原文并核身份/hash，保留实际片段供本轮冻结；删除或变化的原文不能被旧向量冒充为当前正文。不会将组织记忆的 1536 维集合直接当成此知识索引，也不靠补零/截断混用模型空间。
- 源资料类型保持真实：技术参考可为 wiki/other，调查 SOP 为 runbook/sop；目的标签说明用途，不把外部报告改标 SOP 来凑查询命中。知识的来源、文档版本与本 Run 快照分别记录。

### 4. 后续使用与 4177 展示

沿当前左侧流程、右侧详情布局。**C2 的知识节点是检索输入输出主入口**，按技术解释/取证指导分组；每组展示目标、状态和命中数量，点开仍属同一 Run 的实际记录。模型节点和原始 JSON 入口保持。

| 区域 | 展示内容 | 依据 |
| --- | --- | --- |
| C2 输入 | 使用目标、涉及成员/材料路径、实际查询文本、知识类型/过滤、条数与长度限制 | 已保存的实际参数，不能从标题猜测 |
| C2 检索过程 | 本地嵌入模型、维度、检索方式、集合、耗时及实际调用记录；嵌入输入按目标可读 | 真实请求/回执；向量用维度/hash概览，凭据和隐藏推理不入页面 |
| C2 输出 | 命中条目、文档标题/类型/来源、块身份/hash、实际片段、相关度、适用限制及截断 | 保存的知识结果；相关度不叫可信度或案件置信度 |
| C2 空态/失败 | 未查询及原因、完成但无匹配、源不可用/超时/失败、部分输出的实际边界 | 真实状态和错误；历史记录缺字段显示未记录 |
| C3/Deep/C6 输入 | 实际系统/用户提示词、Schema、输入原件；本次进入模型输入的知识来源及目的 | 对应 model_request/source_map 与片段引用位置 |
| C3/Deep/C6 输出 | 模型原答、校验及装配结果、失败原因；能定位的知识引用与引用所在输出 | model_response/校验/装配原件；原答非法和引用未解析仍保留 |
| 使用关联 | **已检索到 → 已进入输入 → 输出有可解析引用**分别显示 | 三种各自证据；没有引用显示未见引用/未记录，不能仅因 prompt 含片段标为已采用或质量通过 |

Deep 按问题范围使用相关片段；C6 用于解释的技术知识和用于建议的方法知识标明用途。可解析引用只证明引用关系，合理使用仍由本次实际原答审查判断，不在页面伪造自动质量判定。查看 4177 不触发新查询或模型调用，既有批次及失败原件保留。

## Validation and delivery

1. 直接检查两个目的的查询/筛选差异、来源范围和稳定引用；非空/查空/失败按真实含义保存，本地模型维度与原文 hash 对应。复用既有测试，只补受影响行为。
2. 用现有可追溯资料正常导入/索引，走一个适用 Case 的实际 C2→C3→本次经过的后续→保存/读回。记录本地数据库、实际嵌入/分析模型及传输适配范围。若 Deep 未触发，直接说明，不强制分支或为此再跑模型。
3. 同一批数据更新 4177，定向核 C2 两个目标的输入输出、空态/错误及模型引用关联；只做本功能页面查看，不做通用可用性测试。非空或存在引用不足以证明知识合理使用；原答偏差如实记录，M01-A/M01-B 不重复采样。
4. 更新交接、配置/新装升级与实际来源，未参与实现者限定结束审计后，一次发布涉及的 API/处理组件及工作台工件；核实际配置/版本和本功能读回。随后归档、一次有效推送 Git/父项目。回退沿发布组件，文档、索引和既有调查数据保留，不清库。
