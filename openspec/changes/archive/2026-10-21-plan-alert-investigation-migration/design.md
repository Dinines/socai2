## Context

用户已决定完整迁移告警/调查，所有一体依赖可原样保留不额外改测，可用性和冗余设计后置。已有完整性评估/I1—I4及restore15项任务足以承接产品实施；无需再建一套总规格或任务框架。

## Goals / Non-Goals

让实施者能确定每批功能、输入输出、真实依赖、最少业务证据、状态及下一步；自动调查与人工调查同为主线。只规划，不开始产品修复或启动自动worker，不补可用性矩阵或额外模块测试。

## Decisions

1. 当前completion-plan为唯一总执行表，roadmap只管六阶段退出，scope管职责，PROGRESS管事实；旧三份计划先原字节复制到history，摘要记history-snapshots.json，避免改写原计划背景。
2. 采用六个业务批次而非六套新阶段：B1归路线二，B2—B5归路线三，B6归路线五；路线四playbook/反馈后置，路线一复用，路线六优化后置。
3. B1与B2独立部分可并行；B3在默认调查上接消费；B4实际自动链使用已接的工具/知识，正常用量源码修复可提前；B5盘点和所需恢复随依赖，不能先全部完成才接默认调查；B6复用前批证据。
4. 自动调查必须单列五段实际行为：自动触发/分诊、按策略关闭、无需人工再点的升级、实际取证/知识/分析、持久结果/证据/报告交付。常规正常消费是功能验证，不重新引入R02启动/退出/恢复专项。
5. 不虚构deep HTTP或将只读结果回放当模型replay；保原主要编排和服务。缺真实外部数据如实partial，只有确为实际调用必需的支撑按原组件整体补迁。
6. 更新现有restore任务中的批次引用和依赖，不新建重复产品待办；跨批任务全部责任完成才勾选。所有产品任务仍pending，仅本规划文档change完成后可归档。

## Risks / Trade-offs

- 新旧计划冲突 → 当前主表替代旧执行顺序，保留历史字节及出处，不改旧回执。
- 自动能力被误降为人工队列 → 总计划单列自动链和B4实际行为，review_only仅当前限制。
- 功能规划变成全量专项验收 → 每批只核本次变化、复用兄弟路径和旧证据，所有一体原样模块不额外改测。
- 缺源或模型失败被隐去 → 状态分列、正常结果错误最小修复，不宣称整体通过。

## Migration Plan

只更新文档、检查CLI/本地链接、由未参与实现者审计总计划及自动调查覆盖，然后归档本规划change。无需产品/环境回退；若修正文档，保留已有历史字节。后续产品实施从总表B1开始，B2可并行准备，仍按原授权和必要真实响应约束执行。
