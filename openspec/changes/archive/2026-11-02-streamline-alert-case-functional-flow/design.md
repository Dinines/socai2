# Design
告警准备入口通过瞬态UI请求进入准确Case，仅预选该告警，不存储业务记录。多Case明确选择，无Case经原关联/创建确认后进入；源环境租户保持，普通Case仍不能启动，专用演示Case沿原单活跃规则。
事件删除独立分类编辑/页头展示，旧值留存不清理；新建、分配后处理中、人工解决及已有同步不变。
响应动作按原数组索引绑定审批，标题/目标/理由与审批决定同卡；免审批、缺目标、字符串建议及所有执行原件保持，无法按明确动作ID匹配的执行另列，不按近似名称拼接。
Case概览保原结果/下一步布局和历史入口。Run原ledger深链仍可读，AI分析入口称执行明细，技术统计移入明细；其他五个主视图/限制与引用保持。
图谱仅改选材与保存探索文案，不改保存、成员、草案、扩展规则。
# Verification
保改前文件；直接验证告警1/多/无Case及取消无写、事件旧值保留、动作审阅不执行、历史/明细可达和数据不变。跑现有受影响测试及语法，浏览宽窄和代表真实数据，只操作不会保存的入口；写入分支用隔离测试内存核对，避免再次污染用户预览。独立结束审计后归档。

## 全案例统一流程（用户追加要求）
所有来源Run经同一个normalizeRun读取，Case的Run关联与列表状态使用同一规则；来源适配只保留字段、身份和关系材料，不选择另一套页面。去掉闲置Case旧图入口及缺模块时的旧图回退；图谱来源区按材料类型统一组件，缺失材料统一空态。附件由数据层提供，页面不按案例来源补演示文件。遍历全部Case与Run验证同一导航/渲染入口、缺字段和新建Case、租户隔离及历史原件不变。
