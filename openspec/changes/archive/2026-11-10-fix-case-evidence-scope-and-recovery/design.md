## Context

C02 的 A3 历史查询返回 A1 记录，当前来源却只标记 A3；引用 A1 被拒。C01 的跨成员发现确实缺少成员声明，C6 另有本次 findings 不存在的编号。现有纠正只覆盖空引用。背景阶段从 4 次工具中预留 2 次，固定 TI/UEBA 优先，缺失知识未补。原件、归因及错误链见主调查报告，本设计不能替代已发生的结果。

## Decisions

1. 新 Case 模型视图用 `query_alert_ids` 表达查询出处、`record_alert_ids` 表达历史返回行的明确主体，`alert_ids` 表达该来源实际可用于成员引用的范围，`membership_basis` 说明依据。仅对服务端 `history` 返回结构中的一致 UUID 身份做映射；以 `record_id`、`record.id` 和存在的子记录 `alert_id` 一致性为条件，不根据名称、内容相似或主机匹配猜归属。案件外／缺失／冲突身份不强行绑定 Case 成员。执行回执只描述查询范围；其他行保持查询绑定且不可冒充直接成员观察。原 ref/path、角色、正文与原件保持。
2. Case 的 C3 及后续来源注册／依赖恢复共同传递上述元数据；独立相同内容不合并成同一来源。历史结果仍按其冻结来源读取，不回填旧工件；已采用旧判断不因本轮输入投影被静默改写。
3. 完整且结构／必要身份明确的 C3/C6 回复可触发最多一次纠正。先收集空引用、来源不存在、成员不相交、缺成员依据、未知本次 finding 及不合法冲突关系，反馈字段路径、原引用、允许范围和本次已有发现编号。模型须重返完整 JSON 并重验，不自动扩大成员、填编号或删改语义。重试 unknown／不完整响应禁止，次数／时间／token 及 C6 预留沿原机制。原答、反馈、纠正答和独立有效片段分别保存。
4. 当前 Case profile 增加背景选源配置：来源优先级、配对已查来源的降序权重、后续工具预留。按冻结对象判断适用来源；有效同次 A 回执只能证明已有相应背景可读，不代表其完整或最新。优先补缺失的资产及知识背景，记录所有来源排序、已查覆盖和跳过理由。总工具 4、预留 2 及单 Run 模型／token／时限不增大。未选择该 Case profile 的历史路径保持兼容。
5. 提示明确 findings 的引用限定当前回复同一 analysis，跨成员比较声明所有实际涉及成员；程序不替代模型判断真实因果或授权。语义质量单独审查，结构通过不能自动记为准确。
6. C6 纠正同时覆盖 conclusion／impact 声明成员与依据成员的关系；supported 结论及有 supported_changes 的影响只由直接观察／人工陈述覆盖，query_binding_only 不算直接依据。Deep 生成 Schema 按 action 限定 query 使用现有 binding 且 answer=null，answer／handoff 使用非空 Answer 且 binding=null，handoff 必须 unresolved 并列缺口。保持接收校验，不放宽无依据的交接。

Deep 的每个 `anyOf` 分支包含完整 object、required、additionalProperties 和字段限制；不能仅写分支差异并依赖网关继承公共约束。真实第二批证明该网关会只按分支列出的字段生成，丢掉公共必填项；该失败保留，完整分支另用独立批次复核。

## Validation and delivery

- 保存原件只读重建 C02 输入，确认 A1 记录三项来源在 C3/Deep/C6 中归属一致、原 ref/path/role/值保持；补案件外、身份不一致及非历史查询对照。

- 验证选源配置错误拒绝、已有回执覆盖降序、知识查询及提示可见、工具额度和预留保持。
- 使用现有本地隔离库新批次走 C1→C2→C3→C4/Deep→C5→C6→保存／读取，复用 H 服务验证反馈后下一轮；模型／工具替身与真实模型结果分别留证，必要模型请求受当前完整 wire 容量限制。无独立真值不报准确率。
- 更新字段／功能交接、问题清单及 4177，未参与实现者独审通过后统一发布一次。发布核对和回执完成后一次性推送 Git、父项目引用；整个主调查未完成项不随本 change 核销。

## Risks

历史查询返回行可能指向案件外告警或身份不一致，只能保持明确背景；不能通过扩大成员集合修复。有限纠正可能仍失败或无预算，如实保存并保持未采用。知识查询可能无匹配，不能将调用成功冒充知识实际使用。后续真实模型仍可能扩大事实，需要独立质量结论。
