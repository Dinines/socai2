# Case 来源、有限纠正与背景取证验收

本 change 对应问题 F03、F04 和 F02 的调度部分，承接[此前归因](../../complete-socai2-investigation-chain/case-current-flow-20261110.md#流程与模型问题归因)。按用户要求，整个 change 先完成本地实现、流程测试、交接及独审，再统一发布 21 并推送 Git／父项目。模型总体质量、生产知识实际使用、产品页面操作和自动消费仍在主调查任务中跟踪。

## 实现与合同

- `case_source_scope.py` 把查询发起成员、返回历史行主体和可引用成员分别保存。只有 `history` 的 `record_id`、`record.id` 及存在的 triage／feedback 主体一致时才认定记录主体。案件外、身份缺失或冲突不猜成员；其他工具明确只有查询绑定。
- C3、Deep、C6 保留这一语义，包括引用既有 C1 冻结查询的依赖恢复。来源 UUID、路径、角色及原文保持，不回写原工件或判断。
- C3/C6 对结构完整、必要身份明确的答复收集成员错配、未知来源、缺少覆盖和本次发现关系错误，返回具体路径、允许来源及本次发现编号。沿原执行器最多纠正一次；纠正答完整重验，失败仍保存独立有效片段。程序不填发现、扩大范围或改写结论。
- Case profile 配置选源优先级、已有同次 A 回执覆盖的降序权重和后续工具预留。缺失资产／知识背景优先，查过不表示查全；每个 Run 的 6 次模型、4 次工具、131,072 token 和时间预留不变。
- 这几个元数据位于内部模型来源映射，不新增数据库列、不改变告警前后端字段或 HTTP 返回合同。执行状态、交付、采用及模型质量仍分开。
