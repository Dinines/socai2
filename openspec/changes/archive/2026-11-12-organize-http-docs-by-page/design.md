# 文档工作顺序

需求先于接口：原frontend-feature-list.md保存唯一125项产品功能，以告警、事件、调查集中展示；原型、服务页面、后端和验收仍分开。

随后按HTTP调用读取路由→请求DTO及业务校验→服务装配→响应DTO/动态结构，审计字段语义与空值。固定Schema之外的dict/items/工件正文单列具体读取合同与版本，不能仅写“object”就称交接完整。审计报告保存在http-handoff-audit子目录，不写入当前文档容器挂载目录。

本轮只静态读取代码和既有文档，不执行新业务请求/模型/数据库。独立审阅只核文档结论。展示分组和文档容器的后续更新等待本轮合同整理完成，不在审计中继续改部署。
