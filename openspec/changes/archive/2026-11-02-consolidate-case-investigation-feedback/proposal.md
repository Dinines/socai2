# Why
产品需求基线之后，用户反馈任务参考材料含义不清、当前工作入口分散、历史缺少用量。用户要求直接修复页面问题，整理基础调查、跟进调查、AI对话和人工确认等复杂产品设计，并减少强制工单核对。

# What Changes
- 明确人工任务的来源调查和可选资料，避免新建时重复选择同一整轮调查；人工结果可直接记录，无附件或工单门槛。
- 调查概览集中展示执行中的调查和待启动草案，历史草案折叠；历史与详情展示相同口径的已有执行统计。
- 在唯一产品文档整理反馈、取舍、产品参考及目标设计，明确已修页面与尚未实现的新生命周期/AI能力。

# Capabilities
## New Capabilities
None.
## Modified Capabilities
- frontend-versioned-investigation-workspace: Case任务材料、当前工作与历史统计呈现。

# Impact
仅本地原型与产品文档，不更改源数据/后台/模型/响应/部署/Git。基础调查自动重跑、对话工具调度、Case记忆、图谱增量方案仅设计，不宣称已实施。
