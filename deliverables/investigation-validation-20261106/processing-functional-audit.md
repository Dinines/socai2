## 三个 Case 的执行为什么都是 unknown

实机链路为 **21 上的 r3 调查作业 → 21 的 LiteLLM 网关 → 43 的 vLLM**。43 的监听端口是 8000，推理模型为 Qwen3.5-9B。三案 A/I 共 7 次调用都收到了原答；三个 Case 在 C3 主分析处均收到 HTTP 408。21 的网关全局等待上限为 45 秒，重试次数和后备路由数均为 0。三个 45 秒窗口内，43 的服务级采样都显示 1 个请求在执行、0 个等待，持续生成期间约 51 tokens/s。记录支持生成期间达到网关时限；43 的采样不能逐请求证明它后来完成了回答。[21 生效配置](../../docs/operations/evidence/ie-audit-20261106-a1/gateway-timeout.json) · [实际路由](../../docs/operations/evidence/ie-audit-20261106-a1/model-route.json) · [43 三段运行记录](../../docs/operations/evidence/ie-audit-20261106-a1/model43-windows.json)

收到 408 时，处理器知道请求已发出，却没有收到原答或用量，故将本轮执行记作 `unknown`。三次启动命令均返回 `ModelCallError`。库里还可读到三个不同含义的字段：

| 页面要回答的问题 | 三案实际值 | 展示依据 |
|---|---|---|
| 本轮调查运行得怎样 | Run 为 `unknown`，交付标记 `none`，C3 错误工件含 HTTP 408 | 展示“C3 模型响应超时，执行待确认”，保留停止原因、时间、成员与工件入口 |
| 现在有什么可以移交给人 | C6 系统收尾步骤完成，回执 `partial`；三案各有一份系统报告和一个当前判断 | 展示“系统待核”，显示实际涉及 1、2、1 条告警；本轮模型判断覆盖分别为 0/1、0/2、0/1 |
| 有没有正式调查 Result | 三案 `result_ids=[]`、`results` 表新增 0 行 | 正式结果显示空态；当前判断沿 `case_assessment_sources.artifact_id` 打开系统报告。三次实际 Run 读取均返回 `can_start=false / not_pending` |

## 交接结论与下一步

1. **可签收数据读取。** 一次一致性事务按三案精确主体读回全部 29 张表，对原文、哈希、指针、范围、回执做了 540 项核对，发现 0 项不一致。随后直接调用部署镜像的页面读取方法 27 次，将其中 53 项与库中值交叉核对，全部一致。范围是数据读取；产品页面渲染和操作写回沿既有签收清单单验。[数据库核对](../../docs/operations/evidence/ie-audit-20261106-a1/readback/summary.json) · [页面实机返回](../../docs/operations/evidence/ie-audit-20261106-a1/page-service-readback.json) · [字段对照](../../docs/operations/evidence/ie-audit-20261106-a1/page-cross-check.json)
2. **三页先签异常态。** 告警页用 M01 复验“有原件、分诊未发布”；事件页核同一事件的成员和已发布摘要；调查页把 C3 超时、系统收尾、模型覆盖和正式 Result 并排列出。当前 CLI 顶层仅返回错误种类，具体原因须读同 Run 的错误工件，这个映射应纳入交接合同。
3. **完整模型结论单独验收。** 下一轮用新案例，在独立配置上测量 C3 从接收、开始生成到完成结构化答复的用时，再确定调查专用时限或输出规模。通过条件是有效 C3 原答、所选后续步骤、C6 正式结果和来源指针能在同一个真实 Run 读回。本轮保留三个 `unknown` 原记录；未变更共享网关时限。命令效果、资产校验和引用充分性作为后续质量回归项。

测试前后 21 的九个相关服务状态及启动时间一致，固定入口复核通过。受控试验首批缺测试依赖的记录与最终通过回执均已保留。[审计前状态](../../docs/operations/evidence/ie-audit-20261106-a1/service-before.json) · [审计后状态](../../docs/operations/evidence/ie-audit-20261106-a1/service-after.json)
