## 调查运行记录页

打开[本机运行记录](http://127.0.0.1:4177/)，从左表选一个案例。表中时间取该次测试最后一次实际启动的 Case 调查 `runs.started_at`，按北京时间显示。右侧按告警分诊、事件诊断、Case 调查列出**每一轮 Run**。点开步骤，再点“输入”或“输出”，即可原地展开对应工件的完整 JSON。调用失败时可以看错误回执；没有形成 Case 的测试也能看已落库的告警和事件步骤。

案例顶部的**调查流程图**可按模块和轮次切换。绿色表示该步成功，红色表示失败，待确认或部分交付单独标注，跳过或没有执行记录的设计分支留白。点有记录的节点可定位到该轮、该步骤或该份工件。补查分为直接查询、问题深查、构图建议和人工确认；图谱步骤另有自己的执行记录。主案例列表仅显示实际测试，受控对照单列。

以事件诊断为例，“输入”是本轮开始时保存的事件和成员告警，“输出”可查看该轮的诊断摘要和发布情况。展开“执行记录（数据库 runs）”可核对状态、时间和停止原因。工件目录收录处理时保存的请求、原答、报告等原件；页尾按测试前准备、调用过程和事后查询分组，便于把实际执行过程与测试验证材料分别核对。

**跑完新测试后，在项目根目录执行一次。** 已有完整导出的，用第一条命令；使用 21 处理验证库、手头只有该批合成测试计划的，用第二条。将下列目录替换为本次测试的实际路径。

```powershell
python docs/operations/update_processing_audit.py --batch "测试导出目录"
python docs/operations/update_processing_audit.py --plan "本次21合成测试目录/plan.json"
```

- `--batch` 识别 `readback/<案例>/database.json`、四案包解压后的 `cases/<案例>/export/`、本地测试驱动的 `exports/<时间戳>/`，也支持直接指定带 `manifest.json` 的单次页面导出目录。核心数据来自 Run、Step 和工件行；页面读回和作业回执存在时一并展示。
- `--plan` 先使用该批已有的 `readback/`；缺少快照时从 21 的专用验证库按测试主体只读导出，再更新页面。读取服务使用本机已有的 21 SSH 配置。已有快照也可直接离线更新。
- 每次独立测试使用新的批次标识。同一案例重跑后可按批次分别查看；重复导入同一快照只保留一条。无参数执行会扫描项目 `docs/operations/evidence/*/readback/`，并保留先前登记的其他批次。更新完成后在浏览器刷新即可。

4177 读取本地的静态文件。若本机尚未启动预览，可从项目根目录执行：

```powershell
python -m http.server 4177 --bind 127.0.0.1 --directory deliverables/investigation-validation-20261106/processing-audit
```
