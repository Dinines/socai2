调查处理模块与业务后端数据交接

告警页以告警为主体，事件页以事件及其当前成员为主体，调查页要同时显示 Case、某次执行（Run）、正式结果（Result）和当前采用的判断。四者通过各自的 ID 关联。一次模型调用失败时，后端仍可交付已经保存的告警原件、事件诊断、执行回执和系统待核说明。

适用范围为 PostgreSQL 16 的 socai2 命名空间，当前共 28 表、450 列，基准迁移 123–126 后增加 127（仅清理未用探索表）。当前表职责（来源：docs/investigation/investigation-table-scope.md）及当前机器字典为现行目录；旧字段字典保留 V1 基线。页面功能及产品验收见逐页功能清单（来源：deliverables/investigation-validation-20261106/frontend-feature-list.md），逐列类型、可空性与约束见字段字典（来源：docs/design/socai2-field-dictionary-20261103.md）。告警相关的前后端字段合同保持稳定；确需调整时按项目变更规则（来源：AGENTS.md#调查数据库-v1-与人工确认）列出影响并取得明确确认，必要读写接线和配置随功能处理。

前次完整读取核验（清理前）： 2026-11-10 在 21 的 aisoc.socai2 完成两案 365 次 GET、16,820 项字段／正文／关联核对。357 次正常返回，8 次错误父归属返回预期 404；读取前后快照一致。覆盖空当前判断、H 全部修订及同租户跨 Case 关系／活动。既有 29 表结构保持，Case/H GET、资产与用户关联、两项只读函数均可按现有身份读取。实际证据（来源：docs/operations/evidence/case-current-flow-20261110-01/readback-03/summary.json）

事件页

页面用途权威存储与关联后端取值
事件概览和成员incidents 取 id, title, description, handling_status, severity_override, priority_value, priority_state, owner_id, created_at；incident_alerts.(incident_id,alert_id) → alerts成员数按告警计，归并依据来自关系行 membership_source, correlation_basis, basis_version。先聚合成员再连接材料、对象或步骤，避免成员数被一对多连接放大。
时间与有效严重度对成员 alerts.event_time 求最早、最晚，并单列无时间数。自动严重度按 info < low < medium < high < critical 取已知成员的最高级severity_effective 优先取人工覆盖 severity_override，其次取成员最高值，两者的来源分别为 manual_override / member_max。两者均缺失时，有效严重度与来源均返回 null。
诊断摘要、未决问题incidents.latest_diagnosis_id → incident_diagnoses.id，同时匹配 incident_id；取 state, summary, diagnosis, open_questions, source_run_id, generated_at已发布诊断用指针读取。全部尝试从 runs.kind=incident_diagnosis 且 incident_id 相同的记录读取。I 的冻结输入含当时的成员及其分诊；当前成员或分诊可能已变化。
进入 Casecase_incidents.(incident_id,case_id) 保存显式关系，case_alerts 保存实际 Case 成员“该事件关联的 Case”和“某成员告警所在的 Case”有不同含义；分别说明关联依据。没有 Case 时事件详情仍可展示。

Case 与调查执行页

页面用途权威存储与关联后端取值
案件资料及成员cases 取 title, handling_status, severity, owner_id, scope_revision, row_version, classification, due_at；成员用 case_alerts、关联事件用 case_incidentsclassification 可为 true_positive / informational / false_positive / null；due_at 是可空带时区的案件期限。任务期限和 Run 预算独立读取。
当前判断cases.current_assessment_id → case_assessments，按 (tenant_id,case_id,id) 匹配；case_assessment_sources / case_assessment_members 给来源和已覆盖成员返回 conclusion, origin, validity, formed_at, adopted_at, scope_revision。origin=system, validity=system_only 表示系统待核说明。列表和详情的 page_data.determination 均沿该指针取值。指针为空时展示尚无采用判断，不能用最近 Result 填充；本批两案即为该空态。
一次调查及其输入runs.kind=baseline AND runs.case_id=cases.id；input_artifact_id 是本轮输入；run_members 的 alert_id, material_id, triage_id, feedback_id, read_state, analysis_state 固定本轮版本requested_at 请求、started_at 实际启动、ended_at 实际结束。两端齐备才计算完成时长。pending_update 尚待启动，unknown 表示执行结果待确认；running/unknown 占用该 Case 的基础执行槽。
步骤、模型及工具输入输出run_steps 按同 run_id 的 seq 排列，parent_step_id 指向父步骤。input_artifact_id / output_artifact_id 指向本轮输入和输出，reused_artifact_id 可指向同案其他 Run 的原件读取 stage_code, kind, state, actual_args, returned_rows, error, usage。completed + returned_rows=0 是执行后查空。skipped 与失败原因各自保留。工件 step_id=NULL 仍可属于 Run。发生错误时继续返回可用原件与失败回执。
正式结果、报告与图谱results.source_run_id 关联实际 Run，result_members 给 conclusion_covered 及依据。report_artifact_id / graph_artifact_id 指向同案同轮工件分别展示 runs.state、delivery_state、结果的 conclusion_state / conclusion_origin / validation_state 和已采用判断。C6 回执中 content_json.outcome.result_id 可空。有报告及系统说明时，正式 Result 仍允许为零。
证据目录、判断依据和威胁数cases.current_evidence_artifact_id → artifacts，匹配同租户同 Case、kind=case_evidence_index、schema_version=socai2.case-evidence.v1读取 entries[] 的证据 ID、关联成员和对象、source_refs、verdict_sources、verdict、威胁身份和状态。计数及范围优先复用 CasePageData.evidence。
人工协作与处置tasks.current_revision_id → task_revisions。活动从 activities.actor 取操作者快照，从 activity_targets 取各目标的前后值。response_links.receipt_artifact_id 指向处置回执区别人工任务、模型提出的后续行动、实际回执。存在 recommendations 时只显示建议。每条活动可能有多个目标，活动数按活动 ID 计。
评论、探索画布、问答comments 按互斥的 alert_id / incident_id / case_id 确定评论对象。未使用的 graph_explorations 空表已清理，正式探索保存服务未实现；不能按旧表设计读取画布。conversations.case_id 关联案件，messages.conversation_id 关联会话，按 sequence 排序评论、用户探索状态和正式结果图分别展示。问答表预留存储位置，当前命令可用性见下文。

证据计数使用当前版本中 state=active 且全部关联告警仍在案件范围的条目。威胁数仅取其中 malicious / suspicious 且有明确威胁身份的条目，按 (namespace,key) 去重。not_recorded / unavailable / invalid_reference 的计数为 null；有效空目录或全撤回为 0；partial 返回已知计数、未覆盖成员及限制。证据的来源行、JSON Pointer、角色和范围均可核对。来源标签、模型判断和人工陈述应保留各自身份。证据合同（来源：services/api/app/socai2/case_evidence.schema.json） · 证据读取和验证（来源：services/api/app/socai2/case_data.py）

只读联查示例

下列 SQL 仅用于调查服务内部维护和取数解释，不是业务后端对接要求。对接请使用HTTP交接包。内部维护时可在 psql 的同一连接顺序执行。tenant_id、case_id、run_id 分别为授权租户、案件和选中调查轮次的 UUID。示例选择当前核验中的模型来源 Case，对应结果列在下一节。内部数据库读取应设置正确租户，并在事务结束后释放事务级配置；业务后端通过 HTTP 认证上下文确定租户。

\set tenant_id '00000000-0000-0000-0000-000000000001'
\set case_id '2b37f5b3-862b-52cc-84bd-86db50dd3ad4'
\set run_id '8d53cdb1-1cba-4df3-8ac2-f2724c062342'
BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY;
SELECT set_config('app.current_tenant_id', :'tenant_id', true);

-- 当前告警材料和已发布分诊；即使分诊为空也返回告警。
SELECT a.id, a.title, a.event_time, m.id AS material_id, m.material_state,
       t.id AS triage_id, t.verdict, t.source_run_id
FROM socai2.case_alerts ca
JOIN socai2.alerts a ON (a.tenant_id,a.id)=(ca.tenant_id,ca.alert_id)
LEFT JOIN socai2.alert_materials m
  ON (m.tenant_id,m.alert_id,m.id)=(a.tenant_id,a.id,a.latest_material_id)
LEFT JOIN socai2.alert_assessments t
  ON (t.tenant_id,t.alert_id,t.id)=(a.tenant_id,a.id,a.latest_triage_id) AND t.kind='triage'
WHERE ca.tenant_id=:'tenant_id'::uuid AND ca.case_id=:'case_id'::uuid ORDER BY a.id;

-- 每个显式关联事件返回一行，含成员数量和已发布诊断。
SELECT i.id, i.title, d.id AS diagnosis_id, d.summary,
       (SELECT count(*) FROM socai2.incident_alerts ia
        WHERE (ia.tenant_id,ia.incident_id)=(i.tenant_id,i.id)) AS member_count
FROM socai2.case_incidents ci
JOIN socai2.incidents i ON (i.tenant_id,i.id)=(ci.tenant_id,ci.incident_id)
LEFT JOIN socai2.incident_diagnoses d
  ON (d.tenant_id,d.incident_id,d.id)=(i.tenant_id,i.id,i.latest_diagnosis_id)
WHERE ci.tenant_id=:'tenant_id'::uuid AND ci.case_id=:'case_id'::uuid ORDER BY i.id;

-- 当前判断与每轮基础调查并列；正式结果按 Run 独立计数。
SELECT c.id AS case_id, a.origin, a.validity, a.conclusion,
       r.id AS run_id, r.state, r.delivery_state, r.started_at, r.ended_at,
       (SELECT count(*) FROM socai2.results x
        WHERE (x.tenant_id,x.case_id,x.source_run_id)=(c.tenant_id,c.id,r.id)
          AND x.kind='baseline') AS baseline_result_count
FROM socai2.cases c
LEFT JOIN socai2.case_assessments a
  ON (a.tenant_id,a.case_id,a.id)=(c.tenant_id,c.id,c.current_assessment_id)
LEFT JOIN socai2.runs r ON (r.tenant_id,r.case_id)=(c.tenant_id,c.id) AND r.kind='baseline'
WHERE c.tenant_id=:'tenant_id'::uuid AND c.id=:'case_id'::uuid ORDER BY r.requested_at,r.id;
-- 逐步回查该 Case 的一轮调查；父步骤、查询和模型分别保留。
SELECT s.seq, s.stage_code, s.kind, s.state, s.parent_step_id, s.error,
       s.input_artifact_id, s.output_artifact_id, s.reused_artifact_id,
       s.returned_rows, s.usage
FROM socai2.runs r
JOIN socai2.run_steps s ON (s.tenant_id,s.run_id)=(r.tenant_id,r.id)
WHERE r.tenant_id=:'tenant_id'::uuid AND r.case_id=:'case_id'::uuid
  AND r.id=:'run_id'::uuid AND r.kind='baseline'
ORDER BY s.seq;
ROLLBACK;

步骤顺序以该 Run 实际 seq/stage_code 为准。展开输入、输出时按工件 ID 限定同租户同 Run，并补读该步下 artifacts.step_id=run_steps.id 的其他工件。展开 reused_artifact_id 时单独按租户、案件、工件 ID 核对所属关系，保留其实际来源 Run。写在 Run 上且 step_id=NULL 的材料单列。进一步核对当前判断来源与证据目录可使用Case 资料与证据目录 SQL（来源：docs/investigation/socai2-page-data-readback-20261106.sql）。
